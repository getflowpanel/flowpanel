`flowpanel eject` writes a starting scaffold for a resource, dashboard or layout into your app and turns off the generated one. From then on the code is yours and gets no FlowPanel updates. Try a [smaller extension point](/docs/customization/overview) first.

## Eject a resource

```bash
pnpm flowpanel eject resource users --dry-run
pnpm flowpanel eject resource users
```

`--dry-run` prints the plan. The command writes list, create, detail, edit and action stubs under `app/admin/users`, then comments out the matching `resource(...)` entry. The stubs are a starting point: queries, policies and UI states are yours to implement. File headers record the FlowPanel version.

`eject` follows a root config that re-exports another module, and a `resources` directory written by `flowpanel new --dir`, where it comments out the call in the file that defines it.

## Eject a dashboard or layout

```bash
pnpm flowpanel eject dashboard /monitoring
pnpm flowpanel eject layout
```

A dashboard becomes one page at its path and its config entry is turned off. A layout becomes an admin `layout.tsx` that wraps the FlowPanel pages; resources and dashboards stay in config.

## Existing files

The command stops if a target file exists. `--force` overwrites it.

## Reverse an eject

Restore the config entry and delete or move the ejected route. Next.js file routing takes precedence over the catch-all page, so the route must go.

Every flag: [flowpanel eject](/docs/reference/cli#flowpanel-eject).
