An adapter is the only part of FlowPanel that talks to the database. FlowPanel ships one for Drizzle and one for Prisma; the runtime depends on the adapter interface, not on either ORM.

## Operations and introspection

An adapter's operations list, get, create, update, delete and optionally restore rows. Each receives the request context: pagination, filters, sort, the projected fields, the scope binding and the input.

Introspection reports each resource's primary key and scalar columns with their types. FlowPanel uses it to fill omitted `columns`, pick generated form controls and validate the names in your config. It does not turn relations into joins.

## Drizzle and Prisma

Drizzle receives a table object, so TypeScript reads the row from `$inferSelect`, and scope becomes an SQL predicate. Prisma receives a model name string resolved through DMMF, so its row type comes from `FlowpanelResources`, and scope merges into the `where` object. See [Drizzle setup](/docs/introduction/drizzle) and [Prisma setup](/docs/introduction/prisma).

## Custom adapters

Write one for a data source with stable CRUD that can honour scope, projection, the search allowlist and pagination, and test it against real storage. For one aggregate or joined screen, a custom query in a widget or page is simpler.

The contract, method by method: [Adapter reference](/docs/reference/adapters).
