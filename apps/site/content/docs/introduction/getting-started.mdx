This tutorial adds a working `/admin` route to an existing application. You will initialize FlowPanel, expose one table or model, apply its migration, and start the admin.

> **Prefer to look around first?** The [ScrapeAI example](https://github.com/getflowpanel/flowpanel/tree/main/examples/ai-scraper) shows resources, dashboards, roles, actions, and realtime updates in one application.

## Before you start

<Compatibility />

You need a Next.js App Router project with Tailwind CSS and either Drizzle or Prisma already configured. Run the commands below from the project root. The Pages Router is not supported.

FlowPanel uses your existing database client and authentication. If the CLI cannot find an auth helper, it creates a development-only session stub that throws in production. Replace it before deployment.

## Initialize FlowPanel

```bash
pnpm dlx @flowpanel/cli init
```

The CLI detects the package manager, ORM, app directory, path alias, database client, schema, auth helper, and Tailwind version. Confirm the detected paths when prompted.

It installs `@flowpanel/kit` and a version-aligned local `@flowpanel/cli`. Existing files are changed only when the CLI has a safe, targeted edit; conflicting files stop the operation. To inspect the plan without writing or installing anything, run:

```bash
pnpm dlx @flowpanel/cli init --dry-run
```

## Add your first resource

Open `flowpanel.config.ts`. The generated config has an empty `resources` array because FlowPanel cannot decide which application data belongs in the admin.

Use the version for your ORM and adjust the import paths and field names to match your project:

Drizzle infers the row type from the table. A Prisma resource starts from a model name string, so the `FlowpanelResources` augmentation binds that name to the generated Prisma type. This is what makes columns, search fields, actions, and renderers type-safe.

Keep the generated auth block if it already matches your application. The example requires the `admin` role; a request without that role receives a server-side access denial, not merely a hidden navigation item.

## Apply the migration

```bash
pnpm flowpanel migrate
```

The command reads `DATABASE_URL`, applies pending SQL files in `flowpanel/migrations`, and records them in FlowPanel's migration table. Use `--dry-run` to list pending files without executing them.

The initial migration is PostgreSQL SQL. Review or adapt it before running against MySQL or SQLite. The audit table remains unused until you configure an `audit.sink`.

## Start the admin

```bash
pnpm flowpanel dev
```

Open [http://localhost:3000/admin](http://localhost:3000/admin). You should see the resource in the navigation and a paginated list at its resource URL. If the navigation is empty, confirm that `resources` contains the resource and restart the dev process so the config is reloaded.

`flowpanel dev` starts Next.js and, when `REDIS_URL` is set and the project has a `scripts/board-server.mts` (or `.ts`) file, the BullMQ board process. `init` does not create that script; see the [queues guide](/docs/guides/queues). Use your normal `pnpm dev` command if you do not need the board integration.

## What the CLI created

The exact paths follow your `app` or `src/app` layout:

| File | Purpose | You edit it when… |
| --- | --- | --- |
| `flowpanel.config.ts` | Resources, dashboards, auth, scope, realtime, and theme | You change admin behavior |
| `app/admin/[[...slug]]/page.tsx` | Catch-all admin page | You change the mount path or eject page behavior |
| `app/api/flowpanel/[...route]/route.ts` | Resource and action handlers | You change the API mount path |
| `app/api/flowpanel/stream/route.ts` | Authenticated SSE endpoint | You change the stream mount path |
| `styles/admin.css` | FlowPanel stylesheet and Tailwind entry | You customize tokens or content scanning |
| `flowpanel/migrations/0001_init.sql` | FlowPanel-owned database tables | You review dialect-specific SQL |

See [Project structure](/docs/introduction/project-structure) for ownership and generated-file details.
