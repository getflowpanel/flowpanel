## Before you start

<Compatibility />

Tailwind is optional: the admin stylesheet is precompiled. The Pages Router is not supported. Run every command from the project root.

## Initialize

```bash
pnpm dlx @flowpanel/cli init
```

`init` detects the package manager, ORM, app directory, path alias, database client, schema and auth helper, asks you to confirm the paths, then installs `@flowpanel/kit` and a local `@flowpanel/cli`. It stops on a conflicting file and writes nothing. `--dry-run` prints the plan without writing; `--path /ops/admin` picks the mount.

When the CLI finds no `getSession` helper, it writes a closed session adapter: connect your provider and map `auth.role` before you open the admin. `--dev-auth` writes an open development identity that refuses to run in production.

## Add your first resource

The generated `flowpanel.config.ts` has an empty `resources` array. With Drizzle, `pnpm flowpanel new <table>` writes the entry for you; see [flowpanel new](/docs/reference/cli#flowpanel-new). By hand:

<AdapterTabs>
  <AdapterTab adapter="drizzle">
    <include>../../snippets/getting-started/drizzle-config.ts</include>
  </AdapterTab>
  <AdapterTab adapter="prisma">
    <include>../../snippets/getting-started/prisma-config.ts</include>
  </AdapterTab>
</AdapterTabs>

Drizzle infers the row type from the table. A Prisma resource is a model name, so the `FlowpanelResources` augmentation binds it to the generated type. The `session` entry types the argument of `auth.role`. A request without the `admin` role is denied on the server.

## Start the admin

```bash
pnpm dev
```

Open [http://localhost:3000/admin](http://localhost:3000/admin). The resource is in the navigation. `pnpm flowpanel dev` runs Next.js with the [queue board](/docs/guides/queues).

## Audit tables

```bash
pnpm flowpanel migrate
```

This applies `flowpanel/migrations` with `DATABASE_URL` and creates `_flowpanel_migrations` and `flowpanel_audit_log`; the SQL targets PostgreSQL. Only [`audit`](/docs/reference/define-config#auditconfig) needs these tables.

## What `init` created

Paths start with `src/` in a `src/app` project.

| File | Purpose |
| --- | --- |
| `flowpanel.config.ts` | Resources, dashboards, auth, scope, realtime and theme |
| `app/admin/[[...slug]]/page.tsx` | Catch-all admin page; exports `generateMetadata` |
| `app/admin/layout.tsx` | Imports the stylesheet and the theme script |
| `app/admin/not-found.tsx` | 404 page inside the admin chrome |
| `app/api/flowpanel/[...route]/route.ts` | Resource and action handlers |
| `app/api/flowpanel/stream/route.ts` | Authenticated SSE endpoint |
| `styles/admin.css` | One import of the precompiled, isolated stylesheet |
| `flowpanel/migrations/0001_init.sql` | SQL for `_flowpanel_migrations` and `flowpanel_audit_log` |

`init` also adds `suppressHydrationWarning` to the root layout's `<html>` tag, because `ThemeScript` sets an attribute on it before hydration. If it cannot patch the file safely, it prints the edit. `flowpanel doctor --fix` restores a missing route file.
