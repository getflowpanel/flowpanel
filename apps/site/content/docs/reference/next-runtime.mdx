`@flowpanel/kit/next` binds a config to the admin page, HTTP handlers, protected
controllers, client metadata and realtime publisher.

## createFlowpanel

<ApiSignature path="../../packages/next/src/create-flowpanel.tsx" name="createFlowpanel" />

Create one module-level runtime and reuse it from your route files:

```ts excerpt
// src/flowpanel.ts
import { createFlowpanel } from "@flowpanel/kit/next";
import config from "@/flowpanel.config";

export const flowpanel = createFlowpanel(config);
```

```ts excerpt
// app/admin/[[...slug]]/page.tsx
import { flowpanel } from "@/src/flowpanel";

export const generateMetadata = flowpanel.metadata;
export default flowpanel.page;
```

```ts excerpt
// app/api/flowpanel/[...route]/route.ts
import { flowpanel } from "@/src/flowpanel";

export const { GET, POST, PUT, PATCH, DELETE, OPTIONS } = flowpanel.handlers;
export const runtime = "nodejs";
```

`createFlowpanel(definition)` returns a frozen `FlowpanelRuntime`:

| Member | Purpose |
| --- | --- |
| `page` | Generated catch-all page component. |
| `metadata` | The page's `generateMetadata`: a `title` per dashboard, list and record. |
| `handlers` | `FlowpanelHandlers` for REST and generated-UI routes. |
| `request()` | Current request's protected `FlowpanelRequest`. |
| `client` | Serializable `FlowpanelClientMetadata` for `@flowpanel/client`. |
| `events.publish(channel, payload?)` | Namespaced, validated realtime event. |
| `dispose()` | Idempotent runtime cleanup hook. |

`events.publish` payloads must serialize to `WireValue` and stay under 64 KiB.
`FlowpanelClientMetadata` holds only paths and protocol data.

### Protected request controllers

`await flowpanel.request()` authenticates once and returns a `FlowpanelRequest`
with a typed `ResourceController<Row>` per resource (`resource(name)` for a
dynamic name). `ResourceListOptions<Row>` takes page, page size, search, filters,
sort, projection and soft-delete visibility.

```ts excerpt
const request = await flowpanel.request();
const result = await request.resources.orders.list({
  pageSize: 25,
  select: ["id", "status", "totalCents"],
  sort: { field: "createdAt", dir: "desc" },
});
```

Controllers return a `FlowpanelResult` for access, validation and not-found
failures, and apply the same policies, projection, scope and write pipeline as the
generated UI. Do not reuse a `FlowpanelRequest` across requests.

### flowpanelMetadata

<ApiSignature path="../../packages/next/src/runtime/page-metadata.ts" name="flowpanelMetadata" />

`flowpanelMetadata(config)` is the page's `generateMetadata`: a title per
dashboard, list and record, and `robots: noindex`. Leave `viewport.themeColor`
unset on the admin layout; the page renders its own.

```ts excerpt
// app/admin/[[...slug]]/page.tsx
import { Flowpanel, flowpanelMetadata } from "@flowpanel/kit/next";
import config from "@/flowpanel.config";

export const generateMetadata = flowpanelMetadata(config);
export default Flowpanel(config);
```

`FlowpanelContent(config, opts?)` is `Flowpanel(config, { ...opts, shell: "bare" })`,
for embedding the admin in your own chrome.

## handlers

<ApiSignature path="../../packages/next/src/handlers.ts" name="handlers" />

`handlers(config)` is the handler factory behind `createFlowpanel(config).handlers`:

```ts excerpt
// app/api/flowpanel/[...route]/route.ts
import { handlers } from "@flowpanel/kit/next";
import config from "@/flowpanel.config";

export const { GET, POST, PUT, PATCH, DELETE, OPTIONS } = handlers(config);
```

Each method is a `RouteHandler`, `(request, context) => Promise<Response>`.

### The routes it mounts

All paths are relative to `/api/flowpanel`.

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/<resource>` | Typed list result for custom clients |
| `GET` | `/<resource>/<id>` | One projected row |
| `POST` | `/<resource>` | Create (JSON API) |
| `PATCH` / `PUT` | `/<resource>/<id>` | Update (JSON API) |
| `DELETE` | `/<resource>/<id>` | Delete (JSON API) |
| `GET` | `/drawer/<resource>/<id>` | Drawer payload for one row |
| `GET` | `/<resource>/reference/<field>` | Options for a reference picker |
| `POST` | `/<resource>/create` | Create form submit |
| `POST` | `/<resource>/<id>/edit` | Edit form submit |
| `POST` | `/<resource>/<id>/update` | Inline cell edit |
| `POST` | `/<resource>/<id>/restore` | Undo a soft delete |
| `POST` | `/<resource>/import` | CSV / JSON import |
| `POST` | `/<resource>/<id>/actions/<action>` | Row action |
| `POST` | `/<resource>/bulk-actions/<action>` | Bulk action |
| `POST` | `/drawer/<resource>/<id>/actions/<action>` | Drawer action |
| `POST` | `/dashboards/<path>/actions/<action>` | Dashboard action |

Each runs the admin role gate and rate limit, the resource gate, read-only mode
for writes, and the action's `access`, in that order.

## stream

<ApiSignature path="../../packages/next/src/stream.ts" name="stream" />

The SSE endpoint for realtime, on its own route.

```ts excerpt
export function stream(
  config: ResolvedAdminConfig,
  opts?: StreamOptions,
): (req: Request) => Promise<Response>;
```

`StreamOptions.heartbeatMs` sets the keep-alive interval, 15 s by default.

```ts excerpt
// app/api/flowpanel/stream/route.ts
import { stream } from "@flowpanel/kit/next";
import config from "@/flowpanel.config";

export const GET = stream(config);
export const runtime = "nodejs";
export const dynamic = "force-dynamic";
```

`flowpanel init` writes this file.

### What the stream checks

Like every route, the stream is gated by `auth.requireRole`; without it, it is
open ([AuthConfig](/docs/reference/define-config#authconfig)). A failed role check
answers `403`. Per connection:

| Limit | Value | Behavior when exceeded |
| --- | --- | --- |
| Channels per connection | 25 | Extra `?channel=` values are dropped, not rejected |
| Channel name charset | `/^[A-Za-z0-9_.:-]{1,128}$/` | Non-matching names are silently ignored |
| Per-resource role gate | `resource.<name>` channels | Dropped when the resource's `access.read` rejects the caller |
| Heartbeat | 15s (`heartbeatMs`) | A `: keep-alive` comment keeps proxies from closing the response |

A channel that never receives events was probably dropped by one of the first
three rows.

## Realtime helpers

```ts excerpt
function publish(channel: string, payload?: unknown): Promise<void>;
function publishResource(
  name: string,
  event: { action: "create" | "update" | "delete"; id?: string },
): Promise<void>;
function subscribe(channel: string, handler: (payload: unknown) => void): () => void;
function bindPublisher(config: ResolvedAdminConfig): void;
```

`publishResource(name, event)` publishes on `resource.<name>`, the channel a
`realtime: true` resource listens on:

```ts excerpt
import { publishResource } from "@flowpanel/kit/next";

await publishResource("orders", { action: "update", id: order.id });
```

In an action, use `ctx.publish`. `handlers`, `Flowpanel` and `stream` call
`bindPublisher` for you; call it in your own route handlers. A worker uses
[`@flowpanel/kit/publish`](/docs/guides/realtime#publish-from-a-worker).

`@flowpanel/kit/server` re-exports `publish`, `publishResource` and
`bindPublisher`, plus `emitAudit`, `requireRole` and the request-context
accessors, without the rest of the Next.js runtime. Publishing before
`bindPublisher` runs uses an in-memory publisher and warns once.

## Route handlers

Factories for single [routes](#the-routes-it-mounts), for mounting one on your
own path. Each takes `ResolvedAdminConfig` and returns a handler.

| Factory | Route |
| --- | --- |
| `resourceCreateRoute` | `POST /<resource>/create` |
| `resourceUpdateRoute` | `POST /<resource>/<id>/edit` |
| `rowActionRoute` | `POST /<resource>/<id>/actions/<action>` |
| `bulkActionRoute` | `POST /<resource>/bulk-actions/<action>` |
| `dashboardActionRoute` | `POST /dashboards/<path>/actions/<action>` |
| `drawerActionRoute` | `POST /drawer/<resource>/<id>/actions/<action>` |
| `drawerRoute` | `GET /drawer/<resource>/<id>` |
| `inlineUpdateRoute` | `POST /<resource>/<id>/update`, for `editable: true` columns |

Reference search, import and restore have no factory; they come only with
`handlers(config)`.

### Serialization pairs

Action routes serialize actions for the client without server-only fields:

| Config type | Serializer | Wire type |
| --- | --- | --- |
| `RowAction` | `serializeRowAction` | `SerializedRowAction` |
| `BulkAction` | `serializeBulkAction` | `SerializedBulkAction` |
| `DashboardAction` | `serializeDashboardAction` | `SerializedDashboardAction` |
| Drawer action | — (inline in `drawerRoute`) | `SerializedDrawerAction` |
| Drawer tab | — (inline in `drawerRoute`) | `SerializedDrawerTab` |

`SerializedDashboardAction.form` is a `SerializedDashboardActionField[]`.

## buildRequestContext

Builds the `RequestContext`. It enforces `auth.requireRole` and the rate limit, so
it throws `FlowpanelAccessError` or `FlowpanelRateLimitError`:

```ts excerpt
import { buildRequestContext } from "@flowpanel/kit/next";

let reqCtx;
try {
  reqCtx = await buildRequestContext({ req, config });
} catch (err) {
  // FlowpanelError carries the right status
  return Response.json({ ok: false, error: err.safeMessage }, { status: err.status });
}
```

## Navigation

```ts excerpt
function buildNav(config: ResolvedAdminConfig, reqCtx?: RequestContext): NavGroup[];
function resourceNavName(resource: ResourceConfig): string;
```

`buildNav` returns the sidebar entries, for your own chrome around a `"bare"`
shell. Pass `reqCtx` to apply each entry's `requireRole` or resource `access`. `resourceNavName` returns
a resource's resolved name and throws if it cannot.
