Widgets are the contents of a dashboard section, of a detail page's widgets tab,
and of a drawer's widget tab. Each builder returns a `WidgetConfig`; every
`query` runs on the server with a `WidgetContext`. In a detail tab and in a
drawer the record being viewed is `ctx.row`; a drawer renders its widgets as
static cards (see [Drawers](/docs/reference/drawer#drawertabwidgets)).

```ts excerpt
import { dashboard, metric, statGroup, table } from "@flowpanel/kit";
import { areaChart } from "@flowpanel/kit/charts";

export const overview = dashboard({
  path: "/",
  label: "Overview",
  dateRange: { preset: "last30d" },
  sections: [
    {
      label: "Revenue",
      widgets: [
        metric("MRR", async ({ db, dateRange }) => mrr(db, dateRange), {
          format: "currency",
          span: 3,
          drilldown: "/admin/invoices",
        }),
        areaChart("Revenue over time", async ({ db }) => revenueSeries(db), {
          x: "day",
          y: ["subscriptions", "one-off"],
          stacked: true,
          span: 9,
        }),
      ],
    },
  ],
});
```

## WidgetContext

What every widget `query` receives.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="WidgetContext" />

`href` builds a link under the admin's own `basePath`, so a config never
hand-types `/admin/…`. `href("orders")` is the list, `href("orders", id)` one
record, and the third argument adds the list page's own query keys —
`{ filter: { status: "paid" } }` becomes `?f_status=paid` and `{ tab: "activity" }`
becomes `?tab=activity`.

`query` memoises for the request, so two widgets that need the same figure run it
once and the next request queries again. Pass a key and a thunk —
`query("mrr", () => mrr(db))` — or the function and its arguments —
`query(mrr, db, ctx.dateRange)` — to key the call by the function and its
arguments: strings, numbers, booleans and dates by value, objects by identity. The
memo holds the promise, so a failure is shared too — the request does not retry.
Pass a function declared once, like `mrr`: one written inline —
`query(async () => …)` — is a new function on every call and never shares.
A function passed alone that declares a parameter receives the context: `query(hourly)` runs
`hourly(ctx)` once for this context, so several widgets built on one SQL statement share it
without `query(hourly, ctx)`. A function with no parameter, or only defaulted ones such as
`async (limit = 5) => …`, is called with no arguments, as before. A function whose first
parameter is optional without a default (`days?: number`) now receives the context: give it a
default (`days = 7`), or pass the argument. A context over another range — the `compare` period —
runs it again with its own range.

`count` is memoised the same way: one resource and `where`, written in any key
order, count once per request. `id` is the viewed record's key as a string, read
through the resource's `rowKey`; a dashboard widget has none.

`dateRange` is a `WidgetDateRange`: the picked range, `previous` and `timeZone`, the
admin's `formatting.timeZone`. `previous` is the period a founder compares with. For
`today`, `yesterday`, `MTD`, `QTD` and `YTD` it is the same stretch one day, month,
quarter or year back at the same clock time, so today at 10:00 compares with yesterday
until 10:00. For `last7d`, `last30d` and a custom range it is the span of the same length
before it, and over a detail tab's whole history it is `null`. Query the previous period
with `ctx.dateRange.previous`; hand `ctx.dateRange` to `fillDays` and days bucket in the
admin's zone.

`filters` holds the dashboard's active filters by key: `{ platform: "kwork" }` for
`?f_platform=kwork`. It is `{}` on a record page and when none is set. Nothing filters
implicitly, so read it in your own query and bind it as a parameter. The previous-period,
capped and tracker contexts keep it, so a number and its change describe the same slice.

`labels` is the admin's resolved `LabelsConfig`, which is where a widget's own
wording should come from. `row` is present only when the widget sits in a detail
tab, and holds that record's projected fields.

```ts excerpt
metric("Paid orders", async (ctx) => ({
  value: await ctx.query("paid-orders", () => countPaid(ctx.db, ctx.dateRange)),
  href: ctx.href("orders", undefined, { filter: { status: "paid" } }),
}));
```

### WidgetFormat

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="WidgetFormat" />

`ctx.format` is `bindFormat(formatting)`: every method reads the admin's `locale`,
`timeZone` and `currency`, so a hint or a list line prints the same day, amount and
duration as a table cell, and a Russian admin never shows `"3 записей"`.

```ts excerpt
stat("Latency", async (ctx) => {
  const s = await ctx.query(latencyStages, ctx.db, ctx.dateRange);
  return {
    value: ctx.format.duration(s.p50Ms),
    hint: `p95 ${ctx.format.duration(s.p95Ms)} · ${ctx.format.plural(s.n, { one: "{n} order", other: "{n} orders" })}`,
  };
});
```

## Shared option types

`Span` is any whole number from `1` to `12` — the widget's width in a 12-column grid. A
section or a widgets tab that declares no `columns` lays out on 12 as soon as one of its
widgets sets `span`, and on its default of 1 or 2 otherwise. Below the `sm` breakpoint every
widget takes the full row.

`NumericFormat` is `"number" | "currency" | "percent" | "bytes" | "duration"`.

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.

Every widget, and a dashboard itself, accepts `realtime`: a channel name, `{ resource: "orders" }`
for that resource's own changes, or a list of either. When one fires, that widget re-runs its
query — the rest of the dashboard stays put. A `{ resource }` that names no registered resource
fails at `defineAdmin` with the name that was probably meant.

Every widget accepts `maxRange`, a whole number of days such as `"30d"`, for rows the
app deletes after that long. The widget queries from `max(from, to − N, now − N)`, so
a range reaching past what is kept is cut, and a comparison never reaches past it
either. When it is cut, the card says so: "Since 2026-08-26; older data is not kept". A
range that ended before `now − N` runs no query at all: the card shows `—` and "No
data: kept for 30 days". On a detail tab, a whole history becomes the last N days,
with the same caption. In development a limit that is not whole days, such as `"1.5d"`,
warns once and caps nothing.

### Captions

Every card has one caption line under its title, computed on the server. In order of
precedence, it shows:
1. the expired state;
2. where `maxRange` cut the range;
3. `freshness`: when the data was last written, in the warn tone with a ▲ past
   `warnAfter`;
4. `coverage`: a note that the data is a sample.

`freshness.at` runs beside the widget's query; one that fails is logged and skipped.
Drawers show only the expired state, and a `custom` widget with `frame: false` has
nowhere to show a caption.

```ts excerpt
metric("Runs today", runsToday, {

});
metric("With analytics consent", consentShare, {
  format: "percent",
  coverage: "users who accepted analytics",
```

## Thresholds

<AutoTypeTable path="../../packages/core/src/types/threshold.ts" name="Threshold" />

Declare where a number turns bad once, and hand the same object to every place that
shows it: `tones` on `metric`, `stat` and `bars`, on a `tracker`, and on the `number`,
`percent` and `duration` column formats. Within the good band the tone is `ok`, and
past `warn` and `err` it is `warn` and `err`. Below `min` observations it is `muted`: a
metric or stat returns its observations as `volume`, and a tracker folds them itself.
`bars` rows carry no volume, so `min` is ignored there. An explicit `tone` always wins. `toneFor(value, threshold, volume)` gives the same
answer for a custom widget or a list row.

```ts excerpt
import { type Threshold, metric, toneFor } from "@flowpanel/kit";

const ERRORS: Threshold = { warn: 0.3, err: 0.5, min: 20 };

metric("Run errors", async (c) => ({ value: rate, volume: runs }), { format: "percent", tones: ERRORS });
const column = { field: "errorRate", format: { kind: "percent", tones: ERRORS } };
toneFor(rate, ERRORS, runs);
```

## Links

A widget link names where it goes instead of spelling a path, so a renamed
`basePath` never breaks it.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="ResourceLink" />

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="DashboardLink" />

`filters` sets dashboard filters on the target, `{ dashboard: "/parsing", filters: { platform: "kwork" } }`.
A key the target does not declare fails at `defineAdmin` (or when a function link
renders), with the closest key. A link never carries the current page's filters on its
own.

A `LinkTarget` is a string, a `ResourceLink` or a `DashboardLink`. A string is used as
written — an external URL or a route of your own app; in development FlowPanel warns
once about a string that starts with the admin's own `basePath`.

- `{ resource: "order" }` is the list, `{ resource: "order", id }` one record, and `tab`
  a detail tab of it.
- `filter` becomes the list's own `f_<field>` keys, and `view` applies one of the
  resource's `views` by name — its search, sort and filters — before them.
- `range` names a `daterange` filter that receives the widget's range bound for bound,
  as `from~to` instants, so the list shows exactly the rows the number counted; the
  filter chip shows the two days in the admin's zone. A detail tab's whole history
  carries no range.
- `filter` is keyed by the target's own fields once the resource is typed. A value is
  written as it is and a `Date` as its day in the admin's zone; `{ gte, lte }` becomes
  `from~to` instants for dates and `min:max` for numbers, and an array becomes `a,b`.
  An object with no URL form throws instead of writing `[object Object]`. `ctx.href`'s
  `filter` is written the same way.
- `{ dashboard: "/system" }` is a dashboard or page by its configured `path`. It
  carries the widget's range — the preset, or `from` and `to` for a custom range —
  unless `range: false`.

A name that is not registered — resource, view, dashboard — throws when the widget
renders and lists what is, so the widget's error card says what to fix.

`ctx.link(target)` resolves the same targets to a string, for the props of a custom
widget:

```ts excerpt
custom(PlatformGrid, async (ctx) => ({
  platforms: (await platforms(ctx.db)).map((p) => ({
    ...p,
    runsHref: ctx.link({ resource: "scraper_run", filter: { platform: p.key }, range: "startedAt" }),
  })),
}));
```

Every link a widget carries takes a `LinkTarget`: a metric's `drilldown` and
`MetricResult.href`, a stat's `href` and `StatResult.href`, a `kv` item's `href` and
`KvResult.href`, a table's `seeAll` and `rowHref`, a chart's `drilldown`, and the
`href` of a `bars`, `funnel` or `list` row. An option set once in the config may also
be a function of the widget context that returns one — or `null` for no link.

## metric

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="metric" />

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricOptions" />

`icon` is handed to the metric card as a React child and rendered verbatim.
Metric icons are deliberately free-form: pass an emoji or a ligature your own
icon font resolves; a Lucide name renders as literal text. This differs from
resource, action and command icons, which use the serializable `IconName`
registry described under [resource icons](/docs/reference/resources#icons).

The sparkline never squeezes the value. On a card too narrow for the value and the
sparkline side by side — two metrics per row on a phone — the sparkline moves under
the value. A value longer than the whole card ends in an ellipsis. A label that runs
out of room stays on one line and shows the full text on hover.

A `metric()` query may return a bare number or string, or a `MetricResult`
carrying the presentation the value itself implies. A result field wins over the
matching static option, which stays as the fallback: `MetricResult.href` renders
as the card's `drilldown`, and `MetricResult.sublabel` as its caption.

A metric that counts rows takes `{ count, where, range }` instead of a query. Its value
is `ctx.count(count, where, { range })`, `compare` counts the period before with the same
scope, and the card links to exactly the rows it counted — the same `where` as list
filters and the same period as the `range` filter — unless you give it a `drilldown`.
When a `where` value is missing, the card counts `0` and has no link, rather than
linking the whole list.

```ts excerpt
metric("Visits", { count: "user_visit", where: (c) => ({ userId: c.id }), range: "startedAt" }, {
  compare: true,
});
metric("Sign-ups", { count: "user", range: "createdAt" }, { compare: true });
```

`where` is keyed by the counted resource's fields and may be a function of the widget
context. For the link to open the same rows, every `where` field must be a column or a
filter of that resource's list and `range` must be one of its `daterange` filters;
`defineAdmin` checks both. Pass `drilldown: () => null` for a card without a link.

`compare: true` queries the period before the picked one as well — the same query
with `ctx.dateRange` set to `ctx.dateRange.previous` — and shows the change against
it with the compared value and the delta rules of `MetricDelta`. For `today` that is
yesterday up to the same clock time; `compare: { against: "weekAgo" }` compares with the
same range seven days earlier instead, so today reads against the same weekday last week.
Pass `compare: { goodWhen: "down" }` for a cost or an error count. It needs a numeric
value, does nothing over a detail tab's whole history or past a widget's `maxRange`, and
yields to a `delta` the query or the `delta` option returns.

```ts excerpt
metric("New users", async (ctx) => countSignups(ctx.db, ctx.dateRange), { compare: true });
```

### MetricResult

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricResult" />

### MetricDelta

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricDelta" />

The card reads a change the way a founder does. Inside ±1 % it shows no arrow and no
colour, and the percentage prints in the admin's locale. With `previous` set it shows
that value muted beside the change (`labels.widget.previous`, `"was {value}"`). A count
whose `previous` is under 20 shows the absolute change — `+3` rather than `+150%` — and a
`format: "percent"` metric shows its change in percentage points (`+3 pp`,
`labels.widget.points`), so 40 % → 43 % never reads as a relative 3 %. `goodWhen: "down"`
colours a fall green — for churn, cost or latency a drop is the good news — and
`"neutral"` never colours.

## table

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="table" />

Point it at a registered `resource` to reuse that resource's columns, or supply
your own `query` and `columns`.

`R` is inferred from `query`, so `columns` is checked against the row that query
returns — a misspelled column is a compile error. A column entry is either a bare
key, which is `keyof R & string` once `R` is known and plain `string` while it is
not, or a `WidgetColumn` object naming and formatting a column the query produced
itself. A bare key on the `resource` path keeps that resource's declared header
and format; an object overrides them.

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="TableWidgetOptions" />

### WidgetColumn

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="WidgetColumn" />

`rowKey` names the field that identifies a row. It defaults to the resource's own
key on the `resource` path and to `"id"` for a `query`; a row without a value
there still renders but never acts.

`rowHref` turns rows into links. It runs on the server, once per row, and
returning `null` leaves that row inert. `seeAll: true` links the card heading to
the resource's list through `ctx.href`; a string is used as the href verbatim.

`emptyState` replaces the table body when there are no rows — a string becomes the
empty state's title, any other node is rendered in the card instead of the table.
With none set the admin's `labels.widget.empty` is used. `limit` caps the rows: it
defaults to 10 on the `resource` path and applies to a `query`'s own rows only
when you set it.

`where` narrows the `resource` read — a filter keyed by its fields, or a function of the
context such as `(c) => ({ userId: c.id })`. Values take the
[`ctx.read` shorthand](/docs/reference/contexts#where-values); a missing value throws
instead of reading every row, and an empty list reads nothing. `range` names a timestamp
field of the resource that the picked range bounds, so "Signups today" is
`table({ resource: "user", range: "createdAt" })`. `defineAdmin` checks both against the
resource's columns and refuses them on a `query` table, which filters its own rows.

```ts excerpt
table({
  resource: "orders",
  label: "Recent orders",
  columns: ["id", { field: "total", label: "Total", format: "money", align: "right" }],
  rowHref: (row, ctx) => ctx.href("orders", row.id),
  seeAll: true,
  limit: 5,
});
```

### StatItem

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatItem" />

`StatValue` is `string | number | boolean | bigint | Date | null | undefined`.
Keeping the literal side explicit preserves full `WidgetContext` autocomplete
inside async `value` resolvers. A `Date` is rendered through the admin's

needs to format one by hand. A resolver may return a [`KvResult`](#kvresult)
instead, so the stat carries its own tone and link.

```ts excerpt
statGroup({

  span: 6,

    { label: "Joined", value: async (ctx) => joinedAt(ctx.row) },

  ],

```

## Cards

Five small cards cover most of what a founder dashboard shows between its metrics
and its tables. Each takes counts and labels only; the card derives the geometry,
formats values through the admin's `formatting` — locale *and* currency, so one
dashboard never prints two currencies for the same money — and colors an item by
its `tone`: a stat, metric or kv value takes the tone's text color, a bar its
fill, and a list row gets a leading dot, with colored text for `warn` and `err`.
Hints, kv values, list text and meta, and bar and funnel labels wrap to two lines
and show the full text on hover; headings, kv labels and numbers stay on one line.

### stat

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="stat" />

One number with a label, without `metric()`'s delta and sparkline machinery. The
value is a literal or a resolver.

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatOptions" />

#### StatResult

A resolver may return a `StatResult` instead of a bare value, so a card computed
from data carries its own tone, caption and link — the same arrangement
`MetricResult` gives `metric()`. A result field wins over the matching static
option, which stays as the fallback. A `Date` is still a value, not a result.

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatResult" />

```ts excerpt
stat("Open invoices", async (ctx) => {
  const filter = { customerId: ctx.id, status: "open" };
  const value = await ctx.count("invoices", filter);
  return { value, href: ctx.href("invoices", undefined, { filter }), tone: value > 0 ? "warn" : "ok" };
});
```

### kv

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="kv" />

The facts about one thing. Each item's `format` accepts a `ColumnFormat` or a
`NumericFormat`, resolved on the server so the card renders a finished string.

An item with `field` shows a field of the card's `record` instead of a `value`. `record`
runs once per card; on a record page it defaults to the viewed row, whose `field`s join the
page's projection, so a profile needs no closure per fact. Its type narrows `field`:

```ts excerpt
kv({
  label: "Feed filters",
  record: (c) => c.read("freelancer_profile", { where: { userId: c.id }, limit: 1 }).then((r) => r[0]),
  items: [{ label: "Rate", field: "hourlyRate", format: "number" }],
});
```

An item with `long` is a paragraph across the card: line breaks are kept and nothing is
clamped. Past `lines` lines (6 by default) — or about 120 characters a line — the rest
folds under "Show all" (`labels.widget.showAll`), with no JavaScript. `empty` prints
instead of "—", muted, when the value is missing or blank.

```ts excerpt
kv({
  label: "Texts",
  columns: 1,
  record: profileOf,
  items: [
    { label: "About", field: "bio", long: true, empty: "Not filled" },
    { label: "Resume", field: "resumeText", long: { lines: 10 }, empty: "Not uploaded" },
  ],
});
```

### bars

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="bars" />

A ranked breakdown. The query returns labels and values; the card sizes every bar
against the largest one, or against `max` when you give it. A rate should set
`max`, or its best row always draws as a full bar:

```ts excerpt
bars({ label: "Win rate by budget", query: async (ctx) => winRates(ctx.db), format: "percent", max: 1 });
```

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="BarsOptions" />

`share: true` shows each row's part of the total beside its value — the Plausible
sources box. By default that is its part of the rows' sum; a top-N query, whose rows
leave the rest out, returns each row's `share` of the real total instead. A row's
`previous` marks its change against the period before with the `MetricDelta` rules: no
arrow inside ±1 %, a count's absolute change below a base of 20, a rate's change in
points, and colour by `goodWhen`.

`compare: true` runs the query a second time for the period before the picked one —
`compare: { against: "weekAgo" }` for the same range seven days earlier — and fills
each row's `previous`, so the change mark needs no `*_prev` query. Rows join by `key`,
else by `label`, and a row's own `previous` wins. A row the earlier period did not
return shows no change; return it with value `0`, or use `breakdown({ keys })`, when
zero is the honest comparison. Nothing is compared over a whole history or past a
widget's `maxRange`. With `top`, pass the compared rows to `breakdown({ previous })`
instead of `compare`, so the rest folds the same keys in both periods.

```ts excerpt
bars({
  label: "New orders by marketplace",
  share: true,
  compare: true,
  query: async (c) => breakdown(await c.query(hourly, c), { by: "platform", value: "orders", keys: PLATFORMS }),
});
```

### funnel

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="funnel" />

Stages in order. Give counts only: the card computes each step's share of the
first step and its drop-off from the one before. The step with the largest drop-off is
marked with the `warn` tone — label and bar — when it loses more than `alertDrop`
of the step before (default `0.5`); pass `alertDrop: 1` to turn the mark off.

#### banner

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="banner" />

"Anything on fire": `list({ variant: "banner", span: 12 })`. Rows are ordered err, then
warn, then info, and within each by `count`. Each carries a glyph as well as a colour
(✕ ▲ ●), so it reads without colour vision, and the strip is tinted by its worst row.
With no rows it shows one ✓ `allClear` line (`labels.widget.allClear`), which is the
answer a founder wants.


#### ListRow

<AutoTypeTable path="../../packages/core/src/types/widget-list.ts" name="ListRow" />

Rows are keyed by their position, so two rows with the same text are both shown.
Give `key` — a record id — when rows are reordered by realtime updates.

```ts excerpt
import { bars, funnel, kv, list, stat } from "@flowpanel/kit";

const widgets = [
  stat("Active trials", async (ctx) => countTrials(ctx.db), { hint: "ends within 7 days" }),
  kv({
    label: "This account",
    items: [
      { label: "Plan", value: "Pro" },
      { label: "Balance", value: async (ctx) => balance(ctx.db), format: "money" },
```

### tracker

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="tracker" />

"Is it healthy right now, per marketplace": one row per key and one block per hour of a
window ending now, whatever the date picker says. The window is 24 hours by default; up
to 48 hours the blocks are hours, beyond that days, all in the admin's zone.

The query receives the window as `ctx.dateRange`. `at` places each row in a block, `by`
makes the rows, and `value` and `volume` fold each block like `series()`. `tones` colours
a block by its value, and a block below `tones.min` observations is muted. A row's dot is
the worst tone of its last three blocks. Each block's hover title and accessible name
reads the time, the value in `format` and the observation count. `summary` may be async,
to read a last success from another table. `rows` takes rows you built yourself instead;
a block without a `title` is named by its row and position, such as "Sync 1/2".
A tracker renders on dashboards and in detail tabs, not in drawers.

## timeline

<ApiSignature path="../../packages/core/src/builders/timeline.ts" name="timeline" />

What happened, newest first, grouped under days of the admin's zone ("Today",
"Yesterday", then dates) with a count per day. Each line has a tone dot, its time (the
full date in its tooltip), a linked title and a meta; a `body` folds under the line.
Consecutive events of one day and one kind with the same `fold` key — the title by
default — fold into one line such as "Orders in feed ×37 09:12–18:40", with the single
events inside. A chip per kind (`kinds`, an `enumOf` or `{ key: [label, tone] }`) filters
the page, and "Older →" pages back. Chips and paging are links under
`?<id>.kind=` and `?<id>.before=`; `id` defaults to the detail tab's key, else
`"timeline"`, so two timelines on one page need their own `id`. The card is rendered on
the server and needs no JavaScript.

`query(ctx, page)` returns events that are not rows of a resource. It receives the page:
return events at or before `page.before` (all of them when it is `null`), at most
`page.limit`, and only `page.kinds` when that is not `null`. FlowPanel merges every list
by time, so a busy kind can never push another kind's newer events off the page.

```ts excerpt
timeline({
  label: "Activity",
  kinds: Activity,
  query: async (ctx, page) => loadEvents(ctx.db, ctx.id, page),
});
```

On a record page a timeline pages through the whole history; `detail.dateRange` does not
narrow it. A timeline cannot sit in a drawer tab: `defineAdmin` points at a detail tab.
"Older →" continues from the last event's moment and skips the events already shown at that
exact moment by count, so when one source holds several rows with the same timestamp at a
page boundary, a database that returns ties in no fixed order may repeat or drop one of them.

<AutoTypeTable path="../../packages/core/src/types/widget-timeline.ts" name="TimelineOptions" />

### Sources

`timeline.source(resource, source)` reads rows of a resource as events, one authorized read
per page (the reader's role, access, scope and field rules apply; a source the reader may not
read adds nothing). `at` is the timestamp; `kind` is a fixed kind or `{ field }`, the column
that holds each row's kind, so one source covers an event log. `refs` names reference
columns whose labels `title` and `meta` receive, resolved in one read per page. A line links
to its first `refs` record, else to the row as its own list opens it; `href: false` leaves it
plain.

```ts excerpt
timeline({
  kinds: Bot,
  sources: [
    timeline.source("telegram_message_log", { kind: { field: "kind" }, at: "createdAt", title: (m) => m.text }),
    timeline.source("notification_log", {
      kind: "failed",
      at: "createdAt",
      tone: "err",
      where: { failedReason: "__notnull__", deliveredAt: "__null__" },
      title: "Delivery failed",
    }),
  ],
});
```

On a record page every source reads only the rows that point at the viewed record: the one
column whose `reference` names this resource, AND-ed with `where`, so a `where` can narrow a
source but never widen it to every record. `by` picks the field when several columns point
at this resource, as a related tab's `by` does; with none, or several and no `by`,
`defineAdmin` throws. A static `where` that sets that field throws too, and a `where`
function's value for it is replaced by the viewed record. On a dashboard a source reads the
rows whose `at` lies in the picked range. `defineAdmin` also checks `resource`, `at`,
`kind`, `by` and `refs`.

## heatmap

<ApiSignature path="../../packages/core/src/builders/activity.ts" name="heatmap" />

How often, day by day: the last `days` days (91, about 13 weeks, by default) ending today,
as weeks side by side and a 12-pixel cell per day, shaded in four steps by quartile, with
month and weekday labels, a legend, a summary line and a tooltip per day. Days are
calendar days of the admin's zone, and weeks start on the locale's first day. The card
scrolls sideways on a phone and needs no JavaScript.

`source` counts rows of a resource — or sums `value` — per day of `at`, a timestamp or a
`YYYY-MM-DD` day. On a record page it reads only the rows that point at the viewed record,
AND-ed with `where`, as a timeline source does: `by` picks the field when several point at
it, and `where` cannot set that field. A source reads at most 10,000 rows; past
that it throws and asks for `query`, which returns totals per day, so the grouping happens
in SQL. A resource needs a single-column key, so a table keyed by `(userId, day)` is read
through `query`.

```ts excerpt
heatmap({ label: "Visits, 13 weeks", source: { resource: "user_visit", at: "startedAt" }, unit: Visits });
```

The heatmap always ends today; a record page's `dateRange` and a dashboard's picker do not
move it, and `maxRange` is ignored.

## checklist

<ApiSignature path="../../packages/core/src/builders/activity.ts" name="checklist" />

## Charts

Chart builders live in `@flowpanel/kit/charts`, which is a separate entry point


### ChartOptionsBase

## Series helpers

A founder screen is one SQL statement per area. These pure helpers turn its rows into
what a card needs, in the admin's zone, so the SQL holds no zone math,
`generate_series` joins, pivots or previous-period twins.

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="series" />

One point per bucket across the range: hours, days, ISO weeks starting on Monday, or
months, bucketed in `range.timeZone`. Pass `ctx.dateRange` and the admin's zone
applies. Keys are `YYYY-MM-DD`, or `YYYY-MM-DDTHH:00` for hours, which chart ticks
already read. `grain: "auto"` picks hours up to 2 days, days up to 92, weeks up to
400 and months beyond.

- **Gaps.** Every bucket is present. A bucket with no rows is `0` for a count or a
  sum, and whatever the `value` function returns for `[]`: return `null` for a ratio
  with no data.
- **Pivots.** Without `by` the one column is `value`, so a sparkline is
  `series(…).map((p) => p.value)`. With `by`, each value of that field is a column;
  `keys` fixes columns that must appear, in order. `top` keeps `keys` and the largest
  other series and folds the rest into `OTHER_KEY`, which charts name
  `labels.widget.other`.
- **Values.** `"12"` strings, bigints and booleans read as numbers. A `YYYY-MM-DD`
  value is that calendar day, and a zoneless timestamp such as `2026-09-21 09:00:00`
  is UTC, as everywhere else in FlowPanel.
- **Whole history.** A range starting at the epoch, such as a record page's
  `ctx.dateRange` without `detail.dateRange`, starts at the first row's bucket; with no
  rows there are no buckets.
- **DST.** On the day clocks skip an hour, that hour has no bucket. On the day they
  repeat one, both of its hours share one bucket.

Folding happens in JavaScript. Above about 50,000 rows, group by hour in SQL first;
development warns once when a fold passes that.

<AutoTypeTable path="../../packages/core/src/runtime/series.ts" name="SeriesOptions" />

<ApiSignature path="../../packages/core/src/runtime/breakdown.ts" name="breakdown" />

One ranked `BarRow` per value of `by`, with `key`, `share` of the real total, and —
given the compared period's rows as `previous` — each row's `previous`. `top` folds
the rest into one `OTHER_KEY` row, so the shares still add up to 1. `labels` takes a
map, an `enumOf()` or a function. Shares only mean something for counts and sums.

<AutoTypeTable path="../../packages/core/src/runtime/breakdown.ts" name="BreakdownOptions" />

<ApiSignature path="../../packages/core/src/runtime/preset-range.ts" name="presetRange" />

A preset's bounds now, in the admin's zone: the same range the date picker would
give it. It is for a query that needs a fixed window such as "today, 7 days and 30
days" beside the picked one. Pass one `now` as the third argument when several
widgets share a query, so their ranges match and the query runs once.

```ts excerpt
import { barChart } from "@flowpanel/kit/charts";
import { bars, breakdown, series, type WidgetContext } from "@flowpanel/kit";

const hourly = (c: WidgetContext) => c.sql<{ at: Date; platform: string; orders: number }>`
  select hour as at, platform, orders_new as orders
  from scraper_hourly_stats where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}`;

bars({
  label: "New orders by marketplace",
  share: true,
  query: async (c) => breakdown(await c.query(hourly, c), { by: "platform", value: "orders", labels: Platform }),
});
barChart(
  "New orders by day",
  async (c) => series(await c.query(hourly, c), c.dateRange, { at: "at", by: "platform", value: "orders", grain: "day" }),
  { x: "date", labels: Platform, stacked: true },
);
```

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="previousRange" />

The range of the same length ending where the given one begins. The shift is elapsed
time, not calendar days: the window before a week that crosses a DST boundary starts
an hour off the wall clock. `ctx.dateRange.previous` is usually what you want.

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="fillDays" />

`series` with one day per bucket and one summed field, kept for existing code:
`fillDays(rows, dateRange, { dateField: "day", valueField: "total" })` equals
`series(rows, dateRange, { at: "day", value: "total", grain: "day" })`. There is one
bucket per calendar day the range touches, both ends included, so `last7d` yields
eight buckets whose first is a partial day.

### DateRangeConfig

<AutoTypeTable path="../../packages/core/src/types/dashboard.ts" name="DateRangeConfig" />

`DateRangePreset` is `"today" | "yesterday" | "last7d" | "last30d" | "MTD" | "QTD" | "YTD"`.

`today`, `yesterday`, `MTD`, `QTD` and `YTD` start at midnight in `formatting.timeZone`
(UTC when it is not set); `last7d` and `last30d` are the last 7 × 24 and 30 × 24 hours.

`presets` narrows the picker to the periods a dashboard's data can answer — an
order-linked page whose rows live 30 days offers `["today", "yesterday", "last7d",
"last30d"]`. A `?preset=` outside the list is ignored and dropped from the URL, and
`preset` defaults to the first entry. A range given as `?from=…&to=…`, as a link from a
custom period carries it, shows as its two days in the picker.

### DashboardFilter

<AutoTypeTable path="../../packages/core/src/types/dashboard.ts" name="DashboardFilter" />

`filters` puts one select per entry beside the date picker. A picked value lands in
the URL as `f_<key>`, the list convention, so a filtered dashboard is a link;
choosing "All" drops one filter and "Clear filters" drops them all. `options` takes a
list, an `enumOf()`, or a function of the context.

`bars`, `tracker` and `table` take `filter: "<key>"`: clicking a bar, a tracker row or
a table row sets that filter on the current dashboard, keeping the range. A bar sets
the filter by its `key`; `breakdown()` fills it, and the folded rest is not a link.
`filter` replaces the row's own `href` or the table's `rowHref`. `defineAdmin`
rejects a `filter` the dashboard does not declare, with the closest key, and a `filter`
on a record page or in a drawer. While a filter is set, an empty card says the filters
left nothing (`labels.widget.filtered`) and links to clear them, and an empty banner
says it instead of "All clear". A chart keeps its own empty text.

```ts excerpt
const byPlatform: DashboardFilter = { key: "platform", label: "Marketplace", options: Platform };

const hourly = (c: WidgetContext) => c.sql<HourRow>`
  select hour as at, platform, runs_total as runs from scraper_hourly_stats
  where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}
    and (${c.filters.platform ?? null}::text is null or platform = ${c.filters.platform ?? null})`;

dashboard({
  path: "/parsing",
  label: "Parsing",
  filters: [byPlatform],
  sections: [{ columns: 12, widgets: [tracker({ query: hourly, at: "at", by: "platform", filter: "platform", span: 12 })] }],
});
```
