Widgets are the contents of a dashboard section, of a detail page's widgets tab,
and of a drawer's widget tab. Each builder returns a `WidgetConfig`; every
`query` runs on the server with a `WidgetContext`. In a detail tab and in a
drawer the record being viewed is `ctx.row`; a drawer renders its widgets as
static cards (see [Drawers](/docs/reference/drawer#drawertabwidgets)).

```ts excerpt
import { dashboard, metric, statGroup, table } from "@flowpanel/kit";
import { areaChart } from "@flowpanel/kit/charts";

export const overview = dashboard({
  path: "/",
  label: "Overview",
  dateRange: { preset: "last30d" },
  sections: [
    {
      label: "Revenue",
      widgets: [
        metric("MRR", async ({ db, dateRange }) => mrr(db, dateRange), {
          format: "currency",
          span: 3,
          drilldown: "/admin/invoices",
        }),
        areaChart("Revenue over time", async ({ db }) => revenueSeries(db), {
          x: "day",
          y: ["subscriptions", "one-off"],
          stacked: true,
          span: 9,
        }),
      ],
    },
  ],
});
```

## WidgetContext

What every widget `query` receives.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="WidgetContext" />

`href` builds a link under the admin's own `basePath`, so a config never
hand-types `/admin/…`. `href("orders")` is the list, `href("orders", id)` one
record, and the third argument adds the list page's own query keys —
`{ filter: { status: "paid" } }` becomes `?f_status=paid` and `{ tab: "activity" }`
becomes `?tab=activity`.

`query` memoises for the request, so two widgets that need the same figure run it
once and the next request queries again. Pass a key and a thunk —
`query("mrr", () => mrr(db))` — or the function and its arguments —
`query(mrr, db, ctx.dateRange)` — to key the call by the function and its
arguments: strings, numbers, booleans and dates by value, objects by identity. The
memo holds the promise, so a failure is shared too — the request does not retry.
Pass a function declared once, like `mrr`: one written inline —
`query(async () => …)` — is a new function on every call and never shares.

`count` is memoised the same way: one resource and `where`, written in any key
order, count once per request. `id` is the viewed record's key as a string, read
through the resource's `rowKey`; a dashboard widget has none.

`dateRange` is a `WidgetDateRange`: the picked range, `previous` and `timeZone`, the
admin's `formatting.timeZone`. `previous` is the period a founder compares with. For
`today`, `yesterday`, `MTD`, `QTD` and `YTD` it is the same stretch one day, month,
quarter or year back at the same clock time, so today at 10:00 compares with yesterday
until 10:00. For `last7d`, `last30d` and a custom range it is the span of the same length
before it, and over a detail tab's whole history it is `null`. Query the previous period
with `ctx.dateRange.previous`; hand `ctx.dateRange` to `fillDays` and days bucket in the
admin's zone.

`labels` is the admin's resolved `LabelsConfig`, which is where a widget's own
wording should come from. `row` is present only when the widget sits in a detail
tab, and holds that record's projected fields.

```ts excerpt
metric("Paid orders", async (ctx) => ({
  value: await ctx.query("paid-orders", () => countPaid(ctx.db, ctx.dateRange)),
  href: ctx.href("orders", undefined, { filter: { status: "paid" } }),
}));
```

### WidgetFormat

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="WidgetFormat" />

`ctx.format` is `bindFormat(formatting)`: every method reads the admin's `locale`,
`timeZone` and `currency`, so a hint or a list line prints the same day, amount and
duration as a table cell, and a Russian admin never shows `"3 записей"`.

```ts excerpt
stat("Latency", async (ctx) => {
  const s = await ctx.query(latencyStages, ctx.db, ctx.dateRange);
  return {
    value: ctx.format.duration(s.p50Ms),
    hint: `p95 ${ctx.format.duration(s.p95Ms)} · ${ctx.format.plural(s.n, { one: "{n} order", other: "{n} orders" })}`,
  };
});
```

## Shared option types

`Span` is any whole number from `1` to `12` — the widget's width in a
`columns: 12` section. Below the `sm` breakpoint every widget takes the full
row.

`NumericFormat` is `"number" | "currency" | "percent" | "bytes" | "duration"`.

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.

Every widget accepts `realtime`, a channel name or list. When one fires, that
widget re-runs its query — the rest of the dashboard stays put.

## Links

A widget link names where it goes instead of spelling a path, so a renamed
`basePath` never breaks it.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="ResourceLink" />

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="DashboardLink" />

A `LinkTarget` is a string, a `ResourceLink` or a `DashboardLink`. A string is used as
written — an external URL or a route of your own app; in development FlowPanel warns
once about a string that starts with the admin's own `basePath`.

- `{ resource: "order" }` is the list, `{ resource: "order", id }` one record, and `tab`
  a detail tab of it.
- `filter` becomes the list's own `f_<field>` keys, and `view` applies one of the
  resource's `views` by name — its search, sort and filters — before them.
- `range` names a `daterange` filter that receives the widget's range bound for bound,
  as `from~to` instants, so the list shows exactly the rows the number counted; the
  filter chip shows the two days in the admin's zone. A detail tab's whole history
  carries no range.
- A `Date` in `filter` is written as its day in the admin's zone.
- `{ dashboard: "/system" }` is a dashboard or page by its configured `path`. It
  carries the widget's range — the preset, or `from` and `to` for a custom range —
  unless `range: false`.

A name that is not registered — resource, view, dashboard — throws when the widget
renders and lists what is, so the widget's error card says what to fix.

`ctx.link(target)` resolves the same targets to a string, for the props of a custom
widget:

```ts excerpt
custom(PlatformGrid, async (ctx) => ({
  platforms: (await platforms(ctx.db)).map((p) => ({
    ...p,
    runsHref: ctx.link({ resource: "scraper_run", filter: { platform: p.key }, range: "startedAt" }),
  })),
}));
```

Every link a widget carries takes a `LinkTarget`: a metric's `drilldown` and
`MetricResult.href`, a stat's `href` and `StatResult.href`, a `kv` item's `href` and
`KvResult.href`, a table's `seeAll` and `rowHref`, a chart's `drilldown`, and the
`href` of a `bars`, `funnel` or `list` row. An option set once in the config may also
be a function of the widget context that returns one — or `null` for no link.

`icon` is handed to the metric card as a React child and rendered verbatim.
Metric icons are deliberately free-form: pass an emoji or a ligature your own
icon font resolves; a Lucide name renders as literal text. This differs from
resource, action and command icons, which use the serializable `IconName`
registry described under [resource icons](/docs/reference/resources#icons).

A `metric()` query may return a bare number or string, or a `MetricResult`
carrying the presentation the value itself implies. A result field wins over the
matching static option, which stays as the fallback: `MetricResult.href` renders
as the card's `drilldown`, and `MetricResult.sublabel` as its caption.

## table

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="table" />

Point it at a registered `resource` to reuse that resource's columns, or supply
your own `query` and `columns`.

`R` is inferred from `query`, so `columns` is checked against the row that query
returns — a misspelled column is a compile error. A column entry is either a bare
key, which is `keyof R & string` once `R` is known and plain `string` while it is
not, or a `WidgetColumn` object naming and formatting a column the query produced
itself. A bare key on the `resource` path keeps that resource's declared header
and format; an object overrides them.

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="TableWidgetOptions" />

### WidgetColumn

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="WidgetColumn" />

`rowKey` names the field that identifies a row. It defaults to the resource's own
key on the `resource` path and to `"id"` for a `query`; a row without a value
there still renders but never acts.

`rowHref` turns rows into links. It runs on the server, once per row, and
returning `null` leaves that row inert. `seeAll: true` links the card heading to
the resource's list through `ctx.href`; a string is used as the href verbatim.

`emptyState` replaces the table body when there are no rows — a string becomes the
empty state's title, any other node is rendered in the card instead of the table.
With none set the admin's `labels.widget.empty` is used. `limit` caps the rows: it
defaults to 10 on the `resource` path and applies to a `query`'s own rows only
when you set it.

```ts excerpt
table({
  resource: "orders",
  label: "Recent orders",
  columns: ["id", { field: "total", label: "Total", format: "money", align: "right" }],
  rowHref: (row, ctx) => ctx.href("orders", row.id),
  seeAll: true,
  limit: 5,
});
```

### StatItem

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatItem" />

`StatValue` is `string | number | boolean | bigint | Date | null | undefined`.
Keeping the literal side explicit preserves full `WidgetContext` autocomplete
inside async `value` resolvers. A `Date` is rendered through the admin's
`formatting` — its `locale` and `timeZone` — like a table cell, so no resolver
needs to format one by hand. A resolver may return a [`KvResult`](#kvresult)
instead, so the stat carries its own tone and link.

```ts excerpt
statGroup({
  label: "Account",
  span: 6,
  stats: [
    { label: "Plan", value: async (ctx) => planOf(ctx.row) },
    { label: "Joined", value: async (ctx) => joinedAt(ctx.row) },
    { label: "Open invoices", value: async (ctx) => ctx.count("invoices", { status: "open" }) },
  ],
});
```

## Cards

Five small cards cover most of what a founder dashboard shows between its metrics
and its tables. Each takes counts and labels only; the card derives the geometry,
formats values through the admin's `formatting` — locale *and* currency, so one
dashboard never prints two currencies for the same money — and colors an item by
its `tone`: a stat, metric or kv value takes the tone's text color, a bar its
fill, and a list row gets a leading dot, with colored text for `warn` and `err`.
Hints, kv values, list text and meta, and bar and funnel labels wrap to two lines
and show the full text on hover; headings, kv labels and numbers stay on one line.

### stat

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="stat" />

One number with a label, without `metric()`'s delta and sparkline machinery. The
value is a literal or a resolver.

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatOptions" />

#### StatResult

A resolver may return a `StatResult` instead of a bare value, so a card computed
from data carries its own tone, caption and link — the same arrangement
`MetricResult` gives `metric()`. A result field wins over the matching static
option, which stays as the fallback. A `Date` is still a value, not a result.

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatResult" />

```ts excerpt
stat("Open invoices", async (ctx) => {
  const filter = { customerId: ctx.row?.id, status: "open" };
  const value = await ctx.count("invoices", filter);
  return { value, href: ctx.href("invoices", undefined, { filter }), tone: value > 0 ? "warn" : "ok" };
});
```

## Charts

Chart builders live in `@flowpanel/kit/charts`, which is a separate entry point
so the recharts bundle never loads for admins that use no charts.

```ts excerpt
import { areaChart, barChart, lineChart, pieChart } from "@flowpanel/kit/charts";
```

Each takes `(label, query, options)`, where `query` returns an array of rows.
The row type is inferred from `query`, so `x` / `y` (and `category` / `value` on
a pie) must name keys of that row — a typo is a compile error. A `query` typed
as `unknown[]` leaves them as plain strings.

## Series helpers

Two pure helpers for the shape a dashboard query usually needs. Bucketing itself
stays in SQL, where the dialect belongs.

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="previousRange" />

The range of the same length ending where the given one begins — the comparison
period a `MetricDelta` is measured against. The shift is elapsed time, not calendar
days: the window before a week that crosses a DST boundary starts an hour off the
wall clock.

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="fillDays" />

Turns sparse grouped rows into one point per day across the range, so a chart
draws a flat stretch where nothing happened instead of skipping the day. Days are
bucketed in `timeZone`, else the range's own `timeZone` — pass `ctx.dateRange` and the
admin's zone applies — else UTC. There is one bucket per calendar day the range
touches, both ends included, so the `last7d` preset — `now - 7d … now` — yields
eight buckets and the first one is a partial day. Narrow the range, or slice the
result, if a chart should show exactly seven bars.

```ts excerpt
import { fillDays, previousRange } from "@flowpanel/kit";

areaChart("Signups", async ({ db, dateRange }) => {
  const rows = await signupsByDay(db, dateRange);
  return fillDays(rows, dateRange, { dateField: "day", valueField: "total" });
}, { x: "date", y: "value" });

const before = previousRange(dateRange);
```
