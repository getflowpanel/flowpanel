Widgets fill dashboard sections, record page tabs and drawer tabs. Each builder
returns a `WidgetConfig`; every `query` runs on the server with a `WidgetContext`.
On a record page or in a drawer, `ctx.row` is the record. A drawer renders
[static cards](/docs/reference/drawer#drawertabwidgets).

```ts excerpt
import { areaChart, dashboard, metric, statGroup, table } from "@flowpanel/kit";

export const overview = dashboard({
  path: "/",
  label: "Overview",
  dateRange: { preset: "last30d" },
  sections: [
    {
      label: "Revenue",
      widgets: [
        metric("MRR", async ({ db, dateRange }) => mrr(db, dateRange), {
          format: "currency",
          span: 3,
          drilldown: { resource: "invoices" },
        }),
        areaChart("Revenue over time", async ({ db }) => revenueSeries(db), {
          x: "day",
          y: ["subscriptions", "one-off"],
          stacked: true,
          span: 9,
        }),
      ],
    },
  ],
});
```

## WidgetContext

What every widget `query` receives.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="WidgetContext" />

`link` turns a named target into an href under `paths.admin`:
`link({ resource: "orders" })` is the list, `{ resource: "orders", id }` one record,
and `{ filter: { status: "paid" } }` adds `?f_status=paid`. Where an option takes a
link, pass the target itself.

`query` memoises for the request, so widgets that ask the same question run it
once. Pass a key and a thunk, `query("mrr", () => mrr(db))`, or a function and its
arguments, `query(mrr, db, ctx.dateRange)`; arguments key by value (objects by
identity). A failure is shared too. Use a function declared once: an inline one is
new on every call and never shares. A function passed alone that declares a
parameter receives the context, so `query(hourly)` runs `hourly(ctx)` once; a
function whose parameters are all defaulted is called with none. The `compare`
period runs it again with its own range.

`count` is memoised the same way: one resource and `where`, written in any key
order, count once per request. `id` is the viewed record's key as a string, read
through the resource's `rowKey`; a dashboard widget has none.

`dateRange` is the picked range with `previous` and `timeZone`. For `today`,
`yesterday`, `MTD`, `QTD` and `YTD`, `previous` is the same stretch one period back
at the same clock time; for `last7d`, `last30d` and a custom range it is the span
of the same length before. Over a record's whole history it is `null`.

`filters` holds the dashboard's active filters by key, `{ platform: "kwork" }` for
`?f_platform=kwork`, and is `{}` when none is set. Bind it in your own query.

`labels` is the resolved `LabelsConfig`. `row` is set on a record page.

```ts excerpt
metric("Paid orders", async (ctx) => ({
  value: await ctx.query("paid-orders", () => countPaid(ctx.db, ctx.dateRange)),
  href: { resource: "orders", filter: { status: "paid" } },
}));
```

## Shared option types

`Span` is a whole number from `1` to `12`. A section without `columns` uses 12
columns once a widget sets `span`. On a phone every widget takes the full row.

`NumericFormat` is `"number" | "currency" | "percent" | "bytes" | "duration"`.

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.

Every widget and dashboard accepts `realtime`: a channel name, `{ resource: "orders" }`,
or a list of them. When one fires, only that widget re-runs.

`maxRange`, such as `"30d"`, is for rows your app deletes after that long. The
widget queries from `max(from, to − N, now − N)` and says so in its caption; a
range that ended before `now − N` runs no query and shows `—`. `heatmap` and
`tracker` do not take it.

### Captions

A card shows at most one caption under its title, in this order of precedence:
1. the expired state;
2. where `maxRange` cut the range;
3. `freshness`: when the data was last written, in the warn tone with a ▲ past
   `warnAfter`;
4. `coverage`: a note that the data is a sample.

A failing `freshness.at` is logged and skipped.

<AutoTypeTable path="../../packages/core/src/types/widget-caption.ts" name="CaptionOptions" />

<AutoTypeTable path="../../packages/core/src/types/widget-caption.ts" name="Freshness" />

```ts excerpt
metric("Runs today", runsToday, {
  freshness: { at: async (c) => lastRollupHour(c), warnAfter: "2h" },
});
metric("With analytics consent", consentShare, {
  format: "percent",
  coverage: "users who accepted analytics",
});
```

## Thresholds

<AutoTypeTable path="../../packages/core/src/types/threshold.ts" name="Threshold" />

Pass one threshold as `tones` to `metric`, `stat`, `bars`, `tracker` and the
`number`, `percent` and `duration` column formats. The tone is `ok`, `warn` or `err`,
and `muted` below `min` observations (a metric or stat returns them as `volume`).
An explicit `tone` wins. `toneFor(value, threshold, volume)` gives the same answer
in your own code.

`warn` below `err` means higher is worse; `warn` above `err` means lower is worse.
A `goodWhen` that contradicts the numbers makes `defineAdmin` throw.

```ts excerpt
import { type Threshold, metric, resource, toneFor } from "@flowpanel/kit";

const ERRORS: Threshold = { warn: 0.3, err: 0.5, min: 20 };

metric("Run errors", async (c) => ({ value: rate, volume: runs }), { format: "percent", tones: ERRORS });
resource(schema.runs, { columns: [{ field: "errorRate", format: { kind: "percent", tones: ERRORS } }] });
toneFor(rate, ERRORS, runs);
```

## Links

A widget link names its target instead of spelling a path.

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="ResourceLink" />

<AutoTypeTable path="../../packages/core/src/types/widget-context.ts" name="DashboardLink" />

A `LinkTarget` is a string (used as written), a `ResourceLink` or a `DashboardLink`.

- `{ resource: "order" }` is the list, `{ resource: "order", id }` one record, and `tab`
  a record tab.
- `filter` becomes the list's `f_<field>` keys, or a dashboard's declared filters. A
  `Date` is written as its day, `{ gte, lte }` as a range, an array as `a,b`. A key
  the target does not declare fails at `defineAdmin`.
- `view` applies one of the resource's saved `views`.
- `range` on a resource link names the `daterange` filter that receives the widget's
  range, so the list shows exactly the counted rows.
- `{ dashboard: "/system" }` is a dashboard or page by `path`. It carries the widget's
  range unless `range: false`.

An unregistered resource, view or dashboard throws and lists the registered ones.

`ctx.link(target)` resolves the same targets to a string, for the props of a custom
widget:

```ts excerpt
custom(PlatformGrid, async (ctx) => ({
  platforms: (await platforms(ctx.db)).map((p) => ({
    ...p,
    runsHref: ctx.link({ resource: "scraper_run", filter: { platform: p.key }, range: "startedAt" }),
  })),
}));
```

Every widget link option takes a `LinkTarget`, or a function of the context that
returns one or `null`.

## metric

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="metric" />

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricOptions" />

A metric's `icon` is rendered as given, such as an emoji; it is not an `IconName`.

A query returns a number, a string, or a `MetricResult`, whose fields win over the
matching options.

A metric that counts rows takes `{ count, where, range }` instead of a query. Its
value is `ctx.count(count, where, { range })`, and it links to exactly the rows it
counted unless you set `drilldown`. A missing `where` value counts `0` with no link.

```ts excerpt
metric("Visits", { count: "user_visit", where: (c) => ({ userId: c.id }), range: "startedAt" }, {
  compare: true,
});
metric("Sign-ups", { count: "user", range: "createdAt" }, { compare: true });
```

`where` may be a function of the context. Its fields must be columns or filters of
the counted list, and `range` one of its `daterange` filters; `defineAdmin` checks
both. `drilldown: () => null` removes the link.

`compare: true` runs the query again with `ctx.dateRange.previous` and shows the
change; `compare: { against: "weekAgo" }` compares with the same range seven days
earlier. Set `goodWhen: "down"` for costs and errors. A `delta` from the query wins.

```ts excerpt
metric("New users", async (ctx) => countSignups(ctx.db, ctx.dateRange), { compare: true });
```

### MetricResult

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricResult" />

### MetricDelta

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="MetricDelta" />

The change prints signed (`+12%`, `−3`). Inside ±1 % it has no sign, and only a
change of 5 % or more is coloured. With `previous` set, the old value shows beside
it. A count whose `previous` is under 20 shows the absolute change, and a
`format: "percent"` metric its change in points (`+3 pp`). `goodWhen: "down"`
colours a fall as good; `"neutral"` never colours.

## table

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="table" />

Point it at a `resource` to reuse its columns, or pass your own `query` and
`columns`, which are checked against the query's row type. On the `resource`
path a bare key keeps the resource's header and format; an object overrides them.

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="TableWidgetOptions" />

### WidgetColumn

<AutoTypeTable path="../../packages/core/src/types/widget.ts" name="WidgetColumn" />

`rowKey` defaults to the resource's key, or `"id"` for a `query`. `rowHref` links
each row (`null` for none); `seeAll: true` links the heading to the list. `limit`
defaults to 10 on the `resource` path. `density: "compact"` sets 40 px rows.

`where` narrows the `resource` read with [`ctx.read` values](/docs/reference/contexts#where-values),
or a function such as `(c) => ({ userId: c.id })`. `range` names the timestamp the
picked range bounds: `table({ resource: "user", range: "createdAt" })`.

```ts excerpt
table({
  resource: "orders",
  label: "Recent orders",
  columns: ["id", { field: "total", label: "Total", format: "money", align: "right" }],
  rowHref: (row) => ({ resource: "orders", id: row.id }),
  seeAll: true,
  limit: 5,
});
```

### stat

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="stat" />

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatOptions" />

#### StatResult

A resolver may return a `StatResult`, whose fields win over the options.

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="StatResult" />

```ts excerpt
stat("Open invoices", async (ctx) => {
  const filter = { customerId: ctx.id, status: "open" };
  const value = await ctx.count("invoices", filter);
  return { value, href: { resource: "invoices", filter }, tone: value > 0 ? "warn" : "ok" };
```

### kv

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="kv" />

Facts about one thing. An item's `format` takes a `ColumnFormat` or `NumericFormat`.
An item with `field` reads the card's `record`, which runs once and defaults to the
viewed row on a record page:

```ts excerpt
kv({
  label: "Feed filters",
  record: (c) => c.read("freelancer_profile", { where: { userId: c.id }, limit: 1 }).then((r) => r[0]),
  items: [{ label: "Rate", field: "hourlyRate", format: "number" }],
});
```

An item with `long` is a paragraph; past `lines` lines (6 by default) the rest
folds under "Show all". `empty` replaces "—" for a missing value.

```ts excerpt
kv({
  label: "Texts",
  columns: 1,
  record: profileOf,
  items: [
    { label: "About", field: "bio", long: true, empty: "Not filled" },
    { label: "Resume", field: "resumeText", long: { lines: 10 }, empty: "Not uploaded" },
  ],
});
```

### bars

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="bars" />

A ranked breakdown, sized against the largest value or `max`. Set `max` for a
rate:

```ts excerpt
bars({ label: "Win rate by budget", query: async (ctx) => winRates(ctx.db), format: "percent", max: 1 });
```

<AutoTypeTable path="../../packages/core/src/types/widget-cards.ts" name="BarsOptions" />

`share: true` shows each row's share of the total; a top-N query returns each
row's `share` itself. A row's `previous` shows its change with the `MetricDelta`
rules.

`compare: true` (or `{ against: "weekAgo" }`) runs the query for the earlier period
and fills each row's `previous`, joining by `key`, else `label`. A row missing from
the earlier period shows no change; `breakdown({ keys })` keeps it at zero. With
`top`, pass the earlier rows to `breakdown({ previous })` instead.

```ts excerpt
bars({
  label: "New orders by marketplace",
  share: true,
  compare: true,
  query: async (c) => breakdown(await c.query(hourly), { by: "platform", value: "orders", keys: PLATFORMS }),
});
```

### tracker

<ApiSignature path="../../packages/core/src/builders/widget.ts" name="tracker" />

One row per key and one block per hour of a window ending now, regardless of the
date picker. The window is 24 hours by default; past 48 hours the blocks are days.

The query receives the window as `ctx.dateRange`. `at` places rows in blocks, `by`
makes the rows, and `value` and `volume` fold each block like `series()`. `tones`
colours blocks; a row's dot is the worst of its last three. `rows` takes prebuilt
rows instead. Not available in drawers.

<AutoTypeTable path="../../packages/core/src/types/widget-tracker.ts" name="TrackerOptions" />

```ts excerpt
tracker({
  label: "Marketplaces · 24 h",
  query: hourly,
  at: "at",
  by: "platform",
  labels: Platform,
  value: errorRate,
  volume: "runs",
  tones: { warn: 0.3, err: 0.5, min: 20 },
  format: "percent",
  summary: async (row, c) => lastSuccess(await c.query(platformHealth), row.key, c.format),
  span: 12,
});
```

## timeline

<ApiSignature path="../../packages/core/src/builders/timeline.ts" name="timeline" />

Events newest first, grouped by day. Consecutive events of one kind with the same
`fold` key collapse into one line. A chip per kind (`kinds`) filters, and "Older"
pages back, under `?<id>.kind=` and `?<id>.before=`; `id` defaults to the tab key.

`query(ctx, page)` returns events that are not resource rows: at or before
`page.before`, at most `page.limit`, of `page.kinds` when set.

```ts excerpt
timeline({
  label: "Activity",
  kinds: Activity,
  query: async (ctx, page) => loadEvents(ctx.db, ctx.id, page),
});
```

On a record page a timeline covers the whole history, ignoring `detail.dateRange`.
Not available in drawers.

<AutoTypeTable path="../../packages/core/src/types/widget-timeline.ts" name="TimelineOptions" />

### Sources

`timeline.source(resource, source)` reads a resource's rows as events, with the
reader's access applied. `at` is the timestamp; `kind` is fixed or `{ field }`.
`refs` names reference columns whose labels reach `title` and `meta`.

```ts excerpt
timeline({
  kinds: Bot,
  sources: [
    timeline.source("telegram_message_log", { kind: { field: "kind" }, at: "createdAt", title: (m) => m.text }),
    timeline.source("notification_log", {
      kind: "failed",
      at: "createdAt",
      tone: "err",
      where: { failedReason: "__notnull__", deliveredAt: "__null__" },
      title: "Delivery failed",
    }),
  ],
});
```

On a record page a source reads only rows referencing the record, AND-ed with
`where`; `by` picks the column when several reference it. On a dashboard it reads
rows whose `at` is in the picked range.

## checklist

<ApiSignature path="../../packages/core/src/builders/activity.ts" name="checklist" />

## Charts

The chart builders come from `@flowpanel/kit`. Recharts loads only when a chart is on the page.

```ts excerpt
import { areaChart, barChart, lineChart, pieChart } from "@flowpanel/kit";
```

Each takes `(label, query, options)`. `x` and `y` (`category` and `value` on a pie)
are checked against the query's row type.

### ChartOptionsBase

Shared by area, bar and line charts.

<AutoTypeTable path="../../packages/core/src/types/widget-charts.ts" name="ChartOptionsBase" />

`ChartBucket` is `"minute" | "hour" | "day" | "week" | "month" | "year" | "auto"`.

Without `y`, the chart plots every numeric key of its first row except `x`, which
is what `series({ by })` returns. `labels` names the series. `bucket` only formats
date ticks; aggregate with `series({ grain })`.

One series draws in `--fp-data`; several use `--fp-chart-1` to `--fp-chart-7` in `y`
order. `colors` pins a series to a colour:

```ts excerpt
lineChart("Signups", signupsByPlan, {
  x: "day",
  y: ["trial", "paid"],
  colors: { paid: "hsl(var(--fp-chart-1))", trial: "hsl(var(--fp-chart-2))" },
});
```

## Series helpers

Pure helpers that turn query rows into chart and bar data in the admin's zone.

<ApiSignature path="../../packages/core/src/runtime/series.ts" name="series" />

One point per bucket across the range: hours, days, ISO weeks starting on Monday, or
months, bucketed in `range.timeZone`. Pass `ctx.dateRange` and the admin's zone
applies. Keys are `YYYY-MM-DD`, or `YYYY-MM-DDTHH:00` for hours, which chart ticks
already read. `grain: "auto"` picks hours up to 2 days, days up to 92, weeks up to
400 and months beyond.

- **Gaps.** Every bucket is present. A bucket with no rows is `0` for a count or a
  sum, and whatever the `value` function returns for `[]`: return `null` for a ratio
  with no data.
- **Pivots.** Without `by` the one column is `value`, so a sparkline is
  `series(…).map((p) => p.value)`. With `by`, each value of that field is a column;
  `keys` fixes columns that must appear, in order. `top` keeps `keys` and the largest
  other series and folds the rest into `OTHER_KEY`, which charts name
  `labels.widget.other`.
- **Values.** `"12"` strings, bigints and booleans read as numbers. A `YYYY-MM-DD`
  value is that calendar day, and a zoneless timestamp such as `2026-09-21 09:00:00`
  is UTC, as everywhere else in FlowPanel.
- **Whole history.** A range starting at the epoch, such as a record page's
  `ctx.dateRange` without `detail.dateRange`, starts at the first row's bucket; with no
  rows there are no buckets.
- **DST.** On the day clocks skip an hour, that hour has no bucket. On the day they
  repeat one, both of its hours share one bucket.

Folding runs in JavaScript. Above about 50,000 rows, group by hour in SQL first.

<ApiSignature path="../../packages/core/src/runtime/breakdown.ts" name="breakdown" />

One ranked `BarRow` per value of `by`, with `key` and `share`, and each row's
`previous` when you pass the earlier period's rows as `previous`. `top` folds
the rest into one `OTHER_KEY` row, so the shares still add up to 1. `labels` takes a
map, an `enumOf()` or a function. Shares only mean something for counts and sums.

<AutoTypeTable path="../../packages/core/src/runtime/breakdown.ts" name="BreakdownOptions" />

<ApiSignature path="../../packages/core/src/runtime/preset-range.ts" name="presetRange" />

A preset's bounds now, in the admin's zone, for a query that needs a fixed window
beside the picked one. Pass the same `now` to widgets sharing a query.

```ts excerpt
import { barChart, bars, breakdown, series, type WidgetContext } from "@flowpanel/kit";

const hourly = (c: WidgetContext) => c.sql<{ at: Date; platform: string; orders: number }>`
  select hour as at, platform, orders_new as orders
  from scraper_hourly_stats where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}`;

bars({
  label: "New orders by marketplace",
  share: true,
  query: async (c) => breakdown(await c.query(hourly), { by: "platform", value: "orders", labels: Platform }),
});
barChart(
  "New orders by day",
  async (c) => series(await c.query(hourly), c.dateRange, { at: "at", by: "platform", value: "orders", grain: "day" }),
  { x: "date", labels: Platform, stacked: true },
);
```

### SectionConfig

<AutoTypeTable path="../../packages/core/src/types/dashboard.ts" name="SectionConfig" />

`variant: "strip"` draws `metric` and `stat` widgets as one band without cards.
`columns` sets cells per line (up to six by default; two on a phone). A record
page's [`detail.stats`](/docs/reference/resources#record-page) is the same strip.

In a `"cards"` section, `table` and `list` cards keep their height and others
stretch to the row; `align: "start"` or `"stretch"` sets it for all.

```ts excerpt
{ variant: "strip", widgets: [newOrders, runs, successRate, bans] }
```

### DateRangeConfig

<AutoTypeTable path="../../packages/core/src/types/dashboard.ts" name="DateRangeConfig" />

`DateRangePreset` is `"today" | "yesterday" | "last7d" | "last30d" | "MTD" | "QTD" | "YTD"`.

`today`, `yesterday`, `MTD`, `QTD` and `YTD` start at midnight in `formatting.timeZone`
(UTC when it is not set); `last7d` and `last30d` are the last 7 × 24 and 30 × 24 hours.

`presets` limits the picker's choices; `preset` defaults to the first.

### DashboardFilter

<AutoTypeTable path="../../packages/core/src/types/dashboard.ts" name="DashboardFilter" />

`filters` adds a select per entry beside the date picker, stored in the URL as
`f_<key>`. `options` takes `SelectOption[]`, an `enumOf()`, or a function of the
widget context; a plain string list is not accepted.

`filterOnClick: "<key>"` on `bars`, `tracker` or `table` sets that filter on click,
replacing the row's link. It is rejected on a record page or in a drawer.

```ts excerpt
const byPlatform: DashboardFilter = { key: "platform", label: "Marketplace", options: Platform };

const hourly = (c: WidgetContext) => c.sql<HourRow>`
  select hour as at, platform, runs_total as runs from scraper_hourly_stats
  where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}
    and (${c.filters.platform ?? null}::text is null or platform = ${c.filters.platform ?? null})`;

dashboard({
  path: "/parsing",
  label: "Parsing",
  filters: [byPlatform],
  sections: [{ columns: 12, widgets: [tracker({ query: hourly, at: "at", by: "platform", filterOnClick: "platform", span: 12 })] }],
});
```
