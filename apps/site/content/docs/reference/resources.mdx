`ref` is a Drizzle table or a Prisma model name. The row type comes from
[`InferRow<Ref>`](/docs/reference/registry#inferrow), which types `columns`,
`search`, `filters` and `defaultSort`.

```ts excerpt
import { resource } from "@flowpanel/kit";
import { orders } from "@/db/schema";

export const ordersResource = resource(orders, {
  label: "Order",
  plural: "Orders",
  icon: "shopping-cart",
  columns: ["id", "customerEmail", { field: "total", format: "money" }, "status"],
  search: ["customerEmail"],
  filters: ["status", { field: "createdAt", type: "daterange" }],
  defaultSort: { field: "createdAt", dir: "desc" },
  detail: { title: (row) => `Order · ${row.customerEmail}` },
});
```

## ResourceOptions

<AutoTypeTable path="../../packages/core/src/types/resource.ts" name="ResourceOptions" />

An empty list shows `empty.title`, `description`, `icon` and `action`. When search
or filters leave no rows it shows `empty.filtered` (or `empty.searched` during a
search; both fill `{query}`) and a button that clears them. On a phone the list
shows 10 rows as cards with the rest behind "N more".

### Detail headings and editing

Three callbacks fill the record page header. Each receives the row's readable
declared and `detail.expose` fields.

- `detail.title(row)` is the `h1` content: text or inline elements.
- `detail.subtitle(row)` is the line under it.
- `detail.badge(row)` is a pill beside the title: `{ label, tone }`.

```ts excerpt
detail: {
  title: (row) => row.email,
  subtitle: (row) => `Customer since ${row.createdAt}`,
  badge: (row) => (row.churned ? { label: "Churned", tone: "warn" } : null),
}
```

A nullish return leaves the slot empty; a nullish `title` falls back to the
resource label and the row identifier.

The Edit button sits beside the heading as a secondary button;
`update: { emphasis: "primary" }` fills it. It is hidden when `update.disabled` is
set or the update policy denies the request. A custom `PageHeader` slot uses the
exported `PageHeaderProps`.

Without `detail.tabs`, the page renders one key/value block. `detail.fields`
chooses and orders the fields in it; omitted, every readable declared field shows.

### Opening a row

`rowClick` decides what a click on a row, or Enter on it, does.

| Value | Effect |
| --- | --- |
| `"detail"` | Navigates to the row's own page under `paths.admin`. |
| `"drawer"` | Opens the [drawer](/docs/reference/drawer). Requires a `drawer` config; `defineAdmin` refuses the combination without one. |
| `false` | Rows render, but a click does nothing. |

Omitted, it follows the resource: `"detail"` when `detail` is configured and
`drawer` is not, `"drawer"` when only a drawer is, and `false` when neither is.
An explicit value always wins, so `rowClick: "detail"` on a resource that also
has a drawer sends the click to the page and leaves the drawer to its own
affordances.

A row without a key never opens. Opening is a router push, not a link, so
cmd-click does not open a new tab; add a column whose `render` returns an anchor
for that.

In a row that opens, an `editable` column starts editing from its pencil icon, a
double click or Enter; a single click opens the row.

### Reading a view

A resource's ref may be a database view. The list, the record page, counts, exports,
reference labels, related tabs and `ctx.read` read the view; create, update, delete,
restore, import and inline edits write to `writeTo`:

```ts excerpt
resource(adminUserRow, {
  name: "user",
  writeTo: user,
  update: { fields: [{ name: "internal", type: "switch" }] },
});
```

`writeTo` must be a table whose primary key the view selects. Every field a form or an
inline `editable` column writes must be a column of both: form fields are typed against the view's row, so select each
writable column in the view. `defineAdmin` checks both and names the missing column. The
write schema is inferred from `writeTo`, the generated edit form offers the table's
writable columns, and an update answers with the view's row, so computed columns are fresh
after a save.

Without `writeTo`, a resource over a view is read-only: its create, update and delete are
disabled, and declaring any of them (or `import`, or an `editable` column) throws at
`defineAdmin`.

### Icons

Resource, dashboard, page, queue, action and command icons take an `IconName`, a
Lucide icon name such as `users`, `settings`, `database` or `trash-2`. An unknown
name is a type error. To render one in your own component:

```tsx excerpt
import { FlowpanelIcon } from "@flowpanel/kit/react";

<FlowpanelIcon name="workflow" className="size-4" />;
```

### Saved views

`views` puts named filter, sort and search presets in a menu above the list.
Filters are keyed by the row's fields:

```ts excerpt
views: [
  { name: "New this week", filters: { createdAt: "last7d" } },
  { name: "Paying, falling asleep", filters: { plan: ["starter", "pro"], daysSinceSeen: { gte: 7 } } },
  { name: "No Telegram", filters: { telegramLinked: false } },
],
```

A `daterange` filter also takes a preset name (`today`, `yesterday`, `last7d`,
`last30d`, `MTD`, `QTD`, `YTD`), resolved on each request. A view may filter only
fields the list declares in `columns`, `filters` or `search`, with values that
match the filter type; `defineAdmin` rejects the rest. For "older than N days",
compute the number in a view and use a `numeric-range` filter.

## ColumnDef

An entry in `columns`. A bare string is shorthand for `{ field: "name" }`.

<AutoTypeTable path="../../packages/core/src/types/resource.ts" name="ColumnDef" />

A column without `field` must set `render` and `label`; it never sorts or
filters and is skipped by export. See
[Joined or computed values](/docs/customization/column-renderers#joined-or-computed-values).

`secondary` shows another field as a muted second line in the cell, such as the
email under a name. Sorting and search still use `field`.

```ts excerpt
columns: [{ field: "name", label: "User", secondary: "email" }],
```

### ColumnFormat

Declarative cell formatting.

```ts excerpt
type ColumnFormat =
  | "badge" | "money" | "number"
  | "date" | "relative" | "percent" | "duration" | "boolean" | "url"
  | { kind: "badge"; tones?: Record<string, Tone>; labels?: Record<string, string> }
  | { kind: "money"; currency?: string; scale?: number }
  | { kind: "number"; tones?: Threshold }
  | { kind: "date"; time?: boolean }
  | { kind: "percent"; digits?: number; heat?: boolean; tones?: Threshold }
  | { kind: "duration"; unit?: "ms" | "s"; tones?: Threshold }
  | { kind: "boolean"; labels?: { true?: string; false?: string } }
  | { kind: "url"; label?: string };
```

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.
The object form of `badge` maps each cell value to a tone:

```ts excerpt
{ field: "status", format: { kind: "badge", tones: { paid: "ok", failed: "err" } } }
```

`labels` gives each raw value its display text. Tones stay keyed by the raw
value, and a value with no label shows as is.

```ts excerpt
{
  field: "role",
  format: {
    kind: "badge",
    tones: { admin: "warn" },
    labels: { admin: "Administrator", freelancer: "Freelancer" },
  },
}
```

The other kinds:

- `date` shows the day in the admin's `timeZone`; `{ kind: "date", time: true }` adds the time. A `YYYY-MM-DD` value shows as itself; a zoneless `YYYY-MM-DD HH:mm:ss` is read as UTC.
- `relative` shows how long ago, such as `5 minutes ago`, in the admin's `locale`.
- `percent` reads a fraction: `0.423` is `42.3%`. `digits` caps the decimals, and `heat: true` shades the cell by its value, so a retention grid reads at a glance and still sorts by number.
- `duration` reads milliseconds, or seconds with `unit: "s"`, and prints the largest units that fit: `4.2 sec`, `2 hr 5 min`.
- `boolean` prints `✓` and `✕`, or `labels: { true: "Yes", false: "No" }`. SQLite's `1` and `0` read as true and false.
- `url` links `http(s)` and same-site values. `label` replaces the text, which defaults to the host and path; any other scheme stays text.
- `{ kind: "number" | "percent" | "duration", tones }` colours the text by a [`Threshold`](/docs/reference/widgets#thresholds), comparing the stored number, so a `duration` in seconds compares seconds. With `tones`, a percent cell is coloured instead of shaded. `cellTone(value, format)` returns the tone a cell gets.

```ts excerpt
columns: [
  { field: "week", label: "Cohort" },
  { field: "w1", label: "Week 1", format: { kind: "percent", heat: true } },
  { field: "p95Ms", label: "p95", format: "duration" },
  { field: "url", format: "url" },
  { field: "lastSeenAt", label: "Last seen", format: "relative" },
]
```

`relative` renders a `<time>` with the exact timestamp in its tooltip, and `url`
opens absolute URLs in a new tab without opening the row.

### Formatting values yourself

The formatters behind every cell, card and export. Each takes the admin's
resolved `formatting`.

<ApiSignature path="../../packages/core/src/format-column.ts" name="formatColumnValue" />

<ApiSignature path="../../packages/core/src/format-column.ts" name="formatNumber" />

<ApiSignature path="../../packages/core/src/format-column.ts" name="badgeProps" />

`formatColumnValue` renders a `ColumnFormat`; `formatNumber` renders a widget's
`NumericFormat` (`number`, `currency`, `percent`, `bytes`, `duration`). Both are in
`@flowpanel/core`, and `@flowpanel/react` re-exports `formatNumber`.
`badgeProps(format, value)` returns the props a badge cell passes to `StatusBadge`,
or `null` for an empty value.

`formatDurationValue`, `formatPercentValue`, `formatRelativeValue` and
`formatBooleanValue` print one kind each; `columnFormatKind`, `percentHeatLevel` and
`urlCellParts` describe what a format asks for; `toDateValue` and `toBooleanValue`
read raw values as cells do. `formatDurationCompact` prints only the largest unit,
such as `2.1h`, as chart axes do.

## Enums

`enumOf()` declares an enum's labels and tones once, for a column's `format`,
filter and field `options`, badges and timeline chips.

<ApiSignature path="../../packages/core/src/builders/enum-of.ts" name="enumOf" />

```ts excerpt
import { enumOf, resource } from "@flowpanel/kit";
import { planEnum, users } from "@/db/schema";

export const Plan = enumOf(planEnum.enumValues, {
  free: ["Free", "muted"],
  starter: ["Starter", "info"],
  pro: { label: "Pro", tone: "accent" },
});

resource(users, {
  columns: [{ field: "plan", format: Plan.format }],
  filters: [{ field: "plan", type: "select", options: Plan.options }],
  detail: { badge: (user) => Plan.badge(user.plan) },
});
```

With the database enum's values first, a missing or extra label is a compile
error; otherwise the entry keys are the values. An entry is a label, a
`[label, tone]` pair or `{ label, tone }`. `label()` prints an unknown value as
itself and a missing one as `—`; `badge()` returns `null` for a missing value;
`badge(value, { href })` makes the pill a link.

## FieldDef

An entry in `create.fields`, `update.fields`, a `DetailTab`, or an action's
`form`. The server enforces every rule.

<AutoTypeTable path="../../packages/core/src/types/resource.ts" name="FieldDef" />

### FieldType

```ts excerpt
type FieldType =
  | "text" | "textarea" | "number" | "email" | "password" | "url"
  | "date" | "datetime" | "time"
  | "boolean" | "switch" | "checkbox"
  | "select" | "multiselect" | "radio"
  | "json" | "markdown" | "tags" | "reference" | "hidden" | "color";
```

Without `type`, a field is `"text"`, or `"reference"` when it sets `reference`.
Only a fully generated form (no `create.fields` or `update.fields`) reads the
column type, and only for numbers, booleans, dates and JSON.

## FilterDef

An entry in `filters`. A bare string is a `text` filter; set `type` for anything
else. A `select` or `multiselect` filter without `options` on a column formatted
with badge `labels`, such as an `enumOf` format, lists those labels.

<AutoTypeTable path="../../packages/core/src/types/resource.ts" name="FilterDef" />

### Default and hidden filters

`defaultValue` applies while the URL has no value for the filter, to the rows,
totals and export alike. Clearing it writes an empty `f_<field>=` to the URL. A
saved view or link turns it off with `null`. `hidden: true` applies the filter
without a control.

```ts excerpt
filters: [
  { field: "isTest", label: "Test accounts", type: "boolean", defaultValue: false },
],
views: [{ name: "Everyone", filters: { isTest: null } }],
```

A filter compares one column. To filter by an expression or through a relation,
read the resource from a view that computes the column and set
[`writeTo`](#reading-a-view).

### FilterType

```ts excerpt
type FilterType =
  | "text" | "select" | "multiselect"
  | "daterange" | "numeric-range" | "boolean" | "tag";
```

`daterange` and `numeric-range` reach your adapter as a `FilterRangeValue`;
`multiselect` as a `FilterInValue`. Both are documented under
[Contexts](/docs/reference/contexts#filter-values).

## Record page

`detail` configures `<paths.admin>/<resource>/<id>`. Type a card that lives in its own file
with `DetailOptions<Row>`:

```ts excerpt
import { type DetailOptions, kv, metric, related, type RowOf } from "@flowpanel/kit";

export const card = {
  title: (u) => u.name ?? u.email,
  subtitle: (u, { format }) => `with us since ${format.date(u.createdAt)}`,
  badge: (u) => [Lifecycle.badge(u.lifecycle), Plan.badge(u.plan)],
  dateRange: { preset: "last30d", presets: ["last7d", "last30d", "QTD"] },
  stats: [metric("Visits", { count: "user_visit", range: "startedAt" }, { compare: true })],
  aside: [kv({ label: "Profile", columns: 1, items: [{ label: "Email", field: "email" }] })],
  tabs: [related("response")],
} satisfies DetailOptions<RowOf<"user">>;
```

- `title`, `subtitle` and `badge` receive the row and a `DetailHeaderContext` — the
  admin's `format`, `labels` and `link`. `badge` returns one pill or a list, in order;
  `null` entries are dropped, and a pill with `href` is a link.
- `stats` renders as a hairline strip under the header, on every tab.
- `aside` is a column beside the tabs from the `lg` breakpoint and below them on a phone,
  on every tab.
- `dateRange` adds a date picker to the header. Its range, with `previous`, reaches
  `stats`, `aside` and every widgets tab. Related rows list every row, a
  [timeline](/docs/reference/widgets#timeline) pages through the whole history and a
  heatmap shows its last `days` days. Without `dateRange` the page has no picker and
  widgets see the record's whole history.

The header, strip, aside and open tab share one widget context, so a repeated
`ctx.count`, `ctx.read` or `ctx.query` runs once per page.

## DetailTab

A tab on the record page. The open tab is the `?tab=<key>` query parameter, and
only that tab runs on the server.

A tab declares exactly one kind of content, and they resolve in this order:
`render`, `widgets`, `resource`, then fields.

### Fields and sections

`fields` renders key/value pairs; `"*"` shows every readable field. An entry is a
field name or a `FieldDef`. Column `format` and `render` apply here too.

A `FieldDef` with `render(row, ctx)` shows its result instead of the value. It
runs on the server, only when the reader may read `name`, concurrently with the
tab's other renders. A render that throws is logged and the field shows its
formatted value; see [server-rendered cells](/docs/reference/drawer#server-rendered-cells)
for the drawer:

```ts excerpt
{
  name: "categoryId",
  label: "Category",
  render: async (job, ctx) => {
    const category = await findCategory(ctx, job.categoryId);
    return `${category.title} (${category.openJobs})`;
  },
}
```

`sections` groups those fields into titled blocks and wins over `fields` on the
same tab:

```ts excerpt
{
  key: "overview",
  label: "Overview",
  sections: [
    { label: "Identity", fields: ["email", "name"] },
    { label: "Billing", fields: [{ name: "mrr", label: "MRR" }, "plan"] },
  ],
}
```

Fields named here are loaded when the tab is open. A field the reader may not
read is left out.

### Widgets

`widgets` puts dashboard widgets in the tab; see
[widget tabs](/docs/build/detail-cards#widget-tabs). `columns` defaults to 2, or 12
once a widget sets `span`. `ctx.row` is the record. A failing widget shows its own
error card.

### Related rows

A tab with `resource` shows that resource's list columns, paged under the URL key
`relatedPage.<key>` and sorted under `relatedSort.<key>`. `hide` drops columns and
their values; the parent foreign key is the usual one. `sort` sets the default
order. An "Open list" link to the filtered list appears when every filter value is
a scalar on a field the target declares.

`filter` is a constraint: an undefined parent value yields no rows and no query.
A row opens by the target's [`rowClick`](#opening-a-row); a drawer opens over the
record page under `?drawer=<resource>:<id>`.

`pageSize` defaults to 25. `count: true` shows the row count in the label.
`widgets` on the same tab render above the rows.

`by` names the target's field that points at this record: it becomes `filter`, reading the
record's `rowKey`, and `hide`, unless you give those yourself.

### Related tabs in one line

<ApiSignature path="../../packages/core/src/builders/related.ts" name="related" />

`related(resource, options)` builds a counted related tab. Without `by`, `defineAdmin` finds
the one column of the target whose `reference.resource` is this resource and uses it; none
or several throw and ask for `by`. `by`, `hide` and `sort.field` are fields of the target's
row, so a typo is a compile error once resources are typed, and `defineAdmin` names the
closest column otherwise. The label defaults to the target's `plural`.

```ts excerpt
detail: {
  tabs: [
    related("response", { label: "Responses", widgets: [responseFunnel] }),
    related("payment", { pageSize: 10, sort: { field: "createdAt", dir: "desc" } }),
  ],
}
```

A tab with neither `by` nor `filter` reads every row of its target.
