Throw one of these from an action, adapter or custom route and FlowPanel answers
with its status and `safeMessage`. Any other error becomes a generic `500` with no
detail in the response beyond its `requestId`.
FlowPanel passes the error to `hooks.onError`, so send it to your logger there.
Without a hook it logs one `console.error` with the operation and the same request
id. In development the log has the whole error; in production only the first line of
the error and its cause, so query parameters and the values they carry stay out of it.

## FlowpanelError

The base class. Every other error extends it.

<ApiSignature path="../../packages/core/src/types/error.ts" name="FlowpanelError" />

| Property | Meaning |
| --- | --- |
| `code` | Stable machine-readable tag, e.g. `"validation_failed"`. |
| `safeMessage` | Shown to the operator verbatim. Keep internals out of it. |
| `status` | HTTP status from `FLOWPANEL_ERROR_STATUS[code]`. |

Construct it directly for a case the subclasses do not cover:

```ts
throw new FlowpanelError("conflict", "This order is already being processed");
```

## The subclasses

| Class | `code` | Status | Default message | Raised by FlowPanel? |
| --- | --- | --- | --- | --- |
| `FlowpanelValidationError` | `validation_failed` | 422 | Validation failed | yes |
| `FlowpanelAuthError` | `unauthenticated` | 401 | Authentication required | no, yours to throw |
| `FlowpanelAccessError` | `forbidden` | 403 | Forbidden | yes |
| `FlowpanelFieldAccessError` | `field_forbidden` | 403 | `Field "x" cannot be changed.` | yes |
| `FlowpanelOperationDisabledError` | `operation_disabled` | 403 | This operation is disabled. | yes |
| `FlowpanelUnknownFieldError` | `unknown_field` | 400 | `Unknown field: "x".` | yes |
| `FlowpanelNotFoundError` | `not_found` | 404 | Not found | yes |
| `FlowpanelConflictError` | `conflict` | 409 | Conflict | yes, for a database conflict |
| `FlowpanelRateLimitError` | `rate_limited` | 429 | Rate limit exceeded | yes |

Each takes an optional message, except the two field errors, which take the field
name, and `FlowpanelValidationError`, which takes its field errors first.

### FlowpanelValidationError

<ApiSignature path="../../packages/core/src/types/error.ts" name="FlowpanelValidationError" />

It carries `fieldErrors`, keyed by field name, as the first constructor argument:

```ts fragment=signature
constructor(fieldErrors: Record<string, string>, message = "Validation failed");
```

Forms show each entry beside its input.

```ts
import { FlowpanelValidationError } from "@flowpanel/kit";

throw new FlowpanelValidationError({
  email: "That address is already registered",
});

// with a banner message as well:
throw new FlowpanelValidationError({ email: "Already registered" }, "Could not save");
```

## Database constraint violations

A create, edit, inline edit or delete that breaks a database constraint does not
become a `500`. FlowPanel reads the Postgres, MySQL, SQLite or Prisma error, through
any wrapping error, and answers with a message from `labels.form`:

| Violation | Column known | Answer |
| --- | --- | --- |
| Unique | yes | 422, `taken` on the field: "Email is already taken" |
| Unique | no, e.g. a composite key | 409, `conflict` |
| Foreign key on a write | yes | 422, `missingReference` on the field |
| Foreign key on a write | no | 409, `missingLink` |
| Foreign key on a delete | either | 409, `inUse` |
| NOT NULL | yes | 422, `required` on the field |

The column is matched to the resource's field by name, ignoring case and `_`, so
`user_id` reaches `userId`. A violation without a column it can match, and any
other database error, stays a `500` and is reported as above.

## FlowpanelConfigError

`defineAdmin` throws a `FlowpanelConfigError` while the config loads, so the app
fails to start. It is not a `FlowpanelError` and is never sent to the client:
one thrown during a request, such as `devAuth()` in production, becomes a `500`.
Every one reads the same way:

```text
[flowpanel] <where in the config>: <what is wrong>. <how to fix>.
```

<ApiSignature path="../../packages/core/src/types/config-error.ts" name="FlowpanelConfigError" />

`where` holds the config path on its own, such as `resource "orders" drawer.tabs[0]`.
The errors cover duplicate or reserved names, duplicate action keys, unknown
columns, an unintrospectable ref without `columns`, unresolved references,
`rowClick: "drawer"` without a drawer, removed options, unsafe route paths, a
production admin without real auth, and `devAuth()` in production. See
[Troubleshooting](/docs/troubleshooting#defineadmin-throws-when-the-app-boots).

### Did you mean

An unknown name close to a registered one gets a suggestion: a match ignoring case
and `_`/`-`, else the closest within edit distance two.

```text
[flowpanel] resource "users" columns[0]: it points at column "emial", which the
adapter does not report. Did you mean "email"? Known columns: "id", "email".
```

It covers column, filter, sort, field, tab, reference, view and link names. A link,
view or count `where` value must match its filter type: an array needs a
`multiselect` filter, `{ gte, lte }` a range filter; a bare `Date` is rejected.
Names computed at run time (function links, `ctx.count`, `ctx.read`, `ctx.rowOf`)
are checked when they run.

### Warnings that do not stop the boot

`defineAdmin` collects non-fatal problems in `warnings`, prints each once in
development, and `flowpanel doctor` lists them. For example, a create form that
cannot succeed:

```text
resource users: create is enabled but required column `email` has no field;
creation will always fail
```

It fires for a required column with no default that neither `create.fields` nor
`create.defaultValues` fills.

## On the page render path

`FlowpanelAuthError` and `FlowpanelAccessError` thrown during a page render:

- No session and `auth.signInUrl` is set → redirect there.
- Signed in, but `auth.access` refuses the whole admin, and `auth.forbiddenUrl` is set → redirect there.
- Signed in and admitted, but one dashboard, page, queue, the Audit log or a resource route refuses the role → the "You don't have access to …" screen inside the admin, with a link to the next page the role can open. `forbiddenUrl` is not used here.
- Otherwise → an inline "Sign in required" or "You don't have access to this admin" screen.

Other errors reach your Next.js error boundary, except failed adapter reads.

### A query that failed

When `list` or `get` throws, FlowPanel shows a card in place of the data with the
request id the error was logged under:

```text
users: list failed
Check the column list and the database schema. Details are in the server log.
Request 5f3c…
```

Outside production the card also shows the message in a closed disclosure. A
`FlowpanelError` or a `redirect()` passes through.

### Widget failures

A widget whose query or render throws becomes one failed card, named by title,
kind and place:

```text
«Pipeline» (custom, /system section 2 widget 1): relation "pipeline_view" does not exist
«Broken» (metric, user tab "summary" widget 1): boom
```

Outside production the card shows it in a closed disclosure; in production only
the server log and the Sentry tag `widget.id` carry it.

## Returning versus throwing

Inside an action's `run` you have both options:

```ts as="RowAction<RowOf<'orders'>>"
run: async (row, input, ctx) => {
  if (row.status === "refunded") {
    return { ok: false, error: "Already refunded" };   // 200 with a failure body
  }
  throw new FlowpanelConflictError("Order is locked"); // 409
}
```

Return `{ ok: false }` for an outcome the operator can fix; throw when the request
itself is invalid.

## Errors the routes produce themselves

The generated UI routes (actions, forms, drawers, inline edits, import and restore) answer every failure as `{ ok: false, error, code, requestId?, fieldErrors? }`: `error` is a string to show, `code` a `FlowpanelErrorCode`, and `requestId` is set once the guards have run. Some errors come from the routes themselves:

| Status | `error` | When |
| --- | --- | --- |
| 400 | `invalid JSON body` | A JSON body that does not parse. |
| 400 | `JSON body must be an object` | A JSON array or scalar. |
| 400 | `invalid form data` | A form body that does not parse. |
| 413 | `request body is too large` | A body over the size limit. |
| 403 | `Cross-origin write requests are not allowed.` | The default browser origin guard blocks a mutation. |
| 403 | `This admin is read-only.` | `readOnly: true` blocks a write. |
| 422 | `too many ids (max N)` | A bulk action gets more ids than its `max`. |
| 404 | `resource not found`, `action not found`, `dashboard not found` | The route names something the config does not register, such as an action removed since the page loaded. |
| 422 | `validation failed` | An action `form` fails validation; `fieldErrors` holds one message per field. See [Actions → Validation](/docs/reference/actions#validation). |

The JSON CRUD API that the [typed client](/docs/reference/client) calls answers with
a `FlowpanelResultError`, `{ ok: false, error: { code, message } }`, instead:

| Status | `code` | When |
| --- | --- | --- |
| 400 | `bad_request` | A body that does not parse or is not a JSON object. |
| 405 | `method_not_allowed` | A method the route does not serve; `Allow` lists the ones it does. |
| 413 | `payload_too_large` | A JSON body over 1 MiB. |
| 415 | `unsupported_media_type` | A write without `Content-Type: application/json`. |

### 404: unknown resource, action or dashboard

The UI routes answer with the same short body in every environment. The message
names the kind: `resource`, `action` or `dashboard`. A route looks the name up only
after it has identified the caller and applied `readOnly`, so a signed-out or
refused caller gets the `403` it would get for a name that exists, never this `404`.

```json
{ "ok": false, "error": { "code": "not_found", "message": "action not found" } }
```

Outside production the server console also prints what is registered:

```text
[flowpanel] action not found: "refnud". Registered actions: "refund", "cancel".
```

The JSON CRUD API answers `{ "code": "not_found", "message": "not found" }` for an
unknown route or resource.
