## Scope

A scope is resolved once per request and applied by the adapter to every query.
Guide: [Multi-tenant scope](/docs/guides/multi-tenant-scope).

```ts
type Scope = Record<string, unknown> | null;
// FlowpanelTypes["session"] when you register it, else Record<string, unknown>
type Session = Record<string, unknown>;
```

`AdminDefinition.scope` receives:

<AutoTypeTable path="../../packages/core/src/types/session.ts" name="ScopeContext" />

```ts as="AdminDefinition"
scope: async ({ session }) => ({ orgId: session?.user?.orgId }),
```

The returned object reaches resource predicates as their first argument, and
policies, mutations and actions as `ctx.scope`. The adapter receives the
resource's predicate bound to it as `ctx.boundScope`. Widgets get no `ctx.scope`:
`ctx.count` and `ctx.read` apply the scope for you, and a `ctx.sql` or `ctx.db`
query must read the tenant from `ctx.session`.

Return `allTenants` from `@flowpanel/kit` for a user who works across tenants: the
resource predicates are skipped for that request, and `isAllTenants(scope)` tells
it apart. A resource's `scopeOf(row)` names the tenant a row belongs to, in the
shape `scope` returns, so the audit log files that user's changes under it.

### The opt-out is mandatory

With a global `scope`, every resource declares its own `scope` or
`scope: "bypass"`. One that does neither stops `defineAdmin` at boot with
`resource "<name>" scope: the admin has a global scope, so every resource needs its own`.

FlowPanel also runs this check per request, in case a resource loses its scope after boot; call it only in your own adapter or route.

## Publisher

The realtime transport, built from `AdminDefinition.realtime` by
`createRealtimeTransport`. Implement it for another bus. Guide:
[Realtime](/docs/guides/realtime). A worker uses `createPublisher` from
`@flowpanel/kit/publish` instead.

<AutoTypeTable path="../../packages/core/src/runtime/publish.ts" name="Publisher" />

<ApiSignature path="../../packages/core/src/runtime/publish.ts" name="createRealtimeTransport" />

```ts of="@flowpanel/kit"
type PublisherOptions =
  | { driver: "memory" }
  | { driver: "redis"; url?: string; client?: RedisLike; keyPrefix?: string };
```

`AdminDefinition.realtime` also takes `channels`, the channels of your own the
stream may serve ([Realtime](/docs/guides/realtime#declare-your-own-channels)):

<AutoTypeTable path="../../packages/core/src/types/realtime.ts" name="RealtimeChannel" />

The memory driver reaches only the publishing process. The Redis driver loads the
optional `ioredis` peer on first use and needs `url` or `client`; with `client`,
FlowPanel publishes on it and calls `duplicate()` only to subscribe. Nothing
connects until the first publish or subscribe. Connection errors are logged once
per kind and never rethrown.

`keyPrefix` defaults to `"flowpanel"`, so `resource.orders` travels as
`flowpanel:resource.orders`. Use one channel per payload shape. Payloads are
JSON in every driver, so a `Date` arrives as an ISO string, and a payload that
cannot be encoded is rejected.

`close()` releases connections the publisher opened; a `client` you passed stays
open. After `close()`, `publish` throws.

### Publishing from a worker

A worker, cron job or script imports only `@flowpanel/kit/publish` and opens one
connection.

<ApiSignature path="../../packages/core/src/runtime/worker-publisher.ts" name="createPublisher" />

<AutoTypeTable path="../../packages/core/src/runtime/redis-publisher.ts" name="PublisherClient" />

<AutoTypeTable path="../../packages/core/src/runtime/redis-publisher.ts" name="RedisLike" />

```ts
import { createPublisher } from "@flowpanel/kit/publish";

const events = createPublisher({
  redis: process.env.REDIS_URL!,
  onError: (err) => console.error("realtime publish failed", err),
});

export async function orderChanged(id: number): Promise<void> {
  await events.resource("orders", { id });
}
```

It also takes the admin's `{ driver: "redis", url, keyPrefix }` options. A
transport error resolves the call and reaches `onError`.

### The memory driver in a Redis deployment

The publisher is bound per process from `config.realtime` and rebinds when the
options change. It warns once per process, on the first publish or stream, when
the driver is `memory` while `REDIS_URL` or `FLOWPANEL_REDIS_URL` is set:

```text
[flowpanel] realtime driver is memory while REDIS_URL is set — other instances
and workers will not receive events; set realtime: { driver: 'redis', url:
process.env.REDIS_URL } in defineAdmin
```

## RateLimiter

<AutoTypeTable path="../../packages/core/src/runtime/rate-limit.ts" name="RateLimiter" />

```ts of="@flowpanel/kit"
function createRateLimiter(opts: RateLimitOptions): RateLimiter;
```

`check` returns `false` over the limit, which becomes a `429`. With `per: "user"`
the key is `AuthConfig.userId`, else the session's `id` or `user.id`, else the IP.
The memory driver counts per process. The Redis driver's key prefix defaults to
`"fp:rl:"`.
