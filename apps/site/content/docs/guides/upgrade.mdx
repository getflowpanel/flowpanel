FlowPanel workspace packages are released together. Most applications should depend on the umbrella `@flowpanel/kit` and local `@flowpanel/cli` at the same version rather than pinning lower-level packages independently.

## Inspect the current install

```bash
pnpm list "@flowpanel/*"
pnpm flowpanel doctor
```

Before changing versions, record ejected files and any direct lower-level FlowPanel dependencies. Read the [changelog](/changelog) for every version you will cross.

## Update aligned packages

```bash
pnpm up "@flowpanel/*" --latest
pnpm install
```

Keep direct FlowPanel packages on the same released version. Multiple copies of `@flowpanel/core` can split request context and module augmentation; `flowpanel doctor` checks for that condition.

## Review database work

```bash
pnpm flowpanel migrate --dry-run
```

Review pending SQL for the target dialect and deployment strategy before applying it. Back up production data according to the application's normal migration policy, then run `pnpm flowpanel migrate` in the controlled release step.

## Validate the application

Run the application's typecheck and production build. Start the admin once so config compilation can catch duplicate/reserved names, stale columns, and unresolved references. Exercise auth, one scoped read/write, forms, actions, realtime, and queues used by the deployment.

## Review ejected files

Ejected files contain a version stamp and are application-owned. The upgrade does not rewrite them. Compare their public imports and behavior with the changelog and current reference; test them separately from generated routes.

If a newer config, renderer, page, or slot now covers the customization, consider returning that surface to generated behavior. Re-enabling config also requires removing the explicit Next.js route.

## Upgrading from 0.3.0 to 0.3.1

0.3.1 adds options, widgets and checks, and changes some outputs. No option is removed; three 0.3.0 names are deprecated and keep working, listed below. A config that compiles on 0.3.0 compiles on 0.3.1 unless it meets one of the type changes below: both example apps upgraded with no config change, and only a unit test that calls `detail.title` directly had to pass the new header context. The [founder admin tutorial](/docs/introduction/founder-admin) shows the new pieces together.

### What an admin shows differently

- **Dates follow `formatting.timeZone`.** With a configured zone, `today`, `yesterday`, `MTD`, `QTD` and `YTD` start at midnight in that zone instead of at UTC midnight, and a list's `daterange` filter reads each picked day in that zone. An admin without `timeZone` sees no change.
- **A configured `timeZone` holds after hydration.** Every `LocalTime` keeps that zone instead of switching to the reader's own, so a page shows one clock. Give a `LocalTime` its own `fallbackTimeZone` to keep the old switch for it.
- **Durations speak the admin's locale.** `format: "duration"` on a metric, stat or bar and in a chart tooltip prints `4.2 sec` or `2 hr 5 min` (`4,2 с`, `2 ч 5 мин` in Russian) instead of `4s` or `2.1h`. A chart's value axis prints the compact `2.1h` / `2,1 ч`.
- **Metric changes read honestly.** A change inside ±1 % shows no arrow and no colour, and the percentage prints in the admin's locale. With `previous` set, a count under 20 shows its absolute change (`+3`), a `percent` metric its change in points (`+3 pp`), and the compared value shows beside it.
- **A capped widget no longer shows `0` for a past range.** `maxRange` counts its N days back from now as well as from the range's end. A range that ended before that runs no query and shows `—` with "No data: kept for N days", and a cut range says where it was cut under the card title.
- **Cards carry one caption line** under their title when a range is cut or a widget sets `freshness` or `coverage`.
- **A count metric on a record page counts only the viewed record's rows.** `metric(label, { count })` in `detail.stats`, `detail.aside` or a detail tab adds the filter to the record to its count and its default link.
- **A related tab that sets both `widgets` and `resource` shows both**, widgets above the rows.
- **Related detail-tab rows open.** A row opens the way it does on the target's own list: its detail page, or its drawer over the record page on the same tab. The drawer keeps its tab in `?drawerTab=` and leaves `?tab=` to the page, so a saved 0.3.0 drawer link that named its tab in `?tab=` opens on the drawer's first tab. Set `rowClick: false` on the target resource to keep the rows inert (its own list's rows too).
- **`span` implies 12 columns.** A section or widgets tab without `columns` lays out on 12 columns once a widget sets `span`; before, `span` did nothing in its one- or two-column grid.
- **Drawer cells use the admin's locale and zone.** A drawer field with a column format, and a drawer widget table's formatted column, print as the table does instead of in en-US and UTC.
- **`filterOnClick` on `bars`, `tracker` or `table` replaces that row's own link** with a link to the filtered dashboard. The folded "Other" bar and a bar without `key` keep their `href`.
- **A Russian locale switches the chrome to Russian.** With `formatting.locale` set to `"ru"` or `"ru-*"`, the built-in labels, the sign-in and access-denied screens included, come from `RU_LABELS` and your `labels` merge over them. Pass `labels: DEFAULT_LABELS` to keep English.
- **Russian counts inflect.** The row count reads «1 333 записи» instead of «Записей: 1 333», and the bulk bar «Выбрано 3 элемента». Setting `table.results` or `bulkBar.selected` yourself keeps your template.
- **Funnels mark a drop only past `alertDrop`.** Set `funnel({ alertDrop: 0.5 })` and the step with the largest drop-off past half turns `warn`; without it no step is toned, and drops and growth print in muted text.
- **Unreadable detail fields are left out** instead of showing as an empty row.
- **Each page can carry its own title.** Export `generateMetadata = flowpanelMetadata(config)` (or `runtime.metadata` from `createFlowpanel`) beside the page and the tab reads "Orders", "Order" or the dashboard's label inside your layout's title template. The page also renders a `theme-color` meta per scheme from `--fp-bg-2`, so a phone's browser chrome matches the page.
- **Visual only, with no switch.** A `stat` title uses the `metric` card's sentence case; hints, `kv` values, `list` text and bar and funnel labels wrap to two lines; widget `tone`s colour their values, bars and list rows; card percentages use the admin's locale; the drawer renders a `statGroup` with the dashboard's card.

### A calmer default look

0.3.1 ships a new default palette and quieter chrome. An admin that set its own tokens keeps them; one that relied on the defaults looks different.

- **Graphite greys, an ink accent and one data colour.** Surfaces, text and borders are neutral greys, the accent is near-black (near-white in dark mode), and state tones are desaturated. Contrast is at least 4.5:1 for every text token on every surface in both schemes, and 3:1 for borders, chart colours and the focus ring. [Keep the 0.3.0 look](#keep-the-030-look) below restores every changed token.
- **Dark mode surfaces sit above the page.** The page (`--fp-bg-2`) is now the darkest plane, cards and nav (`--fp-bg-1`) one step up and fills (`--fp-bg-3`) above them. A host that set only some dark greys in `cssVarsDark` checks that its page is still darker than its cards.
- **Data has its own colour.** Bars, funnels, sparklines, heat cells, a single-series chart and a `default`-toned dot fill with `--fp-data`, which follows `--fp-chart-1`, instead of the accent. A host that sets `theme.accent` or `accentDark` and no `--fp-data` keeps data in that accent, as in 0.3.0; with only `accent`, dark mode draws data in the default data colour, because its accent is FlowPanel's. Set `--fp-data` in `cssVars` to part data from your accent.
- **Smaller radii, no resting shadow.** Radii are 4, 6, 8 and 12 px and `--fp-shadow-xs` is none, so static cards and tables carry a hairline only. Set `--fp-radius*` and `--fp-shadow-xs` in `cssVars` to keep the old ones.
- **Labels are sentence case.** Table headers, `kv` and `statGroup` labels and nav group labels are 12 px regular text, no longer uppercase. The active nav item and tab are neutral instead of accent-coloured.
- **Built-in links lose their arrow and their colour.** "Open full page", "Open list", "Older" and "Newest" carry no `→`/`←`, and card links such as "See all" are secondary text. Put an arrow back through `labels` if you want one.
- **Statuses stay quiet when healthy.** A `badge` column without `tones` colours `failed`, `error` and `rejected` as `err`, `degraded` as `warn` and `pending`, `waiting`, `processing` and `running` as `info`; `active`, `success`, `completed` and any other value are neutral, and `disabled` and `canceled` are muted instead of `err`. Declare `tones: { active: "ok" }` to colour one. Badges have 4 px corners and 12 px text.
- **Metric changes are plain text.** A delta prints `+12% vs previous period` with no pill or arrow, coloured by `goodWhen` only from a 5 % change; smaller changes stay muted. Bar rows read the same way.
- **The banner list leads with a sentence.** `list({ variant: "banner" })` sits on a normal card with a 3 px rule in the worst row's tone; the first row reads as an 18 px line and the rest as dot lines in secondary text, and the all-clear line has no check mark.
- **List lines keep the body colour.** A toned `list` row shows its tone in the dot only.
- **Empty and failed cards take one line.** A widget with no rows says so in one 14 px line where its content would start, a chart included, and a failed widget names the failure in the error colour on a neutral card.
- **A table or list keeps its own height.** In a dashboard row it no longer stretches to its tallest neighbour; set the section's `align: "stretch"` to restore that.
- **Dashboard actions are secondary.** Every dashboard action and every drawer action is an outline button, a destructive one in the error colour; the record page's Edit button too. Give the one action a screen is for `emphasis: "primary"`, or `update: { emphasis: "primary" }` for Edit; drawer actions have no `emphasis` and stay secondary.
- **Compact rows are 40 px with body text**, and a list with no matching rows says so with a button that clears its search and filters; Export hides when there is nothing to export. A phone shows the first 10 cards of a page and folds the rest behind one button.
- **The drawer's subtitle is the resource's label**, not `Resource · id`; set `drawer.subtitle(row)` for your own. Its title is a skeleton while the row loads, and the panel itself takes focus on open.
- **A 404 marks no nav item.** The admin root, the entry every other entry sits under, marks only its own page; any other entry still marks the pages below it.
- **Chart ticks drop a repeated year**, legends write series names in secondary text beside a coloured swatch, and area charts fill flat instead of with a gradient.

### What `defineAdmin` and the runtime now reject

- **Names are checked at boot.** `defineAdmin` throws, with the closest name, on a static link, count metric, saved view, related tab, timeline or heatmap source, `realtime` resource or dashboard filter that names a missing resource, dashboard, view, tab, column or filter. It also rejects a filter value its list would read as other rows: an array without a `multiselect` filter, bounds without a range filter, a single value on a range filter other than a `daterange` preset name, or a bare `Date`.
- **Filters that cannot be written throw.** A link or view filter value with no URL form throws instead of writing `[object Object]`.
- **`ctx.count` with `null` or `""` counts `0`** and warns in development, as `undefined` already did; the Drizzle adapter used to count every row. `ctx.read` throws on those values.
- **Widgets a drawer cannot show are rejected there.** `timeline`, `heatmap`, `checklist` and `tracker` in a drawer tab, and a dashboard filter on a record page or in a drawer, are errors that point at a detail tab.
- **Two timelines on one page need their own `id`.** An un-id'd timeline outside a detail tab takes `timeline`, `timeline-2` and on, and two that set the same `id` fail at `defineAdmin`.
- **The error-boundary `widgetId` changes.** It and the Sentry `widget.id` tag name the widget by label, kind and place instead of `s0.w1` or `activity.w0`.

### Deprecated names that still work

- **`createPublisher` from `@flowpanel/kit`** is now `createRealtimeTransport`, the transport behind an admin's `realtime` option. A worker imports `createPublisher` from `@flowpanel/kit/publish`, which never rejects on a Redis error.
- **`ctx.href(resource, id, { filter, tab })`** still builds a link and no longer triggers the mount-path warning. Return a named target instead — `{ resource: "orders", id }` — or call `ctx.link(target)` where a string is needed.
- **`goodWhen` on a returned `MetricDelta`** still wins. Set `goodWhen` on the metric itself, where it also reads `tones`.

### Types

- **`theme.cssVars` and `cssVarsDark` are `ThemeTokens`.** The known `--fp-*` names complete in an editor and any other key still passes, so existing configs compile.
- **Link fields are wider.** `href`, `drilldown`, `seeAll`, `rowHref` and a row's `href` accept a `LinkTarget`. Code that reads one back as a `string` narrows it with `typeof`.
- **Filters are keyed by rows.** Saved-view filters are keyed by the resource's own row on every Drizzle resource, and link filters by the target's row once resources are typed; a key that is not a field of that row is a compile error.
- **Registering `schema` or `session` narrows types.** `ResourceName`, rows and `Session` then come from your schema and auth, which may surface errors the loose types hid. A `where` or filter value typed `unknown`, such as `ctx.row?.id`, no longer compiles; use `ctx.id` or `ctx.rowOf(…)`.
- **A `ctx.read` row carries only the list's columns, `expose` and `fields`.** Name every other field a card reads in `fields`.
- **`realtime` is typed `RealtimeOption`.** Code that reads `widget.options.realtime` gets `string | { resource } | (string | { resource })[]`; a `{ resource }` target travels on `resource.<name>`.
- **`WidgetConfig` has four new kinds**: `timeline`, `heatmap`, `checklist` and `tracker`. A host that switches exhaustively on `kind` adds cases.
- **`ColumnFormat` gains `{ kind: "number", tones? }`**, and the `percent` and `duration` objects take `tones`. A switch on `format.kind` handles `"number"` in its object branch.
- **`StatusTone` is every `Tone`.** An exhaustive `Record<StatusTone, …>` adds `default`, `accent` and `info`.
- **Optional where it was required.** A chart's `y` and `KvItem.value` may be `undefined`; code that reads them back handles it. `ListCardRow.count` and `.since` are preformatted strings.
- **Header callbacks take a second argument.** `detail.title`, `subtitle` and `badge` receive `(row, { format, labels, link })`, and `badge` may return a list. Code that calls them directly, such as a unit test, passes `headerContext()` from `@flowpanel/test/widgets`.
- **Moved types keep their exports.** `DetailTab` and `DetailTabContext` live in `types/detail.ts`, the chart options in `types/widget-charts.ts` and the list types in `types/widget-list.ts`, still exported from the same entries.

### Code that builds FlowPanel objects by hand

- **A hand-built `WidgetContext` needs the new members.** Add `format: bindFormat(resolveFormatting())`, a `link` function, `read`, `rowOf`, `filters: {}`, a `query` that accepts `(key, fn)`, `(fn, ...args)` and `(fn)`, and `previous` and `timeZone` on `dateRange`. A hand-built `DetailTabContext` adds `read`, `rowOf`, `format`, `link` and the same `dateRange` members. Contexts FlowPanel builds carry them already, and `widgetContext` from `@flowpanel/test/widgets` builds one for tests.
- **`ctx.query(fn)` hands `fn` the context.** With no further arguments it calls `fn(ctx)` when `fn` declares a parameter. A function whose first parameter is optional without a default (`days?: number`) now receives the context: give it a default or pass the argument.
- **A hand-built `ResolvedLabels` adds** `timeline`, `heatmap`, `checklist`, `access`, `detail.tabCount`, the new `widget` keys, `widget.tones` (`err`, `warn`, `ok` and `info`, the words a screen reader says for a status glyph or dot) and `drawer.loading`, `noRows`, `noWidgets` and `chartElsewhere`. Spreading `DEFAULT_LABELS` or `RU_LABELS` first fills them in.
- **`PublisherClient` has a `resource(name, change?)` member.** A test double typed `: PublisherClient` adds it.
- **A custom adapter may report `ResourceIntrospection.kind: "view"`.** A resource over a view without `writeTo` is read-only.
- **`fillDays` now runs through `series`.** `fillDays(rows, ctx.dateRange, …)` buckets in the admin's zone (a plain `{ from, to }` still buckets in UTC), a zoneless timestamp string is read as UTC, `Date` values in `valueField` sum as 0, and a range that starts at the epoch begins at the first row's day.

### Workers, tests, styles and the CLI

- **A worker `publish` resolves on a Redis error.** Pass `onError` to `createPublisher` to observe it; otherwise it logs one line per error kind.
- **`smokeAdmin` opens every detail tab.** Pass `tabs: false` for the old walk.
- **`@flowpanel/test/widgets` needs `@flowpanel/kit`**, a new optional peer of `@flowpanel/test`. Under Vitest it also needs `test.server.deps.inline: [/@flowpanel\//]`, or it fails with `ERR_MODULE_NOT_FOUND` for `next/cache`, and `resolve.alias` for any `@/` import your config or test uses, since Vitest does not read `tsconfig.json`'s `paths`; see [Run it in Vitest](/docs/reference/testing#run-it-in-vitest).
- **`tailwind-merge` 3.** `@flowpanel/react` and `@flowpanel/next` depend on `tailwind-merge@^3`, which merges Tailwind v4 utilities correctly. A class passed through `cn()` may now lose a v4 conflict that v2 kept both sides of. A host on `tailwind-merge@^3` shares one copy with FlowPanel.
- **The scaffolded admin layout forwards a nonce.** In a host with its own root layout, the layout `init` writes renders `ThemeScript` with the `x-nonce` header; under a strict `script-src`, set `x-nonce` for that route too.
- **`init` adds `suppressHydrationWarning` to your root layout.** `ThemeScript` marks `<html>` before React hydrates it, so `init` now adds the attribute to the host root layout's `<html>` tag when it is missing, printing the manual edit instead if it cannot patch the file safely. A 0.3.0 host that already ran `init` should add `suppressHydrationWarning` to its root layout's `<html>` tag by hand, or it will see a hydration error in development and `smokeAdmin` will fail on every route.
- **`flowpanel new` without `--dir` is stricter.** It refuses a config whose `resources` is not an array literal and points at `--dir`, instead of adding a second `resources` key. `--dir <dir>` writes each resource as its own file.
- **`flowpanel eject` follows a re-exporting root config and a split `resources` directory.** `eject resource`, `eject dashboard` and `flowpanel new` now all follow a root `flowpanel.config.ts` that only re-exports another module, and `eject resource` also finds the right file when `resources` is imported from a one-file-per-resource directory. A 0.3.0 host on that layout previously saw `eject` report the resource "not found".

## Upgrading from 0.2 to 0.3

0.3 changes a few defaults and removes one dead option. Read this list against your `flowpanel.config.ts` before you upgrade.

- **Rows open the detail page.** A resource that configures `detail` and no `drawer` now navigates on row click and on Enter. Set `rowClick: false` to keep rows inert, or `rowClick: "drawer"` where a drawer exists.
- **Pie charts show their legend.** `pieChart({ showLegend: false })` restores the previous look.
- **`table()` honours `emptyState` and `limit`.** Both were declared and ignored; a table that relied on seeing every row of a `query` should drop `limit`.
- **`detail.header` is deprecated.** Move it to `detail.title`; `subtitle` and `badge` are new slots beside it. `title` wins when both are set.
- **Validation messages come from `labels.form`.** An empty required field reads `"{label} is required"` (`labels.form.required`) instead of a Zod type message; custom messages still pass through. Override the key to change the wording.
- **`audit.retention` is removed.** It was never applied; delete the line and keep retention where the rows live.
- **Drawer field payload shape.** A drawer's serialized `fields` are `{ name, label? }` objects instead of bare names. Only a host reading the drawer payload directly is affected.
- **Workers publish through `@flowpanel/kit/publish`.** `createPublisher({ redis })` replaces `bindPublisher(config)` in a publish-only process. The Redis wire is unchanged, so 0.2 and 0.3 instances interoperate during a rolling deploy.
- **`formatNumber`'s third argument.** It is now the resolved `formatting` object (`useFormatting()` in a client component, `resolveFormatting(config.formatting)` on the server), not a locale string. A bare locale string still works and keeps 0.2's `USD`/`UTC`, so an ejected widget compiles either way.
- **`Date` values in cards and ticks.** A `Date` in a `stat`, `statGroup` or `kv` value, and every chart x-axis tick, now renders through the admin's `formatting` (`locale`, `timeZone`) like a table cell instead of the server's own clock. Drop any hand-rolled `toISOString().slice(0, 10)` in a widget resolver.
- **`ctx.count` rejects an unknown `where` key.** A key the adapter does not report as a column throws a config error naming the field and the resource, on both count paths, instead of silently counting the whole table on Drizzle and throwing inside Prisma.
- **`HealthBanner`'s error tone is `"err"`.** The component now speaks the shared `Tone` vocabulary; rename `tone="error"` to `tone="err"`.
- **`StatItem.value` takes only `ctx`.** Its never-passed second `row` parameter is gone; the record is `ctx.row`.
- **The memory realtime driver serialises payloads.** Like Redis, it now JSON-encodes on publish and decodes on delivery, so a `Date` in a payload arrives as a string and a non-serialisable payload throws in development too, with or without a subscriber.
- **`ctx.db` stays.** Its deprecation notice now names 1.0 as the removal target; `ctx.sql` and `ctx.count` are the supported way to query from a widget.
- **New package.** Add `@flowpanel/test` as a dev dependency next to `@playwright/test` to run `smokeAdmin` in your browser suite.

## Pre-1.0 expectations

Before 1.0, minor releases may contain breaking changes. Types and deprecation notes are part of the migration path, but they do not replace the changelog and application tests. Upgrade in a reviewable branch and avoid mixing unrelated dependency changes.

If the installed behavior and current site disagree, use the versioned package types and release notes as the authority and report the documentation mismatch.
