Do this review before an admin takes production traffic. FlowPanel runs inside your Next.js process with your database client and your auth; there is no FlowPanel control plane, so each item below is yours.

## Runtime and data ownership

- Review `flowpanel.config.ts`, the generated routes and migrations like the rest of the app.
- Expose only the resources and fields that belong in the admin.
- Custom widgets, pages, renderers and workers are your code: generated-handler policies do not cover them.

## Security boundary

- **Authentication.** Replace any development session with real auth and set `auth.access`. `devAuth()` refuses to start when `NODE_ENV` is `production`. See [Authentication](/docs/guides/authentication).
- **Roles.** Use resource and action `access` and field rules; the server rejects fields an operation may not write. See [Roles and permissions](/docs/guides/permissions).
- **Tenants.** Scope every tenant-owned resource. The first-party adapters fail closed when a bound scope does not constrain the query. See [Multi-tenant scope](/docs/guides/multi-tenant-scope).
- **Client IP.** Set `security.trustedProxies` to the number of proxies that append to `X-Forwarded-For` (`1` on Vercel or behind one nginx). Without it `ctx.ip` is `null`, and `defineAdmin` refuses `rateLimit` with `per: "ip"` in production; with no proxy in front, use `per: "user"`. Never grant access by `ctx.ip`. See [SecurityConfig](/docs/reference/define-config#securityconfig).
- **Origins.** Cross-origin writes are blocked by default. Add exact `security.trustedOrigins` only for another frontend that must write. Server-to-server clients without an `Origin` header pass this check, so authenticate them yourself.
- **Read-only mode.** `readOnly: true` turns off every generated write for a demo, maintenance or an incident.

## Writes and their effects

- Declare explicit create and update fields.
- Turn on the [audit log](/docs/guides/audit-log) and run `flowpanel migrate`, or pass `audit.sink` to keep events in your own store.
- Use the Redis rate-limit driver with more than one instance; the memory driver counts per process.
- `rateLimit` counts each admin page view once, page and metadata together, and a router prefetch counts like a view. The admin's own links do not prefetch; give your own links into the admin `prefetch={false}`, or set the limit with room for their prefetches.
- Audit, realtime and revalidation run after commit. A failure there is logged on the server and leaves the write committed; alert on those log lines ([details](/docs/reference/runtime-contracts#post-commit-effects)).

## Migrations

Run `pnpm flowpanel migrate --dry-run` before applying. On PostgreSQL and SQLite each file and its applied marker share one transaction. MySQL commits DDL implicitly, so make changes restart-safe, take a backup, and plan a forward fix. See [flowpanel migrate](/docs/reference/cli#flowpanel-migrate).

## Realtime and queues

Use the Redis driver when more than one process serves the admin, and treat events as refresh signals, not a durable log. Keep the queue board on a protected network, and give `queue()` a strong `boardSecret` that matches the board's `auth.secret`. See [Realtime](/docs/guides/realtime) and [Queues](/docs/guides/queues).

## Page weight

The admin is one catch-all route, but each page type loads its own client code first: a list starts without the forms' code, which then loads while the browser is idle (or when New or Edit is pointed at), and a chart loads Recharts the first time it draws. First-load JavaScript of the demo app in a production build, gzip, measured before the idle form preload:

| Page | Turbopack | webpack |
| --- | --- | --- |
| List | 245 KB | 241 KB |
| Form | 293 KB | 284 KB |
| Record | 253 KB | 250 KB |
| Dashboard with charts | 387 KB | 396 KB |

Next.js 16 builds with Turbopack unless you pass `--webpack`; Next.js 15.5 builds with webpack. The admin splits its code the same way under both, and the two land within 3% of each other on every page above. CI holds the demo's webpack admin first load to a budget.

Your own client widgets add to every admin page unless they load their heavy parts on use; see [Keep heavy code off other pages](/docs/customization/custom-widgets#keep-heavy-code-off-other-pages). The admin needs JavaScript in the browser; see [JavaScript is required](/docs/introduction/limits#javascript-is-required).

## Observability

Log FlowPanel request IDs, alert on auth, scope, rate-limit, adapter and post-commit failures, and document how to turn off writes and restore from backup. See [Errors](/docs/reference/errors).

## Browser smoke test

Run `smokeAdmin` from `@flowpanel/kit/test` in CI. It opens every dashboard, list and first record, and fails on a 4xx/5xx, a console error, a FlowPanel error card, and, with `a11y: true` and `@axe-core/playwright` installed, an axe WCAG 2.2 AA violation. See [Testing](/docs/reference/testing).

## Release checklist

- [ ] Real authentication; unauthenticated requests fail.
- [ ] `auth.access` and resource policies have allowed and denied tests.
- [ ] Every tenant-owned resource is scoped; cross-tenant reads and writes fail.
- [ ] Trusted origins are set only where needed.
- [ ] Forms, imports, exports, actions and hidden resources expose nothing unintended.
- [ ] Audit log, rate limiting, logs, request IDs and alerts are configured.
- [ ] Pending migrations were reviewed with `--dry-run`; backup and recovery are documented.
- [ ] Realtime and queues use production drivers and protected origins.
- [ ] Typecheck, lint, build and `smokeAdmin` pass.
