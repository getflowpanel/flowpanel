---
title: Resources
description: How resource() turns one table or model into a CRUD page.
---

A resource is one entry in your config that maps to one CRUD page in
the admin. The shape is intentionally small — most resources need only
a list of columns, sometimes a couple of filters.

## Minimal (Drizzle)

```ts
resource(schema.users, {
  columns: ["id", "email", "role", "createdAt"],
})
```

The first argument is the Drizzle table; the second is the resource
options object. The row type is inferred from `table.$inferSelect`, so
`columns: ["pwd"]` against a `users` table without a `pwd` field is a
TypeScript error at the call site.

## `columns` is optional

Leave `columns` out and `defineAdmin` fills it with every column the adapter
introspects, in introspection order:

```ts
resource(schema.users, {})
```

That is a scaffolding convenience, not a production default — it puts every
column in the table, including ones you may not want an operator reading.
Declare `columns` as soon as you know which ones belong there.

If the adapter cannot introspect the ref, or reports zero columns, an omitted
`columns` **throws** at `defineAdmin` time rather than rendering an empty
table. The message names the resource and tells you to declare `columns`
explicitly.

## Labels

`label` is the singular label, `plural` the one the nav and list title use.
`labelOne` is narrower still: it names exactly one record, and the create
page's heading reads `New {labelOne ?? label ?? name}`.

```ts
resource(schema.people, {
  columns: ["id", "email"],
  label: "Person",
  labelOne: "Person",
  plural: "People",
})
```

## Reserved names

`dashboards`, `drawer` and `queues` are the first URL segments FlowPanel's own
routing claims, so a resource (or a queue key) named after one has its requests
captured by the wrong route. `defineAdmin` throws instead of letting that
happen — rename with `options.name`:

```ts
resource(schema.queues, { name: "job_queues", columns: ["id", "state"] })
```

## Minimal (Prisma)

```ts
resource("User", {
  columns: ["id", "email", "role", "createdAt"],
})
```

Prisma's adapter takes the **PascalCase** model name as a string. The
delegate is resolved at runtime as `prisma.user`. To get the same
end-to-end row inference Drizzle gets for free, augment
`FlowpanelResources`:

```ts
import type { User, Post } from "@prisma/client";
declare module "@flowpanel/kit" {
  interface FlowpanelResources {
    User: User;
    Post: Post;
  }
}
```

Without the augmentation the row type falls back to
`Record<string, unknown>`, whose keys are `string` — so `columns: ["emial"]`
compiles, and the `row` inside `render: (row) => ...` is untyped. **Typos are
not caught at compile time until `FlowpanelResources` is augmented.**

They are still caught, just later: `defineAdmin` introspects the adapter and
rejects a resource that points at a column the adapter does not report. That
is a define-time throw when your config module is evaluated, not a red
squiggle in the editor — see [Typos and column
validation](#typos-and-column-validation).

## With filters and actions

```ts
resource(schema.orders, {
  columns: ["id", "status", "total", "createdAt"],
  filters: [
    {
      field: "status",
      type: "select",
      options: [
        { label: "Pending", value: "pending" },
        { label: "Paid", value: "paid" },
      ],
    },
    { field: "createdAt", type: "daterange" },
  ],
  actions: [
    {
      key: "refund",
      label: "Refund",
      confirm: "Refund this order?",
      run: async (row, _input, ctx) => {
        await refund(row.id, ctx.db);
        return { ok: true, refresh: true };
      },
    },
  ],
})
```

`filters` becomes typed query controls in the table header. A bare string
there always renders a **text** filter — there is no inference from the
column's type, so declare a `FilterDef` with an explicit `type` for anything
else. Row-level `actions` appear in the row's overflow menu and run
server-side; `bulkActions` apply across selected rows.

### The injected Delete bulk action

A resource with delete enabled that declares no `bulkActions` gets a default
`delete` bulk action injected by `defineAdmin` — so the selection bar is never
empty by accident. Opt out with either:

```ts
resource(schema.orders, { columns: ["id"], bulkActions: [] })      // no bulk actions
resource(schema.orders, { columns: ["id"], delete: { disabled: true } }) // no delete at all
```

`readOnly: true` on the admin strips every bulk action, injected one included.

## Table density

Set `density: "compact"` for a tighter row height on high-volume tables
(the default is `"comfortable"`):

```ts
resource(schema.events, {
  columns: ["id", "type", "createdAt"],
  density: "compact",
})
```

## Import & export

Add **Export** (CSV / JSON) and **Import** buttons to the list toolbar with the
`export` and `import` options — see
[Import & export](/docs/customization/import-export).

## Access control

Gate a whole resource behind a role with `requireRole` — a `string`,
`string[]`, or `(session) => boolean`. A user who doesn't satisfy it can't
reach the resource. For per-field gating inside the form, see
[role-gated fields](/docs/customization/forms#role-gated-fields).

```ts
resource(schema.invoices, {
  columns: ["id", "amount", "status"],
  requireRole: "admin",
})
```

## Default labels and `humanize`

If you omit `label` on a column or field, FlowPanel humanizes the raw
identifier — `createdAt` becomes "Created at", `apiKey` becomes "API
key", common initialisms (`ID`, `URL`, `API`, ...) stay uppercase. The
helper is exposed as `humanize(name)` and `resolveFieldLabel(label,
field)` from `@flowpanel/kit` if you want to use the same convention
inside a custom renderer.

## Inferring the row type

`resource<Ref>(ref, options)` resolves the row type via `InferRow<Ref>`:

- Drizzle table → `ref["$inferSelect"]`.
- Prisma model name (or any string ref) → `FlowpanelResources[Ref]` if
  augmented, else `Record<string, unknown>`.
- Anything else → `Record<string, unknown>` (loose but safe).

When `InferRow` resolves to a real row type, typos in `columns: [...]`,
`filters[...].field`, `defaultSort.field` and `search: [...]` are compile-time
errors against your real schema. When it falls back to
`Record<string, unknown>` — a Prisma string ref with no registry entry, or a
ref of a shape FlowPanel doesn't recognize — those fields are plain `string`
and nothing is checked at compile time.

## Typos and column validation

Whatever the compiler saw, `defineAdmin` re-checks the config against the
adapter's introspection when it resolves. A `columns` entry, a `filters`
entry, `defaultSort.field`, or a `create.fields` / `update.fields` `name` that
names a column the adapter does not report throws, with the near match spelled
out:

```text
resource "users" points at column "emial" via columns[1], but the adapter
reports no such column. Did you mean "email"? Known columns: "id", "email", …
```

Two deliberate gaps:

- A column that declares no `field` (a `render`-only column — see
  [Column renderers](/docs/customization/column-renderers)) has nothing to
  check, so it is skipped.
- When the adapter cannot introspect the ref at all it reports nothing, and
  validation is skipped rather than guessing. (An **omitted** `columns` still
  throws in that case, because there is nothing to fill it from.)

## Excluding a resource

If a table exists in your schema but you don't want it in the admin,
just don't list it. There's no opt-out — there's only opt-in.
