FlowPanel does not reimplement a queue UI. It registers your BullMQ queues as
nav entries and embeds [bull-board](https://github.com/felixmosh/bull-board) —
which means the interesting part is not the page, it is keeping that board from
being reachable by anyone who finds the port.

```ts
import { defineAdmin, queue } from "@flowpanel/kit";
import { drizzleAdapter } from "@flowpanel/kit/drizzle";
import { db } from "@/server/lib/db";
import * as schema from "@/server/lib/db/schema";
import { getSession } from "@/server/lib/auth";
import { emailQueue, scrapeQueue } from "@/lib/queues";

export default defineAdmin({
  adapter: drizzleAdapter({ db, schema }),
  auth: { session: getSession, role: () => "admin" },
  queues: [
    queue(emailQueue, {
      label: "Email",
      boardUrl: `http://localhost:3001/queue/email?token=${process.env.BOARD_TOKEN}`,
      requireRole: "admin",
    }),
    queue(scrapeQueue, { label: "Scraping", boardUrl: "…" }),
  ],
});
```

## queue()

```ts
export function queue(ref: unknown, options: QueueOptions): QueueConfig;
```

`key` defaults to the queue's own `.name` and is what appears in the URL —
`<basePath>/queues/<key>`, i.e. `/admin/queues/email` at the default
`basePath` (`basePath` carries its own leading slash, so there is none in
front of it).

`defineAdmin` throws when:

- two queues resolve to the same key;
- a queue's ref has no `.name` **and** `options.key` is unset — "queue()
  requires options.key when the queue has no .name";
- the resolved key is one of the reserved route segments `dashboards`,
  `drawer` or `queues`, which FlowPanel's own routing claims first.

Full property tables are on the [queue() reference](/docs/reference/queues).

## The board runs outside the admin

`boardUrl` is embedded in an `<iframe>`. That board is a **separate HTTP
server on its own port**, so none of FlowPanel's gates apply to it — not
`auth.requireRole`, not the queue's `requireRole`. Those protect the admin page;
they cannot protect a port they do not sit in front of.

So the board requires its own shared secret:

```ts
import { startBoardServer } from "@flowpanel/kit/bullmq/board";
import { queuesByName } from "@/lib/queues";

const token = process.env.BOARD_TOKEN;
if (!token) throw new Error("BOARD_TOKEN is required");

startBoardServer({
  queues: queuesByName,
  port: 3001,
  bindHost: "127.0.0.1",
  auth: { token },
});
```

`auth.token` is **required** — there is no unauthenticated mode. The token is
compared in constant time, and requests without it get `401`.

```ts
interface StartBoardServerOptions {
  queues: Record<string, Queue>;
  /** Default 3001. */
  port?: number;
  /** Path the Express app is mounted at. Default '/'. */
  basePath?: string;
  /** Host interface to bind. Default '127.0.0.1'. */
  bindHost?: string;
  /** Required shared secret. */
  auth: { token: string };
}
```

Two things worth doing in production:

- **Stay on loopback.** `bindHost` already defaults to `"127.0.0.1"`, so the
  board is unreachable from outside the host unless you widen it — the
  explicit `bindHost: "127.0.0.1"` above only spells the default out. Reverse-
  proxy the board behind the same auth as the rest of your app rather than
  setting `bindHost: "0.0.0.0"`.
- **Keep the token out of the page.** A `boardUrl` with `?token=` in it puts the
  secret in the iframe's URL, which is fine locally and not fine on a shared
  deployment. Prefer a proxy path that injects the header server-side.

## bullmqAdapter

For reading queue state from your own code — a dashboard widget counting failed
jobs, say — wrap the same instances:

```ts
import { bullmqAdapter } from "@flowpanel/kit/bullmq";
import { emailQueue, scrapeQueue } from "@/lib/queues";

export const queues = bullmqAdapter({ email: emailQueue, scrape: scrapeQueue });
```

```ts
interface BullMQAdapter {
  kind: "bullmq";
  queues: Record<string, Queue>;
}
```

It is a thin wrapper — the point is the single named map, so read through it
rather than reaching for the raw handle again:

```ts
import { metric } from "@flowpanel/kit";
import { queues } from "@/lib/queue-adapter";

metric("Failed jobs", async () => queues.queues.email.getJobCountByTypes("failed"), {
  tone: "err",
  drilldown: "/admin/queues/email",
});
```

(`queues.queues` reads oddly because `bullmqAdapter` returns
`{ kind, queues }` — name the binding after the map, e.g.
`const jobs = bullmqAdapter({ … })` then `jobs.queues.email`.)

## Requirements

`bullmq` and `ioredis` are optional peer dependencies. Install them only if you
use queues:

```bash
pnpm add bullmq ioredis
```

A queue page with an unreachable `boardUrl` renders an empty iframe — the admin
itself keeps working.
