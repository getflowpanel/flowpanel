#### Package

- Breaking: `@flowpanel/core`, `@flowpanel/next`, `@flowpanel/react`, `@flowpanel/charts`, `@flowpanel/client` and the Drizzle, Prisma and BullMQ adapter packages are no longer published: FlowPanel ships as one package, `@flowpanel/kit`. Import the same names from it and its subpaths; the [upgrade guide](https://flowpanel.tech/docs/guides/upgrade) maps each one.
- Breaking: `areaChart`, `barChart`, `lineChart` and `pieChart` come from `@flowpanel/kit`, next to the other widget builders, and `@flowpanel/kit/charts` holds the chart components that were in `@flowpanel/kit/charts/runtime`.
- Breaking: removed `@flowpanel/kit/server`. `getRequestContext`, `requireAccess`, `runWithRequestContext` and `tryGetRequestContext` come from `@flowpanel/kit`, and `publish`, `publishResource`, `bindPublisher` and `emitAudit` from `@flowpanel/kit/next`.
- Breaking: removed `@flowpanel/kit/next/client`, which only the runtime itself used.
- Fixed a CommonJS worker failing to import `@flowpanel/kit/publish` with `ERR_PACKAGE_PATH_NOT_EXPORTED`. The subpath now has a `require` build, so a `.ts` worker in a project without `"type": "module"` runs under `tsx` or `node` as it is.
- Changed the Next.js peer range to `>=15.5.0 <17.0.0`, so Next.js 15.5 and newer 15.x releases work as well as 16.
- Added `llms/`, the whole documentation as plain text in one file per section, next to `llms.txt`.
- Fixed `llms.txt` opening with `> undefined`; it and the `llms/` files now include the config snippets and the compatibility table the docs show.

#### Security

- Fixed a tenant moving its own rows into another tenant: an update through the JSON API, a form or an inline edit that sets the tenant column outside the caller's scope now fails with 403 and leaves the row unchanged, on Drizzle (PostgreSQL, MySQL and SQLite) and Prisma.
- Fixed a Drizzle create on SQLite under a tenant scope writing a row outside the scope for a moment before removing it; the row is now checked before it is written.
- Fixed the client IP coming from the left-most `X-Forwarded-For` entry, which the client sets, so a caller could dodge `rateLimit` with `per: "ip"` and put any address in the audit trail.
- Tenant-scoped create and update on Drizzle keep working with drivers that have no interactive transactions, such as `neon-http`: the scope is then checked just before the write.
- Fixed the memory rate limiter keeping every key it ever saw; it now drops expired buckets and holds at most 10,000 keys.
- Fixed the Redis rate limiter locking a key forever when setting its expiry failed after the first hit; one atomic script now counts the hit and sets the expiry.
- Fixed `devAuth()` signing every request in as an admin in production once `auth.access` was set; it now throws when `NODE_ENV` is `production`, and `defineAdmin` refuses to start with it.
- Fixed `withClerk` letting a custom session claim named `id` replace the Clerk user id that the audit trail and the rate limiter use.
- Fixed `select`, `radio` and `multiselect` values and `reference` ids being checked only in the browser. Every write, row, bulk, drawer and dashboard action forms included, now refuses, with 422 and a field error, a choice the form did not offer this user (function options resolve with the same request) and a reference to a row the user cannot read, tenant scope included. A value the row already holds is kept. Column `reference`s are checked the same way.
- Fixed an inline edit skipping the field's `validate` and `required` rules.
- Changed restore to refuse with 403 when `update.disabled` is set, like every other change to a row.
- Fixed a signed-out caller learning which resources, actions, drawers and imports exist from the answers. Every route now identifies the caller and applies `readOnly` before it looks up what the URL names, so a refused caller gets the same answer for a name that exists and one that does not.
- Fixed a row action's audit diff carrying every changed column, password hashes and tokens included. Audit diffs of row actions, inline edits and restores now hold only fields the actor may read, never `sensitive` ones.
- Fixed `hooks.onError` naming a different actor than the audit trail when `auth.userId` is set.
- Fixed `__null__` and `__notnull__` passing as a reference id on a write.
- Fixed any reader seeing soft-deleted rows with `?deleted=1`. The list, the JSON API's `includeDeleted` and the export now show deleted rows only to a user the resource's `update` rule admits, the same rule restore needs, and the toggle is hidden from everyone else.
- Breaking: fixed any signed-in user receiving every event on your own realtime channels, other tenants' included. Declare each channel other than `resource.<name>` in `realtime.channels`, with an optional `access` rule; the stream refuses an undeclared channel and `defineAdmin` refuses a widget, dashboard or list that subscribes to one. Under an admin-wide `scope`, such a channel delivers `{}` unless it is declared `tenantSafe`.
- Fixed the realtime stream having no limits: one user may hold 10 streams (`maxPerActor`), the next answers 429, and a stream ends after 15 minutes (`maxAgeMs`) so the browser reconnects through `auth.access` and a revoked user stops receiving events. A stream that fails never holds a slot, and a channel whose `access` rule throws is dropped, reported to `hooks.onError` and named in a `refused` event, while the rest of the stream stays open.
- Breaking: fixed every user who could open a queue page reading the bull-board secret from its HTML. Set `boardSecret` on `queue()` and `auth: { secret }` on `startBoardServer`: each page render adds a link signed for that queue that expires in a minute, the board checks it and adds the queue to its own signed session cookie, where each queue expires an hour after its own latest link, the board shows and acts on only the session's queues (Redis-wide statistics and other queues' metrics answer 404), and the secret never reaches the browser. `auth.secret` takes a list so a secret can rotate. `auth.token` and `?token=` links are gone. `startBoardServer` takes `trustedProxies`, so its cookie is `Secure` behind a TLS-terminating proxy.

#### Config and core

The [upgrade guide](https://flowpanel.tech/docs/guides/upgrade) gives the replacement for each.
- Breaking: removed `requireRole` everywhere so every gate takes one `AccessRule`: dashboards, pages and queues take `access`, `auth.requireRole` and the auth presets' `requireRole` became `access`, and a form field is gated by the resource's `fieldAccess`. A queue's `access` also takes a function.
- Breaking: renamed `authorizeOperation` to `requireAccess` and removed `checkRequireRole` and the `RequireRole` type. `requireAccess(rule, context)` throws when the rule rejects the caller, and a missing rule denies instead of allowing.
- Breaking: a leftover `requireRole` anywhere, `basePath`, or a detail or drawer `header` makes `defineAdmin` throw at startup instead of being ignored, and each auth preset throws when given `requireRole`.
- Breaking: removed `isBuiltinBulkDelete`, `assertCountWhereColumns`, `declaredWriteFields` and `emitAudit` from the `@flowpanel/kit` root; the first three serve the runtime only.
- Added the audit log: `audit: { enabled: true }` without a `sink` now writes every event to the `flowpanel_audit_log` table that `flowpanel migrate` creates, through the Drizzle (PostgreSQL, MySQL, SQLite) or Prisma client, where it used to write nothing. A `sink` still replaces the table. An adapter that cannot write the table makes `defineAdmin` throw unless a `sink` is set. A failed write is logged and the change stands.
- Added the `money` field type with `currency`, `minorUnits` and `storage`: the form edits `399.99` beside the currency's sign, in the admin's decimal separator, and stores `39999` in an integer column or `"399.99"` in a decimal one. `storage: "minor" | "major"` overrides what the column type says. `minorUnits` defaults to the currency's own digits (0 for JPY, 3 for KWD) and takes 0 to 8; `defineAdmin` refuses anything else and a currency `Intl` does not know. The form accepts a comma or a point as the decimal separator and the minus sign some locales print. Text that is not an amount gets the new `labels.form.invalidMoney`, and an amount with more decimals than the field keeps gets the new `labels.form.moneyTooPrecise`; both show an example amount. A stored value the currency cannot hold, such as `1999.5` minor units, shows as `19.995`, unrounded, and the form refuses to save it until the amount is corrected. Saving a form without touching a valid amount leaves the stored value exactly as it was. History shows money fields in their currency. It works in resource forms and action forms.
- Added `minorUnits` to the money column format, the same option a `money` field takes: `{ kind: "money", minorUnits: 2 }` shows `5900` as `$59.00`. `scale` still works and is deprecated; `defineAdmin` refuses a format that sets both. A widget's `ctx.format.money` takes `minorUnits` too.
- Changed an action form's missing-field message to the field's label in the admin's language (`labels.form.required`) instead of `"<name> is required"`.
- Added `audit.access`, who sees the Audit log page and History tabs (everyone `auth.access` admits by default), and `detail.history: false` to drop one resource's History tab.
- Added `actorName`, `targetIds` and `scope` to `AuditEvent`, so a sink gets the actor's name from `theme.user`, every id of a bulk action and the request's tenant. The table store writes a large bulk action in as many statements as the database's bound-value limit needs, in one transaction where the driver has one, so a delete of 10,000 rows records whole on SQLite too.
- Added `allTenants`: return it from the admin-wide `scope` for staff who work across tenants. Their requests skip the resource predicates, while a user with a tenant still gets the fail-closed check. A resource's new `scopeOf(row)` names a row's tenant, so their audit events are filed under the tenant of the row they change (a bulk action across tenants records one event per tenant), and they read every tenant's events. An update by such staff that moves a row to another tenant is filed under both tenants. Only `allTenants` itself counts: a copy made by spreading it does not.
- Changed audit events to carry a diff for creates, form updates and deletes too, not only inline edits, row actions and restores; equal dates and JSON values re-submitted by a form no longer count as changes. An export event no longer puts the file format in `targetId`.
- Breaking: `emitAudit` takes the admin config, `emitAudit(config, event)`, instead of `config.audit`, so a host route records events wherever the admin does.
- Breaking: `DrawerAction` takes the options of a `RowAction` apart from `hidden` and `disabled`: `confirm` takes a title, description and button label, `form` takes `FieldDef`s, and it gains `icon`, `variant: "success"`, `inputSchema` and `outputSchema`. `DrawerFieldFormSpec` is removed, and so is `palette`, which never listed the action in ⌘K.
- Breaking: moved the last top-level labels into their groups: `labels.noResults` is `labels.table.noResults`, `searchPlaceholder` is `table.searchPlaceholder`, `allOption` is `filters.allOption` and `formError` is `form.error`. `defineAdmin` throws on the old names, and on `labels.errors.queryTitle`, so a translation never falls back to English unnoticed.
- Added `export.access`, who may export a resource on top of its `read` rule; the Export button hides for everyone else and the export route refuses them.
- Deprecated `RowAction.hidden`; use `when`, which gets the row as `current` with the request context (`when: ({ current }) => current?.status === "open"`).
- Breaking: `audit-log` is a reserved route segment, and a dashboard or page at `/audit-log` collides with the Audit log page when the audit log is on.
- Added `ctx.read`, `rowOf`, `link`, `format`, `filters` and a typed `where` for `count` to the widget context.
- Added typed resource names, rows and session: register `schema` and `session` on `FlowpanelTypes`.

- Added `LinkTarget`, one link shape for every widget link, and `ListFilters`, its filter type, where `null` turns a default off.

- Added the `timeline`, `heatmap`, `checklist` and `tracker` widgets.
- Added `enumOf()` and the `date`, `relative`, `percent`, `duration`, `boolean` and `url` column formats; `date` takes `calendarDay: true` for a SQL `date` column read as midnight UTC.
- Added metrics that count rows (`metric(label, { count })`), compare with the previous period (`compare`), and tone their value against a `Threshold` (`tones`), with `goodWhen` on the metric.
- Added `maxRange`, `freshness` and `coverage` to every widget.
- Added `access` on every widget, the rule dashboards and actions take: a refused widget is left out of the dashboard, record page or drawer, its queries never run, and a section it empties is left out. `WidgetContext` gains `role`.
