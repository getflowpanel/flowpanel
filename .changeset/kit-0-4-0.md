#### Package

- Breaking: FlowPanel ships as one package. `@flowpanel/kit` now holds what `@flowpanel/core`, `@flowpanel/next`, `@flowpanel/react`, `@flowpanel/charts`, `@flowpanel/client` and the Drizzle, Prisma and BullMQ adapters held, and those are no longer published. Import the same names from `@flowpanel/kit` and its subpaths; the [upgrade guide](https://flowpanel.tech/docs/guides/upgrade) maps each one.
- Breaking: `areaChart`, `barChart`, `lineChart` and `pieChart` come from `@flowpanel/kit`, next to the other widget builders, and `@flowpanel/kit/charts` holds the chart components that were in `@flowpanel/kit/charts/runtime`.
- Breaking: removed `@flowpanel/kit/server`. `getRequestContext`, `requireAccess`, `runWithRequestContext` and `tryGetRequestContext` come from `@flowpanel/kit`, and `publish`, `publishResource`, `bindPublisher` and `emitAudit` from `@flowpanel/kit/next`.
- Breaking: removed `@flowpanel/kit/next/client`, which only the runtime itself used.
- Changed the Next.js peer range to `>=15.5.0 <17.0.0`, so Next.js 15.5 and newer 15.x releases work as well as 16.
- Added `llms/`, the whole documentation as plain text in one file per section, next to `llms.txt`.
- Fixed `llms.txt` opening with `> undefined`; it and the `llms/` files now include the config snippets and the compatibility table the docs show.

#### Security

- Fixed a tenant moving its own rows into another tenant: an update through the JSON API, a form or an inline edit that sets the tenant column outside the caller's scope now fails with 403 and leaves the row unchanged, on Drizzle (PostgreSQL, MySQL and SQLite) and Prisma.
- Fixed a Drizzle create on SQLite under a tenant scope writing a row outside the scope for a moment before removing it; the row is now checked before it is written.
- Fixed the client IP coming from the left-most `X-Forwarded-For` entry, which the client sets, so a caller could dodge `rateLimit` with `per: "ip"` and put any address in the audit trail.
- Tenant-scoped create and update on Drizzle keep working with drivers that have no interactive transactions, such as `neon-http`: the scope is then checked just before the write.
- Fixed the memory rate limiter keeping every key it ever saw; it now drops expired buckets and holds at most 10,000 keys.
- Fixed the Redis rate limiter locking a key forever when setting its expiry failed after the first hit; one atomic script now counts the hit and sets the expiry.
- Fixed `devAuth()` signing every request in as an admin in production once `auth.access` was set; it now throws when `NODE_ENV` is `production`, and `defineAdmin` refuses to start with it.
- Fixed `withClerk` letting a custom session claim named `id` replace the Clerk user id that the audit trail and the rate limiter use.

#### Config and core

- Breaking: removed the options and exports deprecated in 0.3: `requireRole` on resources and actions, `ctx.db` in actions and option resolvers, `ctx.href`, detail and drawer `header`, a delta's own `goodWhen`, `basePath`, `AdminConfig`, the root `createPublisher`, and the adapter aliases `applyScope`, `scopeRequired`, `runMigrationSql` and `markMigrationApplied`. The [upgrade guide](https://flowpanel.tech/docs/guides/upgrade) gives the replacement for each.
- Breaking: removed `requireRole` everywhere so every gate takes one `AccessRule`: dashboards, pages and queues take `access`, `auth.requireRole` and the auth presets' `requireRole` became `access`, and a form field is gated by the resource's `fieldAccess`. A queue's `access` also takes a function.
- Breaking: renamed `authorizeOperation` to `requireAccess` and removed `checkRequireRole` and the `RequireRole` type. `requireAccess(rule, context)` throws when the rule rejects the caller, and a missing rule denies instead of allowing.
- Breaking: `defineAdmin` throws at startup on a leftover `requireRole` anywhere, `basePath`, or a detail or drawer `header`, instead of ignoring it, and each auth preset throws when given `requireRole`.
- Breaking: removed `isBuiltinBulkDelete`, `assertCountWhereColumns`, `declaredWriteFields` and `emitAudit` from the `@flowpanel/kit` root; the first three serve the runtime only.
- Added `ctx.read`, `rowOf`, `link`, `format`, `filters` and a typed `where` for `count` to the widget context.
- Added typed resource names, rows and session: register `schema` and `session` on `FlowpanelTypes`.
- Added `InferNamedRow`: `resource("User", { name: "users" })` checks its options against the row `FlowpanelResources` registers under `users`, so a Prisma resource with its own name is typed.
- Added `LinkTarget`, one link shape for every widget link, and `ListFilters`, its filter type, where `null` turns a default off.
- Added checks in `defineAdmin` for the resource, column and filter names a config references; a typo fails at startup with the closest match.
- Added the `timeline`, `heatmap`, `checklist` and `tracker` widgets.
- Added `enumOf()` and the `date`, `relative`, `percent`, `duration`, `boolean` and `url` column formats; `date` takes `calendarDay: true` for a SQL `date` column read as midnight UTC.
- Added metrics that count rows (`metric(label, { count })`), compare with the previous period (`compare`), and tone their value against a `Threshold` (`tones`), with `goodWhen` on the metric.
- Added `maxRange`, `freshness` and `coverage` to every widget.
- Added `detail.stats`, `detail.aside`, `related()` tabs and `FieldDef.render`.
- Added resources over database views that write through `writeTo`.
- Added dashboard `filters`, `filterOnClick`, `dateRange.presets` and `navGroup`.
- Added the `series()`, `breakdown()` and `presetRange()` helpers.
- Added Russian base labels for a Russian `formatting.locale`.
- Added `errors.connectionHint` for refused or unreachable database connections.
- Added `labels.table.empty`, `labels.table.editCell`, `labels.table.saved`, `labels.drawer.title`, `labels.drawer.loadFailed`, `labels.drawer.unsupported`, `labels.form.createDisabled`, `labels.form.editDisabled` and `labels.widget.noChange`, with Russian text.
- Added `labels.form.taken`, `conflict`, `missingReference`, `missingLink` and `inUse` for writes the database refuses, with Russian text.
- Changed `resolveOperationAccess(access, operation)` to take two arguments; the `requireRole` argument is gone.
- Changed a resource's `columns` and `filters` to take string keys of the row (`keyof Row & string`), like every other field slot, so a numeric key no longer type-checks there.
- Changed every error `defineAdmin` throws for a bad config to a `FlowpanelConfigError` that reads `[flowpanel] <where in the config>: <what is wrong>. <how to fix>.`, such as `[flowpanel] resource "orders" rowClick: it is "drawer" but the resource has no drawer. Add drawer: { fields: "*" }, or change rowClick.` Its `where` holds the config path. Code that matched the old wording, such as "Duplicate resource name", needs the new one.
- Changed `ctx.ip` to `null` unless `security.trustedProxies` says how many proxies append to `X-Forwarded-For` (`1` on Vercel or behind one nginx or Traefik); it is then the address the outermost of them recorded, without a port. `ctx.ip` is for logs and rate limits, not for deciding who gets in.
- Breaking: `rateLimit` with `per: "ip"` now needs `security.trustedProxies`; `defineAdmin` refuses it in production and warns in development. An app with no proxy in front uses `per: "user"` for signed-in operators, or `rateLimit.enabled: false`. A caller with no IP is keyed by user id, and one with neither is not limited, so no config can put every caller in one bucket; a public admin without `trustedProxies` gets a warning that signed-out visitors go unlimited.
- Changed `createPublisher` from `@flowpanel/kit/publish` to resolve when Redis fails: the error goes to `onError`, or is logged once per kind. A caller that retried on a rejection should pass `onError`. It also takes the admin's `realtime` options.
- Changed the Redis realtime and rate-limit drivers to accept ioredis 6 as well as 5.
- Fixed concurrent first publishes or subscribes opening one Redis connection each.
- Fixed an unhandled rejection when the Redis realtime driver unsubscribes on a closed or failed connection; it now logs the reason.
- Changed `fillDays` to bucket days in `range.timeZone` when its options name no zone.
- Changed a zoneless timestamp string without seconds, such as `"2026-10-07T10:00"`, to stay text instead of reading as a date.
- Changed `reportUnexpectedError` to log the error once with `console.error` and its request id when no `hooks.onError` is set; before, nothing was logged. In production the log keeps only the first line of the error and its cause, so query parameters stay out of it.
- Changed the untyped slots to real types: `writeTo` takes an `AdapterRef` (a table, view or model name), `queue()` takes a `QueueRef`, and a resource `scope` is a `ResourceScope` whose `query` you annotate with your adapter's shape instead of casting it.
- Changed `defineAdmin` to resolve a resource's `rowKey` once: the declared one, else the table's primary key, else `"id"`.
- Fixed `withLucia` claiming it needs Next.js 16.3 when `next/headers` cannot load; it now says it works only in a Next.js app's server code.
- Changed the "could not introspect" startup error to carry the adapter's own error as its `cause`, so a missing table or a wrong model name shows up in the stack.
- Added a startup check that asks a function `auth.access` about a signed-out visitor: if it lets them in, `defineAdmin` warns in development and refuses to start in production unless the admin is declared public and read-only, as for an admin without `auth.access`. A removed `requireRole` written as a function now gets an error that shows the new argument.

- Added `FlowpanelNotFound(config)` and `createFlowpanel(config).notFound` for the host's `not-found.tsx`: the labelled "Page not found" screen with its way back, which also titles the page.

- Added `robots: { index: false, follow: false }` to every admin page's metadata.
- Added a development note and a link to the authentication guide to the sign-in wall outside production, and a one-time console warning with the same note.
- Breaking: `DrawerPayload.header` is now `DrawerPayload.title`.
- Changed every action and form route to answer a failure as `{ ok: false, error, code, requestId?, fieldErrors? }`. A form validation failure carries `fieldErrors` instead of `issues`, and a 404 is a string, so a stale tab that runs a removed action shows "action not found" instead of an empty toast.
- Changed dashboard, page and queue gates, the admin-wide gate and the stream to read `access`; a dashboard action runs only when both the dashboard's and the action's `access` admit the caller.
- Changed widget links to resolve on the server; an unknown target throws with the registered names.
- Changed date presets and `daterange` filters to start at midnight in `formatting.timeZone`.
- Changed a list row to open its record page when the resource has no drawer, with or without `detail`, so a new resource's rows open and reach Edit. `rowClick: false` keeps rows from opening.
- Changed related tab rows to open their target record.
- Changed a list filter's `defaultValue` to apply until the URL sets the filter.
- Changed a failed widget card, in a drawer too, to keep its title and show the cause in a closed Details disclosure outside production.
- Changed an unknown admin path and a record that does not exist to render the not-found page through `notFound()`: a 404, or a 200 with `noindex` under `cacheComponents`, where Next has already streamed the static shell.
- Changed a failed read whose error chain shows a refused or unreachable Postgres, MySQL, SQLite or Prisma connection to show `errors.connectionHint` in place of `errors.queryHint`.
- Changed the empty-admin screen to lead with `flowpanel new <table>`, written for the package manager that started the server (`pnpm`, `npx`, `yarn` or `bunx`), keep the config snippet as the alternative and link the getting-started guide.
- Changed `required` on a create or edit form field to hold on the server: a create that leaves the field empty, or an edit that clears it, fails with the field's "is required" message. A field the form hides or shows read-only to that user is not checked.
- Changed a resource without `labelOne` or `label` to name one record by its name made singular and readable: `users` reads "User" on the record page and "New user" and "Edit user" on its forms, where `New {label}` and `Edit {label}` now put the label mid-sentence ("New customer").
- Changed the sign-in and access-denied walls to title the page "Sign in required" and "Access denied" instead of the host's title.
- Changed a form route's unexpected failure to reach `hooks.onError` and answer with its `requestId`, like the JSON API.
- Changed a JSON create or edit whose value is not a number for a number column to answer with `labels.form.invalidNumber` ("Total must be a number"), as the form already did, instead of Zod's "expected number" text. A schema's own message is kept.
- Changed the record page heading without `detail.title` to show the row's `name`, `title` or `email` ("Ann") before falling back to "User · <id>".
- Changed a `reference` column on the record page to show the referenced record's label with a link ("Ann"), as the list does, instead of the raw foreign key.
- Changed forms to leave out a field the caller may neither read nor write under `fieldAccess`, and to show one they may only read as read-only.
- Fixed a widget's `redirect()`, `notFound()` and `forbidden()` becoming an error card, on the server and in the browser.
- Fixed `table({ resource })` ignoring the resource's `defaultSort`.
- Fixed kv, stat and stat-group dates rendering in UTC while columns used the viewer's zone.
- Fixed the admin root without a dashboard being titled "Page not found"; it now carries the brand name.
- Fixed a function `readOnly` not applying on create, where it gets an empty row. A field's `readOnly` now also wins over the resource's `fieldAccess.write`.
- Fixed saving a form that shows a read-only field, has a field the signed-in role cannot see, or has a field `fieldAccess.write` keeps from that role, failing with "cannot be changed". The form shows such a field read-only and its route drops it; an API or programmatic write that carries it is still rejected.
- Fixed links doubling the slash when the admin is mounted at `/`.
- Fixed English left in a translated admin: an empty list's title, the drawer's name, its load error, its note for a widget it does not draw, and the create and edit pages of a disabled operation now come from labels.
- Fixed an empty drawer tab naming the raw table instead of the tab.
- Fixed the admin logging a `crypto.randomUUID()` prerender error on every request under `cacheComponents`; the page now waits for the incoming request before it reads it.
- Fixed an edit form that empties a NOT NULL column answering ok and keeping the old value. It now fails with the field's "is required" message, as a create does.

A known column gets a field message ("Email is already taken") with a 422; otherwise the answer is a 409 with `labels.form.conflict`, `missingLink` or `inUse`.

#### Drizzle

- Breaking: a resource `scope` function that returns the query unchanged now throws instead of running it unscoped.
- Added reads of Drizzle views declared with `.existing()`.
- Changed Drizzle forms to reject a fractional value for an integer column before it reaches the database; schemas now come from drizzle-zod 0.8, which supports Zod 4.
- Changed `get` to answer `null` when Postgres rejects the id as text for the key's type (22P02), such as `not-a-uuid` for a uuid key, so the record page shows not found instead of an error.
- Fixed `ctx.sql` binding a `Date` or `bigint` inside a nested `sql` fragment.
- Fixed a `numeric` or `decimal` column (Postgres, MySQL, SQLite) getting a text box and failing "12,50" or "abc" with an Internal server error. It is now a number field, a value that is not a number answers 422 "Total must be a number", and the value is written and read as text, so `12.50` stays `"12.50"`.

#### Prisma

- Breaking: a resource `scope` function that returns the query unchanged now throws instead of running it unscoped.
- Changed `get` to answer `null` for an id that cannot be the model's key, such as `abc` for an `Int @id` or a malformed UUID (P2023), so the record page shows not found instead of an error.
- Fixed a Prisma 7 client silently producing wrong columns and keys: Prisma 7 removed the field metadata from `Prisma.dmmf`, so the adapter now stops with an error that names the supported Prisma 5 and 6.
- Fixed `Decimal` columns logging a React warning per row and losing their scale: reads and writes now return them as strings at the `@db.Decimal` scale, so `49.90` stays `"49.90"`. Prisma 5 does not report the scale, so there the value reads `"49.9"`.
- Fixed create forms requiring every column with a `@default(...)` or `@updatedAt`, such as `createdAt DateTime @default(now())`: the adapter read a DMMF property Prisma does not have and saw no defaults. Those columns are now optional on create, and a `String @id` without a default is kept in the create input instead of being dropped.
- Fixed a `reference` column to a model with an `Int` key, and a list filter on an `Int`, `BigInt` or `Float` field, failing with a Prisma validation error: the adapter turns the string values into numbers before the query.
- Fixed an update or delete of a row that no longer exists throwing Prisma's P2025 when the resource has no scope: `update` returns `null` and `delete` and `restore` do nothing, as the adapter contract says and the Drizzle adapter does.
