---
"@flowpanel/cli": minor
---

- Breaking: removed the fallback to the 0.3 adapter aliases `runMigrationSql` and `markMigrationApplied` from `migrate`, and its reading of `basePath`; see the [upgrade guide](https://flowpanel.tech/docs/guides/upgrade).
- Breaking: the 0.4 audit log needs `actor_name`, `scope_key` and `diff_preview` on `flowpanel_audit_log`, with indexes for a record's history and a tenant's log. `diff_preview` holds a bounded copy of each diff, so History and the Audit log never read the whole diffs. A new project's `0001_init.sql` has them. Beside a 0.3 `0001_init.sql`, `migrate` writes and applies `0002_audit_log_0_4.sql`, which adds them and copies each old diff under 8 KB into `diff_preview`; a larger old one shows "Changes too large to preview" with **Show full value**; on MySQL and SQLite it replaces a 0.3 PostgreSQL `0001_init.sql` with the one for the database. `doctor` warns, and `doctor --fix` writes the file, until the table has the columns, also when the table lacks them but no 0.3 file is there. The MySQL `0002` indexes `resource` and `target_id` by prefix, so a 0.3 table ported by hand with `text` columns upgrades.
- Fixed piped output, with no terminal attached, running a line straight into the block before it; a block now has a blank line on both sides.
- Added `flowpanel new <table> --dir <dir>` to write a resource as its own file, on Drizzle and Prisma. On Prisma it reads `schema.prisma`, links foreign keys to models the directory already registers and adds the model to `FlowpanelResources`; later `new` runs on a config that reads the directory write there too.
- Changed `flowpanel new` to accept the SQL table name as well as the export name, and to write the entry the config's adapter takes, so a Prisma project no longer needs `--kind prisma`.
- Changed the generated `resources` comment to point at `flowpanel new`, which removes it when it adds the first resource.
- Changed the generated config to register the Drizzle `schema` and the session type on `FlowpanelTypes`, so resource names, rows and `auth.role` are typed without a cast.
- Changed `init` with a recognised auth provider to write the preset to `server/lib/flowpanel-session.ts` and use its `flowpanelAuth` as the config's `auth`.
- Changed the closed session stub to return a session with `user.role`.
- Added a wizard question that offers the development identity when no session helper is found.
- Changed the development identity to warn once per process instead of on every request.
- Fixed `init --dev-auth` after `flowpanel new`: on an initialized project it now replaces only the session module the config imports, while it is still exactly one of init's stubs, and asks first in a terminal. A module you wrote is refused with what to change instead, and the closed-stub notice and the `doctor` hint name `init --dev-auth`.
- Fixed the generated config failing to compile when your own `getSession` returns no `user.role`: the role mapping reads `user.role` only when it is a string and treats other sessions as `"guest"`.
- Fixed the generated Prisma config to pass the `provider` that `prismaAdapter` requires, read from the Prisma schema.
- Changed `init` to stop when the Prisma schema names a provider other than `postgresql`, `mysql` or `sqlite`, and to warn when it finds no datasource.
- Added `not-found.tsx`, with its `metadata`, and `generateMetadata` to the generated admin route. `init` updates an admin page written before `generateMetadata` instead of reporting a conflict, and `doctor --fix` restores a missing `not-found.tsx`.
- Changed `init` to render `ThemeScript` with the CSP nonce in an app that already has a root layout.
- Changed the `init` closing output to a warning about the session stub, a "Next" block and the admin URL; a second run keeps `flowpanel.config.ts` and says "Already set up; nothing changed.", and `--dry-run` lists the modules it would use.
- Changed `init` to show starting files for a missing Drizzle client, Drizzle schema or Prisma client, also in a terminal, where the guessed path with nothing there no longer asks again. The starter `users` table generates its `uuid` key, so the admin can create a user, and without `DATABASE_URL` the starter client points at a host that never resolves instead of connecting to localhost, so `next build` runs, the admin shows "Check DATABASE_URL" or the failed read's card, the API answers its JSON error, and `migrate` and `doctor` still say the variable is unset. The starting files use `mysql2` or `better-sqlite3` when that is the driver installed, with the SQL for that database, and say when pnpm 10 skipped the build of a better-sqlite3 older than 13. `init` also writes `@/db` instead of `@/db/index`, and adds `@flowpanel/kit` or `@flowpanel/cli` to package.json when they were installed but not declared.
- Fixed the "No ORM found" message of `init` and `doctor` suggesting a Prisma that `init` then refuses: it installs `@prisma/client@6` and `prisma@6`, or `drizzle-orm@0` with the `pg` driver, in your package manager. The starting Drizzle client file asks for `pg` only when it is not installed, and the message gives the SQL that creates the starter `users` table. `doctor` warns, with `DATABASE_URL` set, when the database has no table for a resource, instead of passing while its list shows "Couldn't load".
- Added support in `init` and `new` for the `prisma-client` generator that Prisma 6.19's `prisma init` writes: the starter `lib/prisma.ts` and the `FlowpanelResources` entries import from the generator's `output`, such as `@/app/generated/prisma/client`. `doctor` fails, with the import to write, when the schema sets an `output` but the client module the config imports still reads `@prisma/client`.
- Changed the Prisma 7 refusal of `init` and `doctor` to link the Prisma setup page, which explains how to stay on Prisma 6.
- Changed the `init` notes: `migrate` is needed only if you turn on the audit log, and the development identity says it throws under `next start`. `doctor` shows the installed Next.js version and names the session check "Session module".
- Fixed `init` writing PostgreSQL-only SQL for MySQL and SQLite projects: `flowpanel/migrations/0001_init.sql` now matches the database, so `migrate` works on all three.
- Changed `init` in a pipe to print the files it wrote, the install result and its warnings, without colour codes.
- Changed `init` in a terminal to ask a module question again, with the reason, when the path does not resolve.
- Changed the `init` conflict message, and `--dry-run` on a conflict, to list every conflicting file with the content `init` would write there, so you can merge it by hand.
- Changed `init` to exit 1 when the final "Apply these changes?" question is cancelled with Ctrl+C.
- Fixed `new` and `eject` for a root config that re-exports another module.
- Changed `migrate` on a connection failure to start with the host, port and error code, and to show the failed SQL only with `FLOWPANEL_DEBUG=1`. A wrong password and a database name the server does not have each get their own line that says which part of `DATABASE_URL` to fix.
- Changed `migrate` to exit 1 with "run `init` first" when there is no `flowpanel.config.ts`.
- Breaking: `migrate` stops before connecting when the database URL your client reads (usually `DATABASE_URL`) is unset or empty, instead of letting the driver fall back to localhost. A URL with a fallback in code, such as `?? "file:local.db"`, and variables such as `REDIS_URL` are not checked.
- Changed `migrate --json` to print a JSON error on a connection failure and `"applied": false` when nothing ran, and fixed `migrate` never exiting on MySQL.
- Fixed `migrate` printing `NOTICE: relation "_flowpanel_migrations" already exists` on PostgreSQL with either adapter: the bookkeeping table is created only when it is missing, and `0001_init.sql` no longer creates it, since `migrate` does.
- Changed every command to say "No Next.js project found in <cwd>" when run outside a project root.
- Changed `dev` to run the project's own `next` binary, so it never downloads `next`.
- Changed `dev` to keep Next.js running when the queue board exits, for example on "BOARD_SECRET is required", with one line that says so and suggests `--no-board`.
- Changed `dev` to check the port first, on both `127.0.0.1` and `::1` ("Port <n> is in use. Pass --port <other>."), to reject a `--port` outside 1 to 65535, and to print the admin URL once Next.js is ready.
- Changed `eject` to print "Use --force to overwrite." after a plan with conflicts.
- Fixed `eject resource` breaking the ejected pages, and in a one-file-per-resource directory the config (`export const x = undefined;`): the resource now stays registered, because the ejected `actions.ts` reads rows through it. Ejected files land under `paths.admin`, the ejected layout keeps the `admin.css` import and `<ThemeScript>`, and the ejected layout and pages export `instant = false` when `cacheComponents` is on.
- Fixed `doctor` failing the catch-all page and not-found checks with "Route overlaps" after `eject resource`: a page that carries the eject marker no longer counts as a route in the admin's way.
- Changed `flowpanel new <table>` to write the table's columns, search, filters and default sort, read from your Drizzle schema or `schema.prisma`, instead of empty options. A UUID or cuid primary key stays out of `columns`, a long `varchar` or text column does too unless every insert needs it, since the columns are also the create form's fields, and an integer column whose name ends in `Cents` or `_cents`, such as `amountCents`, shows as money (`format: { kind: "money", minorUnits: 2 }`).
- Changed `flowpanel new` to turn a foreign key to a registered resource into a column `reference`, labelled by the target's NOT NULL name, title or email and headed by the record it points at ("User", not "User ID"), so the create and edit forms get a searchable picker for it with no `create.fields` to keep in step.
- Changed `flowpanel new` on Prisma to name the resource like a Drizzle table: `name` is the `@@map` table name or the model in plural snake case, so `new users` gives `/admin/users` and "Users" in the navigation. It checks the name against `schema.prisma`, resolves a mapped table name such as `users` to its model, and registers the model's row in `FlowpanelResources` under the resource name; the generated Prisma config no longer has an empty interface that failed lint.
- Fixed `flowpanel new --help` naming `schema.<resource>` as the `--table` default on Prisma, where it is the model name.
- Changed `new` to format a SQL `date` column, such as a Prisma `@db.Date`, as `{ kind: "date", calendarDay: true }`, so the day reads the same in every time zone.
- Changed `new --dir` to add the directory to `flowpanel.config.ts` the first time, or print the line to add; `new` writes into a directory the config already reads, and `--hidden` works without `--dir`.
- Added `doctor` warnings for a session module that is still the closed stub or the development identity, an empty `resources` array, an unset connection variable that your database client reads, such as `DATABASE_URL`, and a `drizzle.config.*` whose `tablesFilter` lets `drizzle-kit push` drop `_flowpanel_migrations` or `flowpanel_audit_log`.
- Changed `doctor` to end with "No failures, N warnings to review.", and `doctor --json` to mark warnings with `"warn": true` and put `hint` only on failing and warning checks.
- Changed `doctor` to fail "@flowpanel/kit matches this CLI" when the kit is not installed.
- Changed `doctor` to count `@flowpanel/kit` installations instead of `@flowpanel/core`.
- Changed `doctor` to run `next typegen` before `tsc` when `.next/types` is missing.
- Changed `doctor --fix` to check the files again after writing, then generate types and run `tsc` once.
- Fixed `doctor` saying "No failures" when `flowpanel.config.ts` cannot be evaluated; that is now a failed check. Before `init`, `doctor` asks for `init` once instead of suggesting `--fix`, and a missing `not-found.tsx` is a warning that `--fix` still repairs.
- Changed `new`, `migrate` and `eject` to print plain lines when the output is not a terminal, and `--help` to list commands in workflow order with examples.
- Raised the minimum `@clack/prompts`, `jiti` and `semver` versions to their current releases; prompts now type a cancelled answer as `CANCEL_SYMBOL`.
- Fixed `init` writing files that `next build` refuses when next.config turns on `cacheComponents`, as `create-next-app` does from Next.js 16.4: the API and SSE routes no longer export `runtime` or `dynamic`, and the admin layout and catch-all page export `instant = false` when `cacheComponents` is on, so `next dev` no longer logs "encountered uncached data" on every admin page.
- Added `doctor` and `init` checks for `cacheComponents`: it needs Next.js 16.3 or newer, the first release that reads `instant`, and `doctor` names each admin file that still exports `runtime`, `dynamic`, `revalidate` or `fetchCache`, or reads the request without `instant = false`. `doctor --fix` adds the line to a catch-all page `init` wrote, and removes the `export const runtime = "nodejs"` and `dynamic = "force-dynamic"` lines 0.3's `init` wrote into the route files.
- Changed the Next.js prerequisite of `init` and `doctor` from 16.3 or newer to 15.5 or newer within 15 and 16.
- Breaking: every command stops with an error on an extra argument, such as `flowpanel doctor extra`, instead of ignoring it (Commander 14).
- Fixed `init`, `doctor` and `migrate` looking only for `flowpanel.config.ts`: a `flowpanel.config.tsx` is now evaluated by `doctor` and loaded by `migrate`, and `init` no longer writes a second `flowpanel.config.ts` beside it.
- Changed `init`, `doctor --fix` and `eject` to stop with an error that names the template and the placeholder when a generated file would have a placeholder without a value, instead of writing broken code.
- Fixed `doctor` dropping a check whose probe crashed, which left the run all green: it is now a warning with `Could not check:` and the first line of the error. When `next typegen` fails, the `tsc --noEmit` hint starts with the typegen error, then shows what `tsc` reported.
- Removed the `doctor` check "Destructive actions have confirm", which matched lines by text and also flagged menu items that take no `confirm`. `doctor` now adds a note, shown as a `·` line and `"info": true` in `--json`, when no `eslint.config.*` in the project or above it, up to the repository or workspace root, loads `@flowpanel/eslint-plugin`, whose `audit-row-action-needs-confirm` rule reads the config's actions properly.
- Changed the generated config and session modules to gate the admin with `access: "admin"`.
- Changed the CLI's config errors to core's format, `[flowpanel] <where in the config>: <what is wrong>. <how to fix>.`: a missing `flowpanel.config.ts`, a mount `paths.admin` or `paths.api` that is computed at runtime, a resource or dashboard the config does not have, and the development session stub refusing to run in production. Every command, `init` included, stops through the same error line, marked `✗` in a pipe.
- Changed `init` in a pipe to print like `new`, `eject` and `migrate`: the dry-run modules and plan as titled blocks, `✓` before "Already set up; nothing changed.", the same step lines while it installs packages, and `! FlowPanel init is incomplete` before the commands that finish it.
- Changed `new` on a table with a singular name, such as better-auth's `user`, to add `plural: "Users"`, so the navigation and list heading read as a collection; mass nouns such as `usage` and `history` are left as they are.
- Changed `init` to write the auth preset module, `flowpanel-session.ts`, beside your auth module, such as `lib/flowpanel-session.ts`, instead of always under `server/lib/`.
- Added an `init` hint when the root layout renders a `<header>`: the sidebar shell fills the window's height, so `shell: "tabs"` fits the admin under that header.
- Changed `new --dir` on a Prisma config to link the docs that show how to keep one resource per file.
- Changed the development session stub `init` writes to throw a `FlowpanelConfigError` in production, so the admin shows "the development session stub … refuses to run in production" in the browser, and to name its own file only in the server log.
- Changed `doctor` to print a passing "ESLint plugin" check once your ESLint config loads the plugin, instead of dropping the line.
- Breaking: `engines.node` is now `^20.19.0 || >=22.12.0`, matching `@flowpanel/kit`; Node.js 20.0 to 20.18 and 21 need an upgrade.
- Changed the `init` hint that suggests `shell: "tabs"` to fire for a header component in the root layout, such as `<SiteHeader />`, `<Header>` or `<Navbar />`, not only for a literal `<header>`.
- Changed `flowpanel new` to give each resource in the navigation an `icon` guessed from its table name, so a new entry lines up with the rest instead of reading like a sub-item.
