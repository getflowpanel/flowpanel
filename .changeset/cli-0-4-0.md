---
"@flowpanel/cli": minor
---

- Added `flowpanel new <table> --dir <dir>` to write a resource as its own file.
- Changed `flowpanel new` to accept the SQL table name as well as the export name.
- Changed the Drizzle and better-auth templates to register `schema` and the session on `FlowpanelTypes`.
- Changed `init` to render `ThemeScript` with the nonce in a host that has its own root layout.
- Fixed `new` and `eject` for a root config that re-exports another module.
- Removed `migrate`'s fallback to `runMigrationSql` and `markMigrationApplied`, and reading the deprecated `basePath` (use `applyMigration` and `paths.admin`).
- Changed the generated config to register the session type and map the role without a cast.
- Changed the closed session stub to return a session with `user.role`.
- Changed a recognised auth provider's generated config to take `flowpanelAuth` from the preset module as its `auth` block.
- Changed the generated `resources` comment to point at `flowpanel new`.
- Changed `flowpanel new` to remove that comment with the first resource.
- Changed the development session stub to warn once per process instead of on every request.
- Fixed the generated Prisma config to pass the `provider` that `prismaAdapter` requires, read from the Prisma schema.
- Changed `init` to stop when the Prisma schema names a provider other than `postgresql`, `mysql` or `sqlite`, and to warn when it finds no datasource.
- Added `not-found.tsx` to the files `init` writes and `doctor --fix` restores.
- Added `generateMetadata` to the generated admin page.
- Added a wizard question that offers the open development identity when no session helper is found.
- Changed the `init` closing output to name `flowpanel new <table>`, the dev command and the admin URL.
- Changed the `init` closing output to say what the session stub does.
- Changed `init` in a pipe to print the files it wrote, the install result and its warnings, without colour codes.
- Changed `init` in a terminal to ask a module question again, with the reason, when the path does not resolve.
- Changed the `init` conflict message to list every conflicting file.
- Changed `init` to update an admin page written before `generateMetadata` instead of reporting a route conflict.
- Changed `init` to exit 1 when the final "Apply these changes?" question is cancelled with Ctrl+C.
- Changed `migrate` on a connection failure, for Drizzle and Prisma, to start with the host, port and error code and to show the failed SQL only with `FLOWPANEL_DEBUG=1`.
- Changed `migrate` to exit 1 with "run `flowpanel init` first" when there is no `flowpanel.config.ts`, before it looks for migration files.
- Changed `init`, `doctor`, `dev`, `new`, `migrate` and `eject` to say "No Next.js project found in <cwd>" outside a project root.
- Changed `dev` to run the project's own `next` binary with Node, so it never downloads `next`.
- Changed `dev` to check the port first and to say "Port <n> is in use. Pass --port <other>."
- Changed `dev` to reject a `--port` that is not a number from 1 to 65535.
- Changed `eject` to print "Use --force to overwrite." after a plan with conflicts.
- Changed `new` to write the entry the config's adapter takes when `--kind` is absent, so a Prisma project no longer needs `--kind prisma`.
- Changed `new --help` to state the default `--kind` once.
- Changed `--path <url>` to `--path <path>` on `init` and `doctor`.
- Changed the program and `dev` descriptions.
- Added `doctor` warnings for a session module that is still the closed stub, an empty `resources` array and a missing `DATABASE_URL` next to migration files.
- Added `"warn": true` to warning checks in `doctor --json`, and a "No failures, N warnings to review." summary line.
- Changed `doctor` to fail "@flowpanel/kit matches this CLI" when the kit is not installed.
- Changed `doctor` to run `next typegen` before `tsc` on Next 15.5 or later when `.next/types` is missing.
- Changed `doctor --fix` to check the files again after writing and to generate types and run `tsc` once.
- Changed `doctor --json` to put `hint` only on failing and warning checks.
- Changed `init --dev-auth` on an initialized project to replace a session module that is still the untouched closed stub, and to stop with exit 1 when the module was edited.
- Added a `doctor` warning for a session module that is still the open development identity.
