# FlowPanel — Reference — resource()

## resource()

Every option on a resource, its columns, fields and filters.

Docs: https://flowpanel.tech/docs/reference/resources

Documented types: resource, ResourceOptions, ColumnDef, formatColumnValue, formatNumber, enumOf, EnumDef, FieldDef, FilterDef, DetailOptions, DetailHeaderContext, DetailBadge, related, RelatedOptions, DetailTab, DetailTabContext, ListResult, ResourceConfig

`ref` is a Drizzle table or a Prisma model name. The row type comes from
[`InferRow<Ref>`](/docs/reference/registry#inferrow), which types `columns`,
`search`, `filters` and `defaultSort`.

```ts
import { resource } from "@flowpanel/kit";
import { orders } from "@/db/schema";

export const ordersResource = resource(orders, {
  labelOne: "Order",
  plural: "Orders",
  icon: "shopping-cart",
  columns: ["id", "customerEmail", { field: "total", format: "money" }, "status"],
  search: ["customerEmail"],
  filters: ["status", { field: "createdAt", type: "daterange" }],
  defaultSort: { field: "createdAt", dir: "desc" },
  detail: { title: (row) => `Order · ${row.customerEmail}` },
});
```

### ResourceOptions

`ResourceOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `name?` | `string` | URL segment and registry key. Defaults to the adapter's table name. |
| `label?` | `string` | The one name for both a row and the list when they read the same, such as `"Staff"`. `labelOne` overrides it for one row and `plural` for the list; without any of the three, the resource name is humanized: `order_items` reads "Order items" and one row "Order item". |
| `labelOne?` | `string` | Name for exactly one row, e.g. `"Customer"`: record, create and edit titles and the drawer. Falls back to `label`. |
| `plural?` | `string` | Name for the list: the nav entry, the list title and the detail crumb. Falls back to `label`. |
| `icon?` | `IconName` | Serializable Lucide icon rendered in navigation and the command palette. |
| `hidden?` | `boolean` | Keep the resource out of the navigation — its routes still work. |
| `navGroup?` | `NavGroupRef` | Sidebar group for this resource. Default: the Resources group. |
| `expose?` | `(keyof Row & string)[]` | Additional fields shared by list and detail presentation. Declare render dependencies explicitly; callbacks never receive an undeclared DB row. |
| `columns?` | `((keyof Row & string) \| ColumnDef<Row>)[]` | Columns of the list table, in order; a bare string is a field name. Omitted, `defineAdmin` fills it in introspection order. |
| `search?` | `(keyof Row & string)[]` | Fields the search box queries. Without this, search is disabled. |
| `filters?` | `((keyof Row & string) \| FilterDef<Row>)[]` | Filter controls above the list. A bare string always renders a text filter — declare a `FilterDef` for any other control. |
| `defaultSort?` | `{ field: keyof Row & string; dir: "asc" \| "desc" }` | Sort applied when the URL carries none. |
| `pageSize?` | `number` | Rows per page. Default: `20`. |
| `density?` | `"comfortable" \| "compact"` | Row height preset for the list table. Default: `"comfortable"`. |
| `rowClick?` | `"detail" \| "drawer" \| false` | What a row click — and Enter on the focused row — does. A row the projection cannot identify never acts. Default: ``"drawer"` when `drawer` is configured, otherwise `"detail"``. |
| `rowKey?` | `keyof Row & string` | Property holding each row's unique id. Default: `the table's primary key, else `"id"``. |
| `drawer?` | `DrawerConfig<Row>` | Side panel opened for a single row. |
| `detail?` | `DetailOptions<Row>` | Full-page view at `<paths.admin>/<resource>/<id>`. |
| `schema?` | `z.ZodTypeAny \| { create?: z.ZodTypeAny; update?: z.ZodTypeAny }` | Validation for writes. Overrides the schema inferred from the adapter. |
| `writeTo?` | `AdapterRef` | The table that create, update, delete and restore write to, when the resource reads a view. Omitted on a view: the resource is read-only, and a declared create/update/delete/import is an error at `defineAdmin`. |
| `create?` | `{ disabled?: boolean; fields?: FieldDef<Row>[]; defaultValues?: Partial<Row> }` | Create form. `disabled` removes the route, not just the button. `defaultValues` fills keys a create leaves empty, on the server only, and wins over a field's own `defaultValue`. |
| `update?` | `{ disabled?: boolean; fields?: FieldDef<Row>[]; /** Additional readable values available to edit-form hidden/readOnly predicates; never a control, default or write. */ expose?: (keyof Row & string)[]; /** * How the record page's edit button reads: `"primary"` fills it with the accent. * @defaultValue "secondary" */ emphasis?: ActionEmphasis; }` | Edit form. `disabled` removes the route, not just the button. |
| `delete?` | `{ disabled?: boolean; softDelete?: keyof Row & string; confirm?: string }` | Delete behaviour. Set `softDelete` to a timestamp column to keep rows recoverable. |
| `actions?` | `RowAction<Row, any, any>[]` | Per-row actions, rendered inline or in the row's menu. |
| `bulkActions?` | `BulkAction<Row, any, any>[]` | Actions applied to a selection of rows. |
| `scope?` | `"bypass" \| ResourceScope` | How the admin-wide `scope` narrows this resource. `"bypass"` opts out explicitly. |
| `access?` | `ResourceAccess<Row>` | Canonical operation-level authorization. |
| `fieldAccess?` | `FieldAccessMap<Row>` | Canonical read/write policy for declared fields. |
| `export?` | `{ formats?: ("csv" \| "json")[]; fields?: (keyof Row & string)[] } \| false` | Export button, off unless set. `formats` defaults to `["csv"]`; `fields` defaults to the visible columns. |
| `import?` | `{ formats?: ("csv" \| "json")[]; fields?: (keyof Row & string)[] } \| false` | Import button. Off unless set; rows are created through the normal write path. |
| `audit?` | `boolean` | Opt this resource out of the admin-wide audit sink. |
| `realtime?` | `boolean \| string` | Refresh the list when the channel fires. `true` uses `resource.<name>`. |
| `views?` | `Array<{ name: string; description?: string; /** Filter values keyed by the row's fields: a value, a preset name for a `daterange`, `{ gte, lte }` or an array. */ filters?: ListFilters<Row>; sort?: { field: keyof Row & string; dir: "asc" \| "desc" }; search?: string; }>` | Filter / sort presets offered as a dropdown above the list. |
| `empty?` | `{ /** Serializable Lucide icon rendered above the empty-state title. */ icon?: IconName; title?: string; description?: string; action?: { label: string; href: string }; /** * Title when search or filters leave no rows; a button beside it clears them. `{query}` is * the search text. Default: `labels.widget.filtered`. */ filtered?: string; /** * Title when a search leaves no rows, in place of `filtered`, e.g. `"Nothing found for «{query}»"`. * Default: `filtered`. */ searched?: string; }` | What the list shows when there are no rows at all. |

`label` names both one row and the list, so it suits a word that reads the same
either way. Set `labelOne` and `plural` when they differ: a resource with only
`label: "Order"` titles its list "Order" too. Without any of the three, the
resource name is humanized and made singular for one row.

An empty list shows `empty.title`, `description`, `icon` and `action`. When search
or filters leave no rows it shows `empty.filtered` (or `empty.searched` during a
search; both fill `{query}`) and a button that clears them. On a phone the list
shows 10 rows as cards with the rest behind "N more".

#### Detail headings and editing

Three callbacks fill the record page header. Each receives the row's readable
declared and `detail.expose` fields.

- `detail.title(row)` is the `h1` content: text or inline elements.
- `detail.subtitle(row)` is the line under it.
- `detail.badge(row)` is a pill beside the title: `{ label, tone }`.

```ts
detail: {
  title: (row) => row.email,
  subtitle: (row) => `Customer since ${row.createdAt}`,
  badge: (row) => (row.churned ? { label: "Churned", tone: "warn" } : null),
}
```

A nullish return leaves the slot empty; a nullish `title` falls back to the row's
`name`, `title` or `email`, then to the resource label and the row identifier.

The Edit button sits beside the heading as a secondary button;
`update: { emphasis: "primary" }` fills it. It is hidden when `update.disabled` is
set or the update policy denies the request. A custom `PageHeader` slot uses the
exported `PageHeaderProps`.

Without `detail.tabs`, the page renders one key/value block. `detail.fields`
chooses and orders the fields in it; omitted, every readable declared field shows.

#### Opening a row

`rowClick` decides what a click on a row, or Enter on it, does.

| Value | Effect |
| --- | --- |
| `"detail"` | Navigates to the row's own page under `paths.admin`. |
| `"drawer"` | Opens the [drawer](/docs/reference/drawer). Requires a `drawer` config; `defineAdmin` refuses the combination without one. |
| `false` | Rows render, but a click does nothing. |

Omitted, it follows the resource: `"drawer"` when a drawer is configured, with or
without `detail`, and `"detail"` otherwise. The record page renders without a
`detail` config, so every row opens unless you set `rowClick: false`.
An explicit value always wins, so `rowClick: "detail"` on a resource that also
has a drawer sends the click to the page and leaves the drawer to its own
affordances.

A row without a key never opens. Opening is a router push, not a link, so
cmd-click does not open a new tab; add a column whose `render` returns an anchor
for that.

In a row that opens, an `editable` column starts editing from its pencil icon, a
double click or Enter; a single click opens the row.

#### Reading a view

A resource's ref may be a database view. The list, the record page, counts, exports,
reference labels, related tabs and `ctx.read` read the view; create, update, delete,
restore, import and inline edits write to `writeTo`:

```ts
resource(adminUserRow, {
  name: "user",
  writeTo: user,
  update: { fields: [{ name: "internal", type: "switch" }] },
});
```

`writeTo` must be a table whose primary key the view selects. Every field a form or an
inline `editable` column writes must be a column of both: form fields are typed against the view's row, so select each
writable column in the view. `defineAdmin` checks both and names the missing column. The
write schema is inferred from `writeTo`, the generated edit form offers the table's
writable columns, and an update answers with the view's row, so computed columns are fresh
after a save.

Without `writeTo`, a resource over a view is read-only: its create, update and delete are
disabled, and declaring any of them (or `import`, or an `editable` column) throws at
`defineAdmin`.

#### Icons

Resource, dashboard, page, queue, action and command icons take an `IconName`, a
Lucide icon name such as `users`, `settings`, `database` or `trash-2`. An unknown
name is a type error. To render one in your own component:

```tsx
import { FlowpanelIcon } from "@flowpanel/kit/react";

<FlowpanelIcon name="workflow" className="size-4" />;
```

#### Saved views

`views` puts named filter, sort and search presets in a menu above the list.
Filters are keyed by the row's fields:

```ts
views: [
  { name: "New this week", filters: { createdAt: "last7d" } },
  { name: "Paying, falling asleep", filters: { plan: ["starter", "pro"], daysSinceSeen: { gte: 7 } } },
  { name: "No Telegram", filters: { telegramLinked: false } },
],
```

A `daterange` filter also takes a preset name (`today`, `yesterday`, `last7d`,
`last30d`, `MTD`, `QTD`, `YTD`), resolved on each request. A view may filter only
fields the list declares in `columns`, `filters` or `search`, with values that
match the filter type; `defineAdmin` rejects the rest. For "older than N days",
compute the number in a view and use a `numeric-range` filter.

### ColumnDef

An entry in `columns`. A bare string is shorthand for `{ field: "name" }`.

`ColumnDef`

| Property | Type | Notes |
| --- | --- | --- |
| `field?` | `keyof Row & string` | Row property this column reads. Omit only when `render` supplies the cell. |
| `secondary?` | `keyof Row & string` | Another field of the row, shown as a muted second line under the cell — the email under a name. It is loaded with the row; sort and search still use `field`. Ignored on a `reference` column. |
| `label?` | `string` | Header text. Defaults to a humanized `field`. |
| `render?` | `(row: Row, ctx: RequestContext) => ReactNode` | Custom cell renderer. Runs on the server; receives the request context. |
| `sortable?` | `boolean` | Allow clicking the header to sort by this column. |
| `width?` | `number \| string` | Fixed column width, in px when a number. |
| `align?` | `"left" \| "center" \| "right"` | Horizontal cell alignment. Defaults to `"left"`. |
| `className?` | `string` | Extra classes on every cell in this column. |
| `hidden?` | `boolean` | Keep the column out of the table (still available to export and drawer). |
| `format?` | `ColumnFormat` | Declarative cell formatting — use instead of `render` where it fits. |
| `reference?` | `ReferenceSpec` | Resolve a foreign key to a label from another resource. |
| `editable?` | `boolean` | Allow editing this cell inline from the list. |

A column without `field` must set `render` and `label`; it never sorts or
filters and is skipped by export. See
[Joined or computed values](/docs/customization/column-renderers#joined-or-computed-values).

`secondary` shows another field as a muted second line in the cell, such as the
email under a name. Sorting and search still use `field`.

```ts
columns: [{ field: "name", label: "User", secondary: "email" }],
```

#### ColumnFormat

Declarative cell formatting.

```ts
type ColumnFormat =
  | "badge" | "money" | "number"
  | "date" | "relative" | "percent" | "duration" | "boolean" | "url"
  | { kind: "badge"; tones?: Record<string, Tone>; labels?: Record<string, string> }
  | { kind: "money"; currency?: string; scale?: number }
  | { kind: "number"; tones?: Threshold }
  | { kind: "date"; time?: boolean; calendarDay?: boolean }
  | { kind: "percent"; digits?: number; heat?: boolean; tones?: Threshold }
  | { kind: "duration"; unit?: "ms" | "s"; tones?: Threshold }
  | { kind: "boolean"; labels?: { true?: string; false?: string } }
  | { kind: "url"; label?: string };
```

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.
The object form of `badge` maps each cell value to a tone:

```ts
{ field: "status", format: { kind: "badge", tones: { paid: "ok", failed: "err" } } }
```

`labels` gives each raw value its display text. Tones stay keyed by the raw
value, and a value with no label shows as is.

```ts
{
  field: "role",
  format: {
    kind: "badge",
    tones: { admin: "warn" },
    labels: { admin: "Administrator", freelancer: "Freelancer" },
  },
}
```

The other kinds:

- `date` shows the day in the admin's `timeZone`; `{ kind: "date", time: true }` adds the time. A `YYYY-MM-DD` value shows as itself; a zoneless `YYYY-MM-DD HH:mm:ss` is read as UTC. Set `calendarDay: true` for a SQL `date` column, such as a Prisma `@db.Date` or a Drizzle `date({ mode: "date" })`: the driver returns midnight UTC, and the cell shows that day in every time zone.
- `relative` shows how long ago, such as `5 minutes ago`, in the admin's `locale`.
- `percent` reads a fraction: `0.423` is `42.3%`. `digits` caps the decimals, and `heat: true` shades the cell by its value, for a retention grid that still sorts by number.
- `duration` reads milliseconds, or seconds with `unit: "s"`, and prints the largest units that fit: `4.2 sec`, `2 hr 5 min`.
- `boolean` prints `✓` and `✕`, or `labels: { true: "Yes", false: "No" }`. SQLite's `1` and `0` read as true and false.
- `url` links `http(s)` and same-site values. `label` replaces the text, which defaults to the host and path; any other scheme stays text.
- `{ kind: "number" | "percent" | "duration", tones }` colours the text by a [`Threshold`](/docs/reference/widgets#thresholds), comparing the stored number, so a `duration` in seconds compares seconds. With `tones`, a percent cell is coloured instead of shaded.

```ts
columns: [
  { field: "week", label: "Cohort" },
  { field: "w1", label: "Week 1", format: { kind: "percent", heat: true } },
  { field: "p95Ms", label: "p95", format: "duration" },
  { field: "url", format: "url" },
  { field: "lastSeenAt", label: "Last seen", format: "relative" },
]
```

`relative` renders a `<time>` with the exact timestamp in its tooltip, and `url`
opens absolute URLs in a new tab without opening the row.

#### Formatting values yourself

The formatters behind every cell, card and export. Each takes the admin's
resolved `formatting`.

`formatColumnValue` renders a `ColumnFormat`; `formatNumber` renders a widget's
`NumericFormat` (`number`, `currency`, `percent`, `bytes`, `duration`). Import both
from `@flowpanel/kit`; `@flowpanel/kit/react` also exports `formatNumber`.
`formatDurationValue`, `formatPercentValue` and `formatRelativeValue` print one
kind each.

### Enums

`enumOf()` declares an enum's labels and tones once, for a column's `format`,
filter and field `options`, badges and timeline chips.

```ts
import { enumOf, resource } from "@flowpanel/kit";
import { customers, planTier } from "@/db/schema";

export const Plan = enumOf(planTier.enumValues, {
  free: ["Free", "muted"],
  starter: ["Starter", "info"],
  pro: { label: "Pro", tone: "accent" },
  business: { label: "Business", tone: "accent" },
});

resource(customers, {
  columns: [{ field: "plan", format: Plan.format }],
  filters: [{ field: "plan", type: "select", options: Plan.options }],
  detail: { badge: (customer) => Plan.badge(customer.plan) },
});
```

With the database enum's values first, a missing or extra label is a compile
error; otherwise the entry keys are the values. An entry is a label, a
`[label, tone]` pair or `{ label, tone }`. `label()` prints an unknown value as
itself and a missing one as `—`; `badge()` returns `null` for a missing value;
`badge(value, { href })` makes the pill a link.

`EnumDef`

| Property | Type | Notes |
| --- | --- | --- |
| `values` | `readonly K[]` | Every value, in declaration order. |
| `labels` | `Readonly<Record<K, string>>` |  |
| `tones` | `Readonly<Record<K, Tone>>` |  |
| `format` | `{ kind: "badge"; labels: Readonly<Record<K, string>>; tones: Readonly<Record<K, Tone>>; }` | A badge column format with these labels and tones. Plain data: safe anywhere. |
| `options` | `SelectOption[]` | `{ label, value }` in declaration order, for a filter, a form field or a dashboard filter. |
| `label` | `(value: unknown) => string` | The label; an unknown value prints as itself, a missing one as `"—"`. |
| `tone` | `(value: unknown) => Tone` | The tone; `"default"` for an unknown value. |
| `badge` | `(value: unknown, options?: { href?: LinkTarget }) => { label: string; tone: Tone; href?: LinkTarget } \| null` | A header badge, or `null` for a nullish value; `href` links it, e.g. to the filtered list. |

### FieldDef

An entry in `create.fields`, `update.fields`, a `DetailTab`, or an action's
`form`. `required` marks the control required and the server rejects a missing
value. `readOnly` and the resource's `fieldAccess` apply to rendering and to writes; a function
`readOnly` is called with the stored row, so it guards edits. `hidden` only removes
the control. `defaultValue` fills a key a create leaves empty and pre-fills a visible
control; the resource's `create.defaultValues` fills keys on the server only and wins
when both name the same key.

`FieldDef`

| Property | Type | Notes |
| --- | --- | --- |
| `name` | `keyof Row & string` | Row property this field writes. |
| `label?` | `string` | Field label. Defaults to a humanized `name`. |
| `help?` | `string` | Hint rendered under the control. |
| `placeholder?` | `string` | Placeholder text for empty inputs. |
| `type?` | `FieldType` | Which control to render. Omitted, a declared field renders as `"text"` — or `"reference"` when `reference` is set. The adapter's column type is consulted only by a fully generated form, and only maps number, boolean, date and json. |
| `options?` | `\| ReadonlyArray<string> \| SelectOption[] \| ((ctx: QueryContext) => Promise<SelectOption[]>)` | Choices for `select` / `multiselect` / `radio`. A function resolves per request. |
| `reference?` | `ReferenceSpec` | Turn the field into a searchable picker over another resource. |
| `required?` | `boolean` | Require a value. The form marks it, and the server rejects a create that leaves it empty or an edit that clears it. |
| `readOnly?` | `boolean \| ((values: Partial<Row>) => boolean)` | Render non-editable. Enforced server-side, not just in the UI. |
| `hidden?` | `boolean \| ((values: Partial<Row>) => boolean)` | Leave the field out of the form entirely. |
| `validate?` | `\| z.ZodTypeAny \| ((value: unknown, values: Partial<Row>) => string \| null \| Promise<string \| null>)` | Per-field validation, run server-side after the resource schema. |
| `defaultValue?` | `unknown \| ((ctx: QueryContext) => Promise<unknown>)` | Value used when creating, for keys the operator left empty; a visible field also pre-fills with it. The resource's `create.defaultValues` wins for the same key. |
| `span?` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | Width in a 12-column form grid. Defaults to full width. |
| `group?` | `string` | Fieldset heading this field is grouped under. |
| `render?` | `(row: Row, ctx: RequestContext) => ReactNode \| Promise<ReactNode>` | Detail pages and drawers only: what the field shows instead of its value — a join or a computed label. |

#### FieldType

```ts
type FieldType =
  | "text" | "textarea" | "number" | "email" | "password" | "url"
  | "date" | "datetime" | "time"
  | "boolean" | "switch" | "checkbox"
  | "select" | "multiselect" | "radio"
  | "json" | "markdown" | "tags" | "reference" | "hidden" | "color";
```

Without `type`, a field is `"text"`, or `"reference"` when it sets `reference`.
Only a fully generated form (no `create.fields` or `update.fields`) reads the
column type, and only for numbers, booleans, dates and JSON.

### FilterDef

An entry in `filters`. A bare string is a `text` filter; set `type` for anything
else. A `select` or `multiselect` filter without `options` on a column formatted
with badge `labels`, such as an `enumOf` format, lists those labels.

`FilterDef`

| Property | Type | Notes |
| --- | --- | --- |
| `field` | `keyof Row & string` | Row property this filter narrows. |
| `label?` | `string` | Control label. Defaults to a humanized `field`. |
| `type` | `FilterType` | Which control to render, and how the value is encoded in the URL. |
| `options?` | `\| ReadonlyArray<string> \| SelectOption[] \| ((ctx: QueryContext) => Promise<SelectOption[]>)` | Choices for `select` / `multiselect`. A function is resolved per request. |
| `defaultValue?` | `unknown` | Applied while the URL names no value for the filter: the list, its count, pages, export and API all read it. Clearing the control writes an empty `f_<field>=` so the default stays off; a view or link turns it off with `null`. |
| `hidden?` | `boolean` | Apply the filter, and its `defaultValue`, without showing a control for it. |

#### Default and hidden filters

`defaultValue` applies while the URL has no value for the filter, to the rows,
totals and export alike. Clearing it writes an empty `f_<field>=` to the URL. A
saved view or link turns it off with `null`. `hidden: true` applies the filter
without a control.

```ts
filters: [
  { field: "isTest", label: "Test accounts", type: "boolean", defaultValue: false },
],
views: [{ name: "Everyone", filters: { isTest: null } }],
```

A filter compares one column. To filter by an expression or through a relation,
read the resource from a view that computes the column and set
[`writeTo`](#reading-a-view).

#### FilterType

```ts
type FilterType =
  | "text" | "select" | "multiselect"
  | "daterange" | "numeric-range" | "boolean" | "tag";
```

`daterange` and `numeric-range` reach your adapter as a `FilterRangeValue`;
`multiselect` as a `FilterInValue`. Both are documented under
[Contexts](/docs/reference/contexts#filter-values).

### Record page

`detail` configures `<paths.admin>/<resource>/<id>`. Type a card that lives in its own file
with `DetailOptions<Row>`:

```ts
import { type DetailOptions, kv, metric, related, type RowOf } from "@flowpanel/kit";

export const card = {
  title: (u) => u.name ?? u.email,
  subtitle: (u, { format }) => `with us since ${format.date(u.createdAt)}`,
  badge: (u) => [Lifecycle.badge(u.lifecycle), Plan.badge(u.plan)],
  dateRange: { preset: "last30d", presets: ["last7d", "last30d", "QTD"] },
  stats: [metric("Visits", { count: "user_visit", range: "startedAt" }, { compare: true })],
  aside: [kv({ label: "Profile", columns: 1, items: [{ label: "Email", field: "email" }] })],
  tabs: [related("response")],
} satisfies DetailOptions<RowOf<"user">>;
```

- `title`, `subtitle` and `badge` receive the row and a `DetailHeaderContext`: the
  admin's `format`, `labels` and `link`. `badge` returns one pill or a list, in order;
  `null` entries are dropped, and a pill with `href` is a link.
- `stats` renders as a hairline strip under the header, on every tab.
- `aside` is a column beside the tabs from the `lg` breakpoint and below them on a phone,
  on every tab.
- `dateRange` adds a date picker to the header. Its range, with `previous`, reaches
  `stats`, `aside` and every widgets tab. Related rows list every row, a
  [timeline](/docs/reference/widgets#timeline) pages through the whole history and a
  heatmap shows its last `days` days. Without `dateRange` the page has no picker and
  widgets see the record's whole history.

The header, strip, aside and open tab share one widget context, so a repeated
`ctx.count`, `ctx.read` or `ctx.query` runs once per page.

`DetailOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `expose?` | `(keyof Row & string)[]` | Extra fields used only by detail headers, hidden-tab predicates, related filters, or custom detail renderers. They never widen list rows. |

### DetailTab

A tab on the record page. The open tab is the `?tab=<key>` query parameter, and
only that tab runs on the server.

A tab shows `render` when it has one. Otherwise it shows its `widgets` and its
`resource` list, widgets above the rows, or its fields when it has neither.

#### Fields and sections

`fields` renders key/value pairs; `"*"` shows every readable field. An entry is a
field name or a `FieldDef`. Column `format` and `render` apply here too.

A `FieldDef` with `render(row, ctx)` shows its result instead of the value. It
runs on the server, only when the reader may read `name`, concurrently with the
tab's other renders. A render that throws is logged and the field shows its
formatted value; see [server-rendered cells](/docs/reference/drawer#server-rendered-cells)
for the drawer:

```ts
{
  name: "categoryId",
  label: "Category",
  render: async (job, ctx) => {
    const category = await findCategory(ctx, job.categoryId);
    return `${category.title} (${category.openJobs})`;
  },
}
```

`sections` groups those fields into titled blocks and wins over `fields` on the
same tab:

```ts
{
  key: "overview",
  label: "Overview",
  sections: [
    { label: "Identity", fields: ["email", "name"] },
    { label: "Billing", fields: [{ name: "mrr", label: "MRR" }, "plan"] },
  ],
}
```

Fields named here are loaded when the tab is open. A field the reader may not
read is left out.

#### Widgets

`widgets` puts dashboard widgets in the tab; see
[widget tabs](/docs/build/detail-cards#widget-tabs). `columns` defaults to 2, or 12
once a widget sets `span`. `ctx.row` is the record. A failing widget shows its own
error card.

#### Related rows

A tab with `resource` shows that resource's list columns, paged under the URL key
`relatedPage.<key>` and sorted under `relatedSort.<key>`. `hide` drops columns and
their values; the parent foreign key is the usual one. `sort` sets the default
order. An "Open list" link to the filtered list appears when every filter value is
a scalar on a field the target declares.

`filter` is a constraint: an undefined parent value yields no rows and no query.
A row opens by the target's [`rowClick`](#opening-a-row); a drawer opens over the
record page under `?drawer=<resource>:<id>`.

`pageSize` defaults to 25. `count: true` shows the row count in the label.
`widgets` on the same tab render above the rows.

`by` names the target's field that points at this record: it becomes `filter`, reading the
record's `rowKey`, and `hide`, unless you give those yourself.

#### Related tabs in one line

`related(resource, options)` builds a counted related tab. Without `by`, `defineAdmin` finds
the one column of the target whose `reference.resource` is this resource and uses it; none
or several throw and ask for `by`. `by`, `hide` and `sort.field` are fields of the target's
row, so a typo is a compile error once resources are typed, and `defineAdmin` names the
closest column otherwise. The label defaults to the target's `plural`.

```ts
detail: {
  tabs: [
    related("response", { label: "Responses", widgets: [responseFunnel] }),
    related("payment", { pageSize: 10, sort: { field: "createdAt", dir: "desc" } }),
  ],
}
```

A tab with neither `by` nor `filter` reads every row of its target.

`RelatedOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `key?` | `string` | The tab's URL key. Default: `the resource name`. |
| `label?` | `string` | Tab label. Default: `the target's `plural`, else its `label`, else its humanised name`. |
| `by?` | `Field<N>` | The target's field that points at the record. Omitted: inferred from its `reference`. |
| `count?` | `boolean` | Show the row count in the label. Default: `true`. |
| `pageSize?` | `number` | Rows per page. Default: `25`. |
| `sort?` | `{ field: Field<N>; dir: "asc" \| "desc" }` | Default order of the rows. |
| `hide?` | `Field<N>[]` | Columns to leave out. Default: ``[by]``. |
| `widgets?` | `WidgetConfig[]` | Widgets above the rows, with `ctx.row` set to the record being viewed. |
| `columns?` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | Grid columns for `widgets`. |
| `emptyState?` | `string` | Shown instead of the generic label when there are no rows. |
| `hidden?` | `(row: Record<string, unknown>) => boolean` | Hide the tab for records that should not show it. |

#### Empty state

`emptyState` replaces the default text when a tab has no rows, widgets or
readable fields.

```ts
{ key: "responses", label: "Responses", resource: "response", filter: (u) => ({ userId: u.id }), emptyState: "No responses yet" }
```

#### Custom content

`render(row, ctx)` returns any React content. `row` holds the declared and
`detail.expose` fields; `ctx` is a [`DetailTabContext`](#detailtabcontext).

`DetailTab`

| Property | Type | Notes |
| --- | --- | --- |
| `key` | `string` | Stable identifier, stored in the URL's `?tab=` search parameter. |
| `label` | `string` | Tab label. |
| `hidden?` | `(row: Row) => boolean` | Hide the tab for rows that should not show it. |
| `fields?` | `(keyof Row \| FieldDef<Row>)[] \| "*"` | Field list to render as a key/value view. `"*"` shows every column. |
| `sections?` | `Array<{ label: string; fields: (keyof Row \| FieldDef<Row>)[] }>` | Grouped key/value fields, one block per entry. Wins over `fields`. |
| `resource?` | `ResourceName` | Render rows of a related resource instead of fields. |
| `filter?` | `(row: Row) => Record<string, unknown>` | Filter applied to `resource`, derived from the row being viewed. |
| `by?` | `string` | The target's field that points at this record; becomes `filter` and `hide` unless those are given. A `related()` tab infers it from the one target column whose `reference.resource` is this resource. |
| `count?` | `boolean` | Show the row count in the tab's label — `"Responses · 12"`. Default: `false; true through `related()``. |
| `pageSize?` | `number` | Related rows per page. Default: `25`. |
| `hide?` | `string[]` | Related-tab columns to omit, typically the parent foreign key. |
| `sort?` | `{ field: string; dir: "asc" \| "desc" }` | Related-tab default sort; falls back to the target's `defaultSort`, then its primary key. |
| `widgets?` | `WidgetConfig[]` | Dashboard widgets with `ctx.row` set to the record being viewed; with `resource`, above its rows. |
| `columns?` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | Grid columns for `widgets`; omitted, 12 when a widget sets `span`. Default: `2`. |
| `render?` | `(row: Row, ctx: DetailTabContext) => ReactNode` | Render arbitrary content instead of fields, widgets or a related resource. |
| `emptyState?` | `string` | Shown instead of the generic label when the tab has nothing to show: no related rows, no widgets, or no fields the reader may see. |
