# FlowPanel — Reference — Widgets (part 2)

### checklist

Items done or not. An item is done when `done` holds a value other than `null`,
`undefined`, `false`, a blank string or an empty list. The summary counts
non-`optional` items.

With `ordered`, done items show their date and the gap since the previous step.
`layout: "steps"` lays them out in a row. Not available in drawers.

```ts
checklist({
  label: "Journey",
  ordered: true,
  layout: "steps",
  items: async (c) => {
    const user = c.rowOf("user");
    return [
      { label: "Signed up", done: user.createdAt },
      { label: "Linked Telegram", done: user.telegramLinkedAt, optional: true },
      { label: "First reply sent", done: user.firstSentAt },
    ];
  },
});
```

`labels.checklist` words the summary, the gap and the marks' names for screen readers.

`ChecklistOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `label?` | `string` | Card heading. |
| `items` | `ChecklistItem[] \| ((ctx: WidgetContext) => Promise<ChecklistItem[]>)` | The items, or a function that reads them per request. |
| `ordered?` | `boolean` | Each done step shows when, and the time since the previous done step. |
| `layout?` | `"list" \| "steps"` | `"steps"` lays the items out in a row from the `md` breakpoint. Default: `"list"`. |
| `summary?` | `boolean` | "7 of 12" with a bar; optional items are not counted. Default: `true`. |
| `emptyState?` | `ReactNode` | Shown instead of the items when there are none. Text or any node. |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |
| `realtime?` | `RealtimeOption` | Re-run when any of these channels fire. |

#### ChecklistItem

`ChecklistItem`

| Property | Type | Notes |
| --- | --- | --- |
| `label` | `string` |  |
| `done` | `unknown` | Done unless `null`, `undefined`, `false`, a blank string or an empty list; `0` counts. A `Date` or an ISO string also says when, shown by an `ordered` checklist. |
| `hint?` | `string` | A muted note under the label. |
| `optional?` | `boolean` | Not counted in the summary; muted while not done. |
| `tone?` | `Tone` | The mark's color when done. Default: `"ok"`. |
| `href?` | `LinkTarget` | Links the label — a path or a named target. |
| `precision?` | `"day"` | The date has no clock: print the day, and measure no gap to or from it. A bare `YYYY-MM-DD` needs no flag. |

#### filled

One checklist item per labelled field, done when the field has a value.

```ts
checklist({
  label: "Profile",
  items: async (c) => filled(await profileOf(c), { bio: "About", hourlyRate: "Rate" }),
});
```

### custom

Your own component in the grid. `props` is a value or a server function. See
[Build a custom widget](/docs/customization/custom-widgets).

`CustomOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |
| `frame?` | `boolean` | Wrap the component in the standard widget card. Default: `true`. |
| `label?` | `string` | The card's title when framed, and the name errors and slow-widget timings use. |

### Charts

The chart builders come from `@flowpanel/kit`. Recharts loads only when a chart is on the page.

```ts
import { areaChart, barChart, lineChart, pieChart } from "@flowpanel/kit";
```

Each takes `(label, query, options)`. `x` and `y` (`category` and `value` on a pie)
are checked against the query's row type.

#### ChartOptionsBase

Shared by area, bar and line charts.

`ChartOptionsBase`

| Property | Type | Notes |
| --- | --- | --- |
| `x` | `RowKey<R>` | Row key plotted on the x-axis. |
| `y?` | `RowKey<R> \| RowKey<R>[]` | Row key(s) plotted on the y-axis; an array draws one series per key. Default: every key of the first row except `x`, in its order — the columns a `series({ by })` returns. |
| `labels?` | `KeyLabels` | Legend and tooltip name per series key: a map, an `enumOf()` or a function. Default: the key. |
| `colors?` | `Readonly<Record<string, string>>` | A CSS colour per series key, e.g. `{ paid: "hsl(var(--fp-chart-1))" }`. Default: `--fp-data` for a single series, `--fp-chart-1…7` in `y` order for several. |
| `height?` | `number` | Chart height in px. Default: `240`. |
| `format?` | `NumericFormat` | How y-values are rendered in ticks and tooltips. |
| `minorUnits?` | `number` | The y-values are minor units with this many digits, as on a `money` field: with `format: "currency"`, `2` shows `260000` as $2,600. |
| `tooltip?` | `"default" \| "compact" \| false` | `false` omits the `<Tooltip>` entirely. |
| `drilldown?` | `Link` | Turns the whole card into a link — a path, a named target, or one computed from the context. |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |
| `bucket?` | `ChartBucket` | How x-axis ticks print a date key. It does not aggregate: fold rows with `series({ grain })`. |

`ChartBucket` is `"minute" | "hour" | "day" | "week" | "month" | "year" | "auto"`.

Without `y`, the chart plots every numeric key of its first row except `x`, which
is what `series({ by })` returns. `labels` names the series. `bucket` only formats
date ticks; aggregate with `series({ grain })`. For amounts stored in cents, set
`format: "currency"` and `minorUnits: 2`, and the axis and tooltips show money.

One series draws in `--fp-data`; several use `--fp-chart-1` to `--fp-chart-7` in `y`
order. `colors` pins a series to a colour:

```ts
lineChart("Signups", signupsByPlan, {
  x: "day",
  y: ["trial", "paid"],
  colors: { paid: "hsl(var(--fp-chart-1))", trial: "hsl(var(--fp-chart-2))" },
});
```

### Series helpers

Pure helpers that turn query rows into chart and bar data in the admin's zone.

One point per bucket across the range: hours, days, ISO weeks starting on Monday, or
months, bucketed in `range.timeZone`. Pass `ctx.dateRange` and the admin's zone
applies. Keys are `YYYY-MM-DD`, or `YYYY-MM-DDTHH:00` for hours, which chart ticks
already read. `grain: "auto"` picks hours up to 2 days, days up to 92, weeks up to
400 and months beyond.

- **Gaps.** Every bucket is present. A bucket with no rows is `0` for a count or a
  sum, and whatever the `value` function returns for `[]`: return `null` for a ratio
  with no data.
- **Pivots.** Without `by` the one column is `value`, so a sparkline is
  `series(…).map((p) => p.value)`. With `by`, each value of that field is a column;
  `keys` fixes columns that must appear, in order. `top` keeps `keys` and the largest
  other series and folds the rest into `OTHER_KEY`, which charts name
  `labels.widget.other`.
- **Values.** `"12"` strings, bigints and booleans read as numbers. A `YYYY-MM-DD`
  value is that calendar day, and a zoneless timestamp such as `2026-09-21 09:00:00`
  is UTC, as everywhere else in FlowPanel.
- **Whole history.** A range starting at the epoch, such as a record page's
  `ctx.dateRange` without `detail.dateRange`, starts at the first row's bucket; with no
  rows there are no buckets.
- **DST.** On the day clocks skip an hour, that hour has no bucket. On the day they
  repeat one, both of its hours share one bucket.

Folding runs in JavaScript. Above about 50,000 rows, group by hour in SQL first.

`SeriesOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `at` | `keyof R & string` | The timestamp or `YYYY-MM-DD` field that places a row in a bucket. |
| `value?` | `Fold<R>` | How a bucket's rows become its number. Default: the row count. |
| `by?` | `keyof R & string` | One column per value of this field; without it the one column is `value`. |
| `keys?` | `readonly string[]` | Values of `by` present as columns, in this order, even with no rows. |
| `grain?` | `Grain` | `"auto"`: hours up to 2 days, days up to 92, weeks up to 400, else months. Weeks start Monday. Default: `"auto"`. |
| `top?` | `number` | Keep `keys` and the N largest other series; the rest fold into `OTHER_KEY`. |

One ranked `BarRow` per value of `by`, with `key` and `share`, and each row's
`previous` when you pass the earlier period's rows as `previous`. `top` folds
the rest into one `OTHER_KEY` row, so the shares still add up to 1. `labels` takes a
map, an `enumOf()` or a function. Shares only mean something for counts and sums.

`BreakdownOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `by` | `keyof R & string` | One row per value of this field. |
| `value?` | `Fold<R>` | How a value's rows become its number. Default: the row count. |
| `keys?` | `readonly string[]` | Values always present, at zero when no row has them. |
| `labels?` | `KeyLabels` | Row labels: a map, an `enumOf()`, or a function. Default: the value itself. |
| `top?` | `number` | Keep `keys` and the N largest other rows; the rest fold into one `OTHER_KEY` row. |
| `previous?` | `readonly R[]` | The compared period's rows, folded the same way into each row's `previous`. |
| `href?` | `(key: string) => LinkTarget \| null` | Where a row's label leads. |

A preset's bounds now, in the admin's zone, for a query that needs a fixed window
beside the picked one. Pass the same `now` to widgets sharing a query.

```ts
import { barChart, bars, breakdown, series, type WidgetContext } from "@flowpanel/kit";

const hourly = (c: WidgetContext) => c.sql<{ at: Date; platform: string; orders: number }>`
  select hour as at, platform, orders_new as orders
  from scraper_hourly_stats where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}`;

bars({
  label: "New orders by marketplace",
  share: true,
  query: async (c) => breakdown(await c.query(hourly), { by: "platform", value: "orders", labels: Platform }),
});
barChart(
  "New orders by day",
  async (c) => series(await c.query(hourly), c.dateRange, { at: "at", by: "platform", value: "orders", grain: "day" }),
  { x: "date", labels: Platform, stacked: true },
);
```

The range of the same length ending where the given one begins, in elapsed time.
`ctx.dateRange.previous` is usually what you want.

Equals `series(rows, dateRange, { at: dateField, value: valueField, grain: "day" })`.

### Dashboards

Both return their argument, typed.

`DashboardConfig`

| Property | Type | Notes |
| --- | --- | --- |
| `path` | `string` | Path under `paths.admin`. `"/"` makes this the admin's landing page. |
| `label` | `string` | Nav entry and page title. |
| `icon?` | `IconName` | Serializable Lucide icon rendered in navigation and the command palette. |
| `navGroup?` | `NavGroupRef` | Sidebar group for this entry. Default: the kind's own group — Dashboards or Pages. |
| `dateRange?` | `DateRangeConfig` | Adds a date picker whose value reaches every widget query. |
| `filters?` | `DashboardFilter[]` | Selects beside the date picker; the values reach every widget as `ctx.filters`. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |
| `refresh?` | ``${number}s` \| `${number}m`` | Re-renders the whole dashboard on an interval, e.g. `"60s"` or `"5m"`; paused while the tab is hidden. |
| `sections` | `SectionConfig[]` | Widget bands, rendered top to bottom. |
| `actions?` | `DashboardAction<any, any>[]` | Optional top-bar action buttons rendered in the dashboard page header. |
| `hideActionsBar?` | `boolean` | Hide the default `DashboardActionsBar`. |
| `access?` | `AccessRule` | Who may see and open this dashboard and run its actions. |

`refresh` (`"<n>s"` or `"<n>m"`) re-renders the dashboard on that interval while the
tab is visible and shows the data's age by the date picker.

#### SectionConfig

`SectionConfig`

| Property | Type | Notes |
| --- | --- | --- |
| `label?` | `string` | Section heading. Omit for an untitled band. |
| `description?` | `string` | Supporting copy under the heading. |
| `columns?` | `1 \| 2 \| 3 \| 4 \| 6 \| 12` | Grid columns the widgets lay out across; omitted, 12 when a widget sets `span`. Default: `1`. |
| `variant?` | `"cards" \| "strip"` | `"strip"` draws the section's `metric`/`stat` widgets as one band with no card; another kind warns in development. Default: `"cards"`. |
| `align?` | `"stretch" \| "start"` | How cards in one row size: `"stretch"` to the tallest, `"start"` each to its content. Default: a `table` or `list` keeps its own height, every other card stretches. |
| `widgets` | `WidgetConfig[]` |  |

`variant: "strip"` draws `metric` and `stat` widgets as one band without cards.
`columns` sets cells per line (up to six by default; two on a phone). A record
page's [`detail.stats`](/docs/reference/resources#record-page) is the same strip.

In a `"cards"` section, `table` and `list` cards keep their height and others
stretch to the row; `align: "start"` or `"stretch"` sets it for all.

```ts
{ variant: "strip", widgets: [newOrders, runs, successRate, bans] }
```

#### DateRangeConfig

`DateRangeConfig`

| Property | Type | Notes |
| --- | --- | --- |
| `preset?` | `DateRangePreset` | Range selected on first load; one outside `presets` is dropped with a development warning. |
| `default?` | `{ from: Date; to: Date }` | Explicit range used when no preset is given. |
| `presets?` | `DateRangePreset[]` | Presets the picker offers, in order. A URL preset outside the list is ignored, and without `preset` or `default` the first entry is selected. Default: all seven. |

`DateRangePreset` is `"today" | "yesterday" | "last7d" | "last30d" | "last12m" | "MTD" | "QTD" | "YTD"`.

`today`, `yesterday`, `MTD`, `QTD` and `YTD` start at midnight in `formatting.timeZone`
(UTC when it is not set); `last7d` and `last30d` are the last 7 × 24 and 30 × 24 hours.
`last12m` starts on the 1st of the month eleven months back, so a monthly chart gets
twelve buckets, the current month included; it compares with the same range a year back.

`presets` limits the picker's choices; `preset` defaults to the first.

#### DashboardFilter

`DashboardFilter`

| Property | Type | Notes |
| --- | --- | --- |
| `key` | `string` | The URL key `f_<key>`, as a list's filters use, and the key in `ctx.filters`. |
| `label` | `string` | The select's label. |
| `options` | `SelectOption[] \| EnumDef \| ((ctx: WidgetContext) => Promise<SelectOption[]>)` | The choices: a list, an `enumOf()`, or a function of the context. |

`filters` adds a select per entry beside the date picker, stored in the URL as
`f_<key>`. `options` takes `SelectOption[]`, an `enumOf()`, or a function of the
widget context; a plain string list is not accepted.

`filterOnClick: "<key>"` on `bars`, `tracker` or `table` sets that filter on click,
replacing the row's link. It is rejected on a record page or in a drawer.

```ts
const byPlatform: DashboardFilter = { key: "platform", label: "Marketplace", options: Platform };

const hourly = (c: WidgetContext) => c.sql<HourRow>`
  select hour as at, platform, runs_total as runs from scraper_hourly_stats
  where hour >= ${c.dateRange.from} and hour < ${c.dateRange.to}
    and (${c.filters.platform ?? null}::text is null or platform = ${c.filters.platform ?? null})`;

dashboard({
  path: "/parsing",
  label: "Parsing",
  filters: [byPlatform],
  sections: [{ columns: 12, widgets: [tracker({ query: hourly, at: "at", by: "platform", filterOnClick: "platform", span: 12 })] }],
});
```
