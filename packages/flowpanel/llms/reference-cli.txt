# FlowPanel — Reference — CLI

## CLI

Every flowpanel command: init, dev, new, migrate, doctor and eject.

Docs: https://flowpanel.tech/docs/reference/cli

`@flowpanel/cli` sets up, migrates, checks and extends an admin. Start with
`pnpm dlx @flowpanel/cli init`; it installs the CLI as a dev dependency, so later
commands run as `pnpm flowpanel <command>`. The CLI uses the package manager of
your lockfile.

`flowpanel [options] [command]` — Admin panels the fast way
- `-V, --version` output the version number

`flowpanel init [options]` — Initialize FlowPanel in this project
- `--yes` Accept detected defaults without prompting (CI mode)
- `--dry-run` Print the filesystem plan without writing or installing
- `--json` Emit machine-readable JSON (implies --yes)
- `--path <url>` Mount the admin at a static URL, for example /ops/admin
- `--db <module>` Local module exporting your db or prisma client
- `--schema <module>` Local module exporting your Drizzle schema
- `--auth <module>` Local module exporting getSession(request)
- `--dev-auth` Explicitly use an open development-only admin identity

`flowpanel migrate [options]` — Apply SQL migrations from flowpanel/migrations/
- `--dry-run` Print migrations that would be applied without running them
- `--json` Emit machine-readable JSON

`flowpanel doctor [options]` — Check FlowPanel health and wiring
- `--fix` Auto-fix missing route files from templates
- `--dry-run` Show fixes without writing (use with --fix)
- `--json` Emit machine-readable JSON
- `--path <url>` Resolved admin URL when the config uses a dynamic path

`flowpanel eject [options] <target> [name]` — Eject a FlowPanel piece into your app/admin folder. Targets: resource <name>, dashboard <path>, layout.
- `<target>`
- `[name]`
- `--force` Overwrite files if they already exist
- `--dry-run` Print the filesystem plan without writing
- `--json` Emit machine-readable JSON

`flowpanel dev [options]` — Run Next.js dev server (and bull-board if REDIS_URL is set)
- `--port <port>` Next.js dev port Default: `3000`.
- `--no-board` Skip the bull-board server even if REDIS_URL is set

`flowpanel new [options] <resource>` — Add a resource(...) entry to the admin config
- `<resource>`
- `--table <expr>` First argument expression (default: schema.<resource>)
- `--kind <kind>` Adapter kind: drizzle (default) or prisma Default: `drizzle`.
- `--dir <dir>` Write the resource to <dir>/<name>.ts and add it to <dir>/index.ts
- `--hidden` Register the resource without a navigation entry
- `--dry-run` Print the filesystem plan without writing
- `--json` Emit machine-readable JSON

Every command takes `--help`. Failures exit non-zero; `FLOWPANEL_DEBUG=1` adds the
stack trace. Commands that write build the whole plan first: `--dry-run` prints it,
`--json` returns it for CI, and a failure rolls back earlier writes. A file with
different content is a conflict, never overwritten.

### flowpanel init

`flowpanel init [options]` — Initialize FlowPanel in this project
- `--yes` Accept detected defaults without prompting (CI mode)
- `--dry-run` Print the filesystem plan without writing or installing
- `--json` Emit machine-readable JSON (implies --yes)
- `--path <url>` Mount the admin at a static URL, for example /ops/admin
- `--db <module>` Local module exporting your db or prisma client
- `--schema <module>` Local module exporting your Drizzle schema
- `--auth <module>` Local module exporting getSession(request)
- `--dev-auth` Explicitly use an open development-only admin identity

Detects Next.js, the ORM (Drizzle if both are installed) and the auth helper,
installs `@flowpanel/kit` and `@flowpanel/cli`, and writes the wiring files.

```text
◇  Detected stack ─────────────────────────────────────╮
│  Next.js 16.3.1 · TypeScript · Drizzle · Tailwind 4  │
├──────────────────────────────────────────────────────╯
◇  7 written
◇  Wrote ─────────────────────────────────────────────────╮
│  flowpanel.config.ts                                    │
│  app/admin/[[...slug]]/page.tsx                         │
│  app/api/flowpanel/[...route]/route.ts                  │
│  app/api/flowpanel/stream/route.ts                      │
│  styles/admin.css                                       │
│  flowpanel/migrations/0001_init.sql                     │
│  app/admin/layout.tsx (imports the admin stylesheet)    │
├─────────────────────────────────────────────────────────╯
◇  Installed @flowpanel/kit, @flowpanel/cli
```

What varies:

- **`src/`**: in a `src/` project, `app/` and `styles/` paths move under `src/`.
- **Admin mount**: `/admin`, or `/flowpanel` when `/admin` is taken, or
  `--path /ops/admin`. If the fallback is taken too, nothing is written.
- **Admin layout**: imports the stylesheet and renders `ThemeScript` with the
  `x-nonce` request header. Under a strict `script-src`, your middleware must set
  `x-nonce` and the matching CSP header; FlowPanel does not write that middleware.
  `init` adds `suppressHydrationWarning` to the root layout's `<html>` tag, or prints
  the edit when it cannot patch the file. Without a root layout, the admin gets its
  own.
- **Authentication**: for `better-auth`, `next-auth`, `@clerk/nextjs` or `lucia`,
  when the auth module exports the provider's instance rather than `getSession`,
  `init` writes `server/lib/flowpanel-session.ts` on the matching
  [preset](/docs/guides/authentication). Otherwise it writes a closed `getSession`
  adapter. `--dev-auth` writes an open development identity.
- **Install**: skipped for packages already in `package.json`.

#### When `init` stops

- **No Next.js, or neither Drizzle nor Prisma, in `package.json`**: exits `1` with
  the install command.
- **No terminal and no `--yes`, `--dry-run` or `--json`**: exits `1`. Pass `--yes`
  in CI.
- **A failed install**: keeps the files, prints the commands to run by hand, and
  exits `1`. So does an installed `@flowpanel/kit` or `@flowpanel/cli` from another
  minor version.

Re-running `init` skips matching files. A conflicting file stops it with nothing
written. `--yes` accepts detected paths; it never overwrites.

### flowpanel migrate

`flowpanel migrate [options]` — Apply SQL migrations from flowpanel/migrations/
- `--dry-run` Print migrations that would be applied without running them
- `--json` Emit machine-readable JSON

Applies the SQL files in `flowpanel/migrations/` through your config's adapter,
loading the config with `jiti`.

```bash
$ pnpm flowpanel migrate
```

`--dry-run` lists the files without loading the config or connecting, so it cannot
tell which are applied. `--json` returns the pending and applied lists. Applied IDs
live in `_flowpanel_migrations`.

Migrators are serialized at the database, and a concurrent duplicate is a no-op.
On PostgreSQL and SQLite each file and its marker share one transaction. MySQL
commits DDL implicitly: Drizzle holds an advisory lock and Prisma a claim row that
records where a failed run stopped. See [adapter migrations](/docs/reference/adapters#adapter).
Procedural scripts such as trigger bodies are rejected; run them with your ORM's
own migrations.

Every command reads `.env.local`, then `.env`; shell variables win.

### flowpanel doctor

`flowpanel doctor [options]` — Check FlowPanel health and wiring
- `--fix` Auto-fix missing route files from templates
- `--dry-run` Show fixes without writing (use with --fix)
- `--json` Emit machine-readable JSON
- `--path <url>` Resolved admin URL when the config uses a dynamic path

Runs these checks:

- Next.js ≥ 16.3 and < 17, and TypeScript installed
- an ORM the adapters support — Drizzle or Prisma
- `flowpanel.config.ts` exists
- the four generated files exist: the API route, the SSE route, the seed
  migration, and the catch-all admin page
- only one reachable `@flowpanel/core` installation across the installed
  dependency graph, including package-local peers and third-party plugins.
  Stale pnpm store entries are ignored; uninstalled projects skip this check
- no destructive row/bulk action declared without a `confirm`
- `tsc --noEmit` passes

Mount checks follow route groups, parallel slots and intercepting routes.

```bash
$ pnpm flowpanel doctor
$ pnpm flowpanel doctor --fix
$ pnpm flowpanel doctor --fix --dry-run
```

`--fix` recreates missing generated files from the `init` templates. Other failures
print a hint. A failed check exits non-zero, so it can run in CI.

### flowpanel eject

`flowpanel eject [options] <target> [name]` — Eject a FlowPanel piece into your app/admin folder. Targets: resource <name>, dashboard <path>, layout.
- `<target>`
- `[name]`
- `--force` Overwrite files if they already exist
- `--dry-run` Print the filesystem plan without writing
- `--json` Emit machine-readable JSON

Ejects a `resource`, `dashboard` or `layout` into your repo. See
[Eject to source](/docs/customization/eject).

```bash
$ pnpm flowpanel eject resource users
$ pnpm flowpanel eject dashboard "/monitoring"
$ pnpm flowpanel eject layout
```

It writes the files and comments out the config entry, as one transaction.
`--force` replaces existing files. It follows a re-exporting root config and a
`new --dir` resources directory.

### flowpanel dev

`flowpanel dev [options]` — Run Next.js dev server (and bull-board if REDIS_URL is set)
- `--port <port>` Next.js dev port Default: `3000`.
- `--no-board` Skip the bull-board server even if REDIS_URL is set

Runs `next dev`, plus the queue board when `scripts/board-server.mts` (or `.ts`)
exists and `REDIS_URL` is set.

```bash
$ pnpm flowpanel dev --port 3000
```

Output is prefixed `[next]` and `[board]`; when one exits, both stop.
`--no-board` skips the board.

### flowpanel new

`flowpanel new [options] <resource>` — Add a resource(...) entry to the admin config
- `<resource>`
- `--table <expr>` First argument expression (default: schema.<resource>)
- `--kind <kind>` Adapter kind: drizzle (default) or prisma Default: `drizzle`.
- `--dir <dir>` Write the resource to <dir>/<name>.ts and add it to <dir>/index.ts
- `--hidden` Register the resource without a navigation entry
- `--dry-run` Print the filesystem plan without writing
- `--json` Emit machine-readable JSON

Adds a resource to the config, or as its own file with `--dir`.

```bash
$ pnpm flowpanel new posts
```

```text
└  Added resource "posts" to flowpanel.config.ts
```

It adds `resource(schema.posts, { columns: ["id"] })` to the `resources` array and
the `resource` import if missing. It checks the schema has the table, by SQL name
or export name, and exits `1` if not, or if the resource exists. It follows a
root config that re-exports another module.

#### One file per resource

```bash
$ pnpm flowpanel new user_visit --dir admin/config/resources --hidden
```

`--dir` reads the Drizzle schema and writes `admin/config/resources/user-visit.ts`:

```ts excerpt
import { enumOf, resource } from "@flowpanel/kit";
import * as schema from "@/db/schema";

const Surface = enumOf(schema.activitySurface.enumValues, { web: "web", tma: "tma" });

export const userVisit = resource(schema.userVisit, {
  hidden: true,
  columns: [
    "id",
    { field: "userId", reference: { resource: "user", labelField: "name" } },
    { field: "surface", format: Surface.format },
    { field: "startedAt", format: { kind: "date", time: true } },
    "touches",
  ],
  filters: [{ field: "surface", type: "select" }],
  defaultSort: { field: "startedAt", dir: "desc" },
});
```

and adds it to `admin/config/resources/index.ts`. Columns are chosen by type; an
enum gets an `enumOf` stub; a foreign key becomes a `reference` labelled by the
target's `name`, `title` or `email` when the target already has a file, so scaffold
referenced tables first. JSON and long text are left out, `name`, `title` and
`email` become search fields, and the list sorts by `createdAt` or `startedAt`.
`--hidden` keeps the resource out of the navigation.

Re-running changes nothing; a different existing file stops it. `--dir` is
Drizzle only. Without `--dir`, a config whose `resources` is not an array literal
is left alone.

`--table <expr>` sets the table expression and skips the schema check.
`--kind prisma` writes `resource<unknown>("posts", …)`.
