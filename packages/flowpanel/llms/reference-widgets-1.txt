# FlowPanel — Reference — Widgets (part 1)

## Widgets

Every widget builder and the options it accepts.

Docs: https://flowpanel.tech/docs/reference/widgets

Documented types: WidgetContext, WidgetFormat, CaptionOptions, Freshness, Threshold, ResourceLink, DashboardLink, metric, MetricOptions, MetricResult, MetricDelta, table, TableWidgetOptions, WidgetColumn, statGroup, StatGroupOptions, StatItem, stat, StatOptions, StatResult, kv, KvOptions, KvItem, KvResult, bars, BarsOptions, BarRow, funnel, FunnelOptions, FunnelStep, list, ListOptions, banner, ListRow, tracker, TrackerOptions, TrackerRow, timeline, TimelineOptions, TimelineSource, TimelineEvent, TimelinePage, heatmap, HeatmapOptions, HeatmapSource, checklist, ChecklistOptions, ChecklistItem, filled, custom, CustomOptions, ChartOptionsBase, areaChart, AreaChartOptions, barChart, BarChartOptions, lineChart, LineChartOptions, pieChart, PieChartOptions, series, SeriesOptions, breakdown, BreakdownOptions, presetRange, previousRange, fillDays, dashboard, page, DashboardConfig, SectionConfig, DateRangeConfig, DashboardFilter, ResolvedDateRange, WidgetDateRange, PageConfig, PageProps

Widgets fill dashboard sections, record page tabs and drawer tabs. Each builder
returns a `WidgetConfig`; every `query` runs on the server with a `WidgetContext`.
On a record page or in a drawer, `ctx.row` is the record. A drawer renders
[static cards](/docs/reference/drawer#drawertabwidgets).

```ts
import { areaChart, dashboard, metric, statGroup, table } from "@flowpanel/kit";

export const overview = dashboard({
  path: "/",
  label: "Overview",
  dateRange: { preset: "last30d" },
  sections: [
    {
      label: "Revenue",
      widgets: [
        metric("MRR", async ({ db, dateRange }) => mrr(db, dateRange), {
          format: "currency",
          span: 3,
          drilldown: { resource: "invoices" },
        }),
        areaChart("Revenue over time", async ({ db }) => revenueSeries(db), {
          x: "day",
          y: ["subscriptions", "one-off"],
          stacked: true,
          span: 9,
        }),
      ],
    },
  ],
});
```

### WidgetContext

What every widget `query` receives.

`WidgetContext`

| Property | Type | Notes |
| --- | --- | --- |
| `db` | `DB` | Your database client, exactly as handed to the adapter. |
| `session` | `Session \| null` |  |
| `role` | `string` | The signed-in role, as `auth.role` returns it. |
| `dateRange` | `WidgetDateRange` | The picked range, the period before it and the admin's zone, resolved to dates. |
| `filters` | `Readonly<Record<string, string>>` | The dashboard's active filters by key; `{}` on a record page or with none set. Bind them as parameters. |
| `req` | `Request` |  |
| `row?` | `Record<string, unknown>` | Row of the record being viewed when the widget sits in a detail tab. |
| `id?` | `string` | The viewed record's key as a string — `row[rowKey]`. Absent on a dashboard, or when the key is not a string or number. |
| `link` | `(target: LinkTarget) => string` | Resolve a link target to an href, for the props of a custom widget. |
| `query` | `{ <T>(key: string, fn: () => Promise<T>): Promise<T>; <A extends unknown[], T>(fn: (...args: A) => Promise<T>, ...args: A): Promise<T>; <T>(fn: (ctx: WidgetContext<DB>) => Promise<T>): Promise<T>; }` | Memoises a query per request: a key and a thunk, or a function and its arguments. A function passed alone that declares a parameter is called with this context: `query(hourly)` runs `hourly(ctx)`. |
| `labels` | `ResolvedLabels` | The admin's resolved chrome strings, so a widget never hard-codes English. |
| `format` | `WidgetFormat` | The admin's formatters — locale, zone and currency from `formatting`. |
| `sql` | `<Row = Record<string, unknown>>( strings: TemplateStringsArray, ...values: unknown[] ) => Promise<Row[]>` | One read-only statement, as a tagged template; every interpolated value binds as a parameter, never as text. Runs exactly the statement you write — no tenant scope, access rule or soft-delete filter applied; `count`/reads do. |
| `count` | `<N extends ResourceName>( resource: N, where?: Where<RowOf<N>>, options?: CountOptions<RowOf<N>>, ) => Promise<number>` | How many rows of a registered resource match `where`, under the same role, access and scope checks as its list. Memoised per request by resource, `where` and range; a resource the session may not read counts `0`. |
| `read` | `<N extends ResourceName>( resource: N, options?: ReadOptions<RowOf<N>>, ) => Promise<RowOf<N>[]>` | Rows of a registered resource under the same role, access, scope, field and soft-delete rules as its list. Memoised per request by resource and options; a resource the session may not read returns `[]`. |
| `rowOf` | `<N extends ResourceName>(resource: N) => RowOf<N>` | The record this card shows, typed by its resource. Throws on a dashboard, which has no record, and on another resource's card; the message names both. |

`link` turns a named target into an href under `paths.admin`:
`link({ resource: "orders" })` is the list, `{ resource: "orders", id }` one record,
and `{ filter: { status: "paid" } }` adds `?f_status=paid`. Where an option takes a
link, pass the target itself.

`query` memoises for the request, so widgets that ask the same question run it
once. Pass a key and a thunk, `query("mrr", () => mrr(db))`, or a function and its
arguments, `query(mrr, db, ctx.dateRange)`; arguments key by value (objects by
identity). A failure is shared too. Use a function declared once: an inline one is
new on every call and never shares. A function passed alone that declares a
parameter receives the context, so `query(hourly)` runs `hourly(ctx)` once; a
function whose parameters are all defaulted is called with none. The `compare`
period runs it again with its own range.

`count` is memoised the same way: one resource and `where`, written in any key
order, count once per request. `id` is the viewed record's key as a string, read
through the resource's `rowKey`; a dashboard widget has none.

`dateRange` is the picked range with `previous` and `timeZone`. For `today`,
`yesterday`, `MTD`, `QTD` and `YTD`, `previous` is the same stretch one period back
at the same clock time; for `last7d`, `last30d` and a custom range it is the span
of the same length before. Over a record's whole history it is `null`.

`filters` holds the dashboard's active filters by key, `{ platform: "kwork" }` for
`?f_platform=kwork`, and is `{}` when none is set. Bind it in your own query.

`labels` is the resolved `LabelsConfig`. `row` is set on a record page.

```ts
metric("Paid orders", async (ctx) => ({
  value: await ctx.query("paid-orders", () => countPaid(ctx.db, ctx.dateRange)),
  href: { resource: "orders", filter: { status: "paid" } },
}));
```

#### WidgetFormat

`WidgetFormat`

| Property | Type | Notes |
| --- | --- | --- |
| `date` | `(value: MomentInput) => string` | The calendar day in the admin's zone; a `YYYY-MM-DD` string is that day. |
| `dateTime` | `(value: MomentInput) => string` | Day and clock, as a table cell shows a timestamp. |
| `relative` | `(value: MomentInput, now?: Date) => string` | How long ago — `5 minutes ago`, `yesterday`. `now` defaults to the current time. |
| `number` | `(value: NumberInput, digits?: number) => string` | A number with the locale's grouping and at most `digits` decimals. |
| `money` | `(value: NumberInput, options?: { currency?: string; digits?: number; minorUnits?: number }) => string` | An amount, in minor units when `minorUnits` is set, in `currency` (default `formatting.currency`). `digits` defaults to 0 for a whole amount, else to `minorUnits` or the currency's own: `1999` with `minorUnits: 2` and `19.99` are both `€19.99`. |
| `percent` | `(value: NumberInput, digits?: number) => string` | A fraction as a percentage — `0.42` is `42%`. |
| `duration` | `(ms: NumberInput) => string` | Milliseconds as the largest units that fit — `2 hr 5 min`. |
| `plural` | `(count: number, label: string \| PluralLabel) => string` | A count in the plural form the locale picks; `{n}` is the formatted count. |

`ctx.format` formats with the admin's `locale`, `timeZone` and `currency`, the same
way table cells do. Outside a widget, such as in a `page()` component,
`bindFormat(formatting)` from `@flowpanel/kit` returns the same formatters for a
`ResolvedFormatting`.

```ts
stat("Latency", async (ctx) => {
  const s = await ctx.query(latencyStages, ctx.db, ctx.dateRange);
  return {
    value: ctx.format.duration(s.p50Ms),
    hint: `p95 ${ctx.format.duration(s.p95Ms)} · ${ctx.format.plural(s.n, { one: "{n} order", other: "{n} orders" })}`,
  };
});
```

### Shared option types

`Span` is a whole number from `1` to `12`. A section without `columns` uses 12
columns once a widget sets `span`. On a phone every widget takes the full row.

`NumericFormat` is `"number" | "currency" | "percent" | "bytes" | "duration"`.

`Tone` is `"default" | "accent" | "ok" | "warn" | "err" | "info" | "muted"`.

Every widget and dashboard accepts `realtime`: a channel name, `{ resource: "orders" }`,
or a list of them. When one fires, only that widget re-runs.

Every widget accepts `access`, the same rule a dashboard or action takes: a role, a
list of roles, or a function. A widget the caller's role is refused is left out of
the dashboard, record page or drawer, and its queries never run. A section left
with no widget is left out too. `ctx.role` gives a query the caller's role.

```ts
metric("MRR", (ctx) => mrr(ctx.db, ctx.dateRange), { format: "currency", access: "admin" });
```

`maxRange`, such as `"30d"`, is for rows your app deletes after that long. The
widget queries from `max(from, to − N, now − N)` and says so in its caption; a
range that ended before `now − N` runs no query and shows `—`. `heatmap` and
`tracker` do not take it.

#### Captions

A card shows at most one caption under its title, in this order of precedence:
1. the expired state;
2. where `maxRange` cut the range;
3. `freshness`: when the data was last written, in the warn tone with a ▲ past
   `warnAfter`;
4. `coverage`: a note that the data is a sample.

A failing `freshness.at` is logged and skipped.

`CaptionOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `access?` | `AccessRule` | Who sees the widget. A refused widget is left out of the page and its queries never run. |
| `freshness?` | `Freshness` | Say under the title how old the data is. |
| `coverage?` | `string` | Say under the title that the data is a sample, e.g. "users who accepted analytics". |

`Freshness`

| Property | Type | Notes |
| --- | --- | --- |
| `at` | `(ctx: WidgetContext) => Promise<Date \| null>` | When the data was last written, e.g. the newest rollup row; `null` when unknown. |
| `warnAfter?` | ``${number}m` \| `${number}h` \| `${number}d`` | Older than this shows in the warn tone with a ▲. |

```ts
metric("Runs today", runsToday, {
  freshness: { at: async (c) => lastRollupHour(c), warnAfter: "2h" },
});
metric("With analytics consent", consentShare, {
  format: "percent",
  coverage: "users who accepted analytics",
});
```

### Thresholds

`Threshold`

| Property | Type | Notes |
| --- | --- | --- |
| `warn` | `number` | The value at which it is a warning. |
| `err` | `number` | The value at which it is an error. |
| `goodWhen?` | `GoodWhen` | Which direction is good. Left out, the numbers say it: `warn` below `err` means higher is worse, and reverse. Given, it must agree with them, or `defineAdmin` throws. |
| `min?` | `number` | Below this many observations the value is `muted`: too few to judge. |

Pass one threshold as `tones` to `metric`, `stat`, `bars`, `tracker` and the
`number`, `percent` and `duration` column formats. The tone is `ok`, `warn` or `err`,
and `muted` below `min` observations (a metric or stat returns them as `volume`).
An explicit `tone` wins. `toneFor(value, threshold, volume)` gives the same answer
in your own code.

`warn` below `err` means higher is worse; `warn` above `err` means lower is worse.
A `goodWhen` that contradicts the numbers makes `defineAdmin` throw.

```ts
import { type Threshold, metric, resource, toneFor } from "@flowpanel/kit";

const ERRORS: Threshold = { warn: 0.3, err: 0.5, min: 20 };

metric(
  "Run errors",
  async (c) => {
    const { rate, runs } = await runErrorRate(c);
    return { value: rate, volume: runs };
  },
  { format: "percent", tones: ERRORS },
);
resource(schema.monitors, { columns: [{ field: "errorRate", format: { kind: "percent", tones: ERRORS } }] });
toneFor(0.42, ERRORS, 120); // "warn": 120 runs, above warn and below err
```

### Links

A widget link names its target instead of spelling a path.

`ResourceLink`

| Property | Type | Notes |
| --- | --- | --- |
| `resource` | `N` |  |
| `id?` | `string \| number` | One record's page instead of the list. |
| `filter?` | `true extends ManyNames<N> ? Record<string, unknown> : ListFilters<RowOf<N>>` | List filters keyed by the target's fields: a value, `{ gte, lte }` or an array, written as the list's own `f_<field>` URL keys. Any keys while the link does not name one resource. |
| `view?` | `string` | A view from the resource's `views`, applied by name before `filter`. |
| `tab?` | `string` | A detail tab, with `id`. |
| `range?` | `true extends ManyNames<N> ? string : keyof RowOf<N> & string` | A `daterange` filter field that receives the widget's range, bound for bound. |

`DashboardLink`

| Property | Type | Notes |
| --- | --- | --- |
| `dashboard` | `string` |  |
| `range?` | `boolean` | Carry the widget's range: the preset, or `from`/`to` for a custom range. A resource link names the `daterange` field instead. Default: `true`. |
| `filter?` | `Record<string, string>` | Dashboard filters the link sets, by key; a link carries no filter implicitly. |

A `LinkTarget` is a string (used as written), a `ResourceLink` or a `DashboardLink`.

- `{ resource: "order" }` is the list, `{ resource: "order", id }` one record, and `tab`
  a record tab.
- `filter` becomes the list's `f_<field>` keys, or a dashboard's declared filters. A
  `Date` is written as its day, `{ gte, lte }` as a range, an array as `a,b`. A key
  the target does not declare fails at `defineAdmin`.
- `view` applies one of the resource's saved `views`.
- `range` on a resource link names the `daterange` filter that receives the widget's
  range, so the list shows exactly the counted rows.
- `{ dashboard: "/system" }` is a dashboard or page by `path`. It carries the widget's
  range unless `range: false`.

An unregistered resource, view or dashboard throws and lists the registered ones.

`ctx.link(target)` resolves the same targets to a string, for the props of a custom
widget:

```ts
custom(PlatformGrid, async (ctx) => ({
  platforms: (await platforms(ctx.db)).map((p) => ({
    ...p,
    runsHref: ctx.link({ resource: "scraper_run", filter: { platform: p.key }, range: "startedAt" }),
  })),
}));
```

Every widget link option takes a `LinkTarget`, or a function of the context that
returns one or `null`.

### metric

`MetricOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `icon?` | `string` | Rendered as-is next to the label. Any string — an emoji, a ligature. No icon-name lookup exists. |
| `format?` | `NumericFormat` | How the number is rendered. |
| `minorUnits?` | `number` | The query returns minor units with this many digits, as on a `money` field: with `format: "currency"`, `2` shows `260000` as $2,600. `tones` compare the amount shown. |
| `sublabel?` | `string` | Small caption under the value. |
| `delta?` | `(ctx: WidgetContext) => Promise<MetricDelta \| null>` | Period-over-period change, queried alongside the value. |
| `compare?` | `boolean \| { against?: "previous" \| "weekAgo" }` | Query the compared period too and show the change: `previous`, or `against: "weekAgo"` for the same range seven days back. Needs a numeric value; a `delta` the query returns wins. |
| `goodWhen?` | `"up" \| "down" \| "neutral"` | Which direction is good news; colours the change ("neutral" doesn't), and `tones` must agree with it. Default: `"up"`. |
| `sparkline?` | `(ctx: WidgetContext) => Promise<number[]>` | Trend line drawn inside the card. |
| `tone?` | `Tone` | Semantic color of the value. |
| `tones?` | `Threshold` | Tone the value against a threshold; an explicit `tone` wins. |
| `drilldown?` | `Link` | Turns the whole card into a link — a path, a named target, or one computed from the context. |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |

A metric's `icon` is rendered as given, such as an emoji; it is not an `IconName`.

A query returns a number, a string, or a `MetricResult`, whose fields win over the
matching options.

A metric that counts rows takes `{ count, where, range }` instead of a query. Its
value is `ctx.count(count, where, { range })`, and it links to exactly the rows it
counted unless you set `drilldown`. A missing `where` value counts `0` with no link.

```ts
metric("Visits", { count: "user_visit", where: (c) => ({ userId: c.id }), range: "startedAt" }, {
  compare: true,
});
metric("Sign-ups", { count: "user", range: "createdAt" }, { compare: true });
```

`where` may be a function of the context. Its fields must be columns or filters of
the counted list, and `range` one of its `daterange` filters; `defineAdmin` checks
both. `drilldown: () => null` removes the link.

`compare: true` runs the query again with `ctx.dateRange.previous` and shows the
change; `compare: { against: "weekAgo" }` compares with the same range seven days
earlier. Set `goodWhen: "down"` for costs and errors. A `delta` from the query wins.
A value that was 0 in the earlier period reads "new" beside "was 0", since a
percentage of nothing means nothing; 0 both times reads "No change".

```ts
metric("New users", async (ctx) => countSignups(ctx.db, ctx.dateRange), { compare: true });
```

A query that sums a cents column returns minor units: set `minorUnits` with
`format: "currency"` and the card shows the amount, as a chart's `minorUnits` does.
`stat()` and `bars()` take it too, and `tones` and `max` read the amount shown.

```ts
metric("Revenue", (ctx) => revenueCents(ctx.db, ctx.dateRange), {
  format: "currency",
  minorUnits: 2,
  compare: true,
});
```

#### MetricResult

`MetricResult`

| Property | Type | Notes |
| --- | --- | --- |
| `value` | `number \| string` |  |
| `tone?` | `Tone` |  |
| `sublabel?` | `string` |  |
| `delta?` | `MetricDelta` |  |
| `href?` | `LinkTarget` | Turns the whole card into a link — a path or a named target. |

#### MetricDelta

`MetricDelta`

| Property | Type | Notes |
| --- | --- | --- |
| `value` | `number` | Fractional change — `0.12` renders as +12%. Inside ±1% the card shows no direction. |
| `vs` | `string` | What the comparison is against, e.g. `"prior period"`. |
| `previous?` | `number` | The value compared against, shown muted beside the change. A count under 20 shows the absolute change (`+3`); a `percent` metric shows percentage points (`+3 pp`). |

The change prints signed (`+12%`, `−3`). Inside ±1 % it has no sign, and only a
change of 5 % or more is coloured. With `previous` set, the old value shows beside
it. A count whose `previous` is under 20 shows the absolute change, and a
`format: "percent"` metric its change in points (`+3 pp`). `goodWhen: "down"`
colours a fall as good; `"neutral"` never colours.

### table

Point it at a `resource` to reuse its columns, or pass your own `query` and
`columns`, which are checked against the query's row type. On the `resource`
path a bare key keeps the resource's header and format; an object overrides them.

`TableWidgetOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `label?` | `string` | Card heading. |
| `filterOnClick?` | `string` | A dashboard filter key: clicking a row sets it to the row's `rowKey` value on the current dashboard. |
| `resource?` | `ResourceName` | Registered resource to pull rows and columns from. |
| `query?` | `(ctx: WidgetContext) => Promise<R[]>` | Supply rows yourself instead of reading a resource. |
| `where?` | `Record<string, unknown> \| ((ctx: WidgetContext) => Record<string, unknown>)` | Narrow the `resource` read: a filter keyed by its fields, or one computed from the context — `(c) => ({ userId: c.id })`. A missing value throws instead of reading every row. |
| `range?` | `string` | A timestamp field of `resource` that the picked range bounds, as `ResourceLink.range` does. |
| `columns?` | `Array<RowKey<R> \| WidgetColumn<R>>` | Columns to show, defaulting to the resource's own list columns; give an object to name/format a query-produced column. |
| `rowKey?` | `RowKey<R>` | Which field identifies a row. Defaults to the resource's own key, and to `"id"` for a `query`. A row without one renders but is never acted on. |
| `rowHref?` | `(row: R, ctx: WidgetContext) => LinkTarget \| null` | Turn each row into a link — a path or a named target. Return `null` to leave a row inert. |
| `seeAll?` | `boolean \| Link` | Link the card heading. `true` links the `resource`'s own list; a `Link` names any target, and a string is used as written. |
| `limit?` | `number` | Row cap. An explicit value caps both paths; the default applies only to the `resource` read. Default: `10`. |
| `emptyState?` | `ReactNode` | Rendered in place of the table body when there are zero rows. |
| `density?` | `"comfortable" \| "compact"` | Row height: `"compact"` sets 40px rows for a card that lists a few. Default: `"comfortable"`. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |

#### WidgetColumn

`WidgetColumn`

| Property | Type | Notes |
| --- | --- | --- |
| `field` | `RowKey<R>` |  |
| `label?` | `string` |  |
| `format?` | `ColumnFormat` |  |
| `align?` | `"left" \| "center" \| "right"` |  |
| `width?` | `number \| string` |  |

`rowKey` defaults to the resource's key, or `"id"` for a `query`. `rowHref` links
each row (`null` for none); `seeAll: true` links the heading to the list. `limit`
defaults to 10 on the `resource` path. `density: "compact"` sets 40 px rows.

`where` narrows the `resource` read with [`ctx.read` values](/docs/reference/contexts#where-values),
or a function such as `(c) => ({ userId: c.id })`. `range` names the timestamp the
picked range bounds: `table({ resource: "user", range: "createdAt" })`.

```ts
table({
  resource: "orders",
  label: "Recent orders",
  columns: ["id", { field: "total", label: "Total", format: "money", align: "right" }],
  rowHref: (row) => ({ resource: "orders", id: row.id }),
  seeAll: true,
  limit: 5,
});
```

`StatItem`

| Property | Type | Notes |
| --- | --- | --- |
| `label` | `string` |  |
| `value` | `StatValue \| ((ctx: WidgetContext) => Promise<StatValue \| KvResult>)` | A literal, or a function resolved per request that may return a `KvResult`. The record, in a detail tab, is `ctx.row`. |

`StatValue` is `string | number | boolean | bigint | Date | null | undefined`; a

```ts
statGroup({

```

### Cards

Small cards take values and labels, format them with the admin's `formatting`,
and colour items by `tone`.

#### stat

One number with a label, without `metric()`'s delta and sparkline.

`StatOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `hint?` | `string` | Small caption under the value. |
| `href?` | `Link` | Turns the whole card into a link — a path, a named target, or one computed from the context. |
| `tone?` | `Tone` | Semantic color of the value. |
| `tones?` | `Threshold` | Tone the value against a threshold; an explicit `tone` wins. |
| `goodWhen?` | `GoodWhen` | Which direction is good news; `tones` must agree with it. Default: `"up"`. |
| `format?` | `NumericFormat` | How a numeric value is rendered. |

| Property | Type | Notes |
| --- | --- | --- |

| `goodWhen?` | `"up" \| "down" \| "neutral"` | Which direction is good news; colours each row's change ("neutral" doesn't), and `tones` must agree with it. Default: `"up"`. |
| `tones?` | `Threshold` | Tone each bar against a threshold by its value; a row's own `tone` wins. |
| `compare?` | `boolean \| { against?: "previous" \| "weekAgo" }` | Runs the query for the compared period too and fills each row's `previous`, joined by `key` then `label`. No change shows past `maxRange` or over a whole history. |
| `emptyState?` | `ReactNode` | Shown instead of the bars when the query returns nothing. Text or any node; the drawer shows only text. |
| `span?` | `Span` | Width in the dashboard's 12-column grid. |
| `maxRange?` | `RangeLimit` | Cap the date range at its last N days — `"30d"` — for data kept only that long. |
| `realtime?` | `RealtimeOption` | Re-run the query when any of these fire: a channel name, or `{ resource }` for that resource's own changes. |

`share: true` shows each row's share of the total; a top-N query returns each
row's `share` itself. A row's `previous` shows its change with the `MetricDelta`
rules.

`compare: true` (or `{ against: "weekAgo" }`) runs the query for the earlier period
and fills each row's `previous`, joining by `key`, else `label`. A row the earlier
period lacks counts as 0 there, unless those rows fold the rest into "Other", where
it shows no change. A row that grew from 0 reads "new" instead of a percentage, and
a row at 0 both times shows no change. A query with a `LIMIT` of its own should fold
the rest with `breakdown({ top })`, or a row that was just outside it reads "new". With `top`, pass the earlier
rows to `breakdown({ previous })` instead.

```ts
bars({
  label: "New orders by marketplace",
  share: true,
  compare: true,
  query: async (c) => breakdown(await c.query(hourly), { by: "platform", value: "orders", keys: PLATFORMS }),
});
```

#### tracker

date picker. The window is 24 hours by default; past 48 hours the blocks are days.

The query receives the window as `ctx.dateRange`. `at` places rows in blocks, `by`
makes the rows, and `value` and `volume` fold each block like `series()`. `tones`
colours blocks; a row's dot is the worst of its last three. `rows` takes prebuilt
rows instead. Not available in drawers.

### timeline

Events newest first, grouped by day. Consecutive events of one kind with the same
`fold` key collapse into one line. A chip per kind (`kinds`) filters, and "Older"
pages back, under `?<id>.kind=` and `?<id>.before=`; `id` defaults to the tab key.

`query(ctx, page)` returns events that are not resource rows: at or before
`page.before`, at most `page.limit`, of `page.kinds` when set.

```ts
timeline({
  label: "Activity",
  kinds: Activity,
  query: async (ctx, page) => loadEvents(ctx.db, ctx.id, page),
});
```

On a record page a timeline covers the whole history, ignoring `detail.dateRange`.
Not available in drawers.

`TimelineOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `label?` | `string` | Card heading. |
| `kinds` | `EnumDef \| Record<string, EnumEntry>` | The kinds — a chip each, with its label and tone. An `enumOf` works as is. |
| `query?` | `(ctx: WidgetContext, page: TimelinePage) => Promise<TimelineEvent[]>` | Events that are not rows of a resource. |

| `id?` | `string` | The URL namespace of the chips and the paging, `?<id>.kind=` and `?<id>.before=`; unique per page. Default: `the detail tab's key, else "timeline", "timeline-2", … in page order`. |

| `span?` | `Span` | Width in the dashboard's 12-column grid. |

#### Sources

`timeline.source(resource, source)` reads a resource's rows as events, with the
reader's access applied. `at` is the timestamp; `kind` is fixed or `{ field }`.
`refs` names reference columns whose labels reach `title` and `meta`.

```ts
timeline({
  kinds: Bot,
  sources: [
    timeline.source("telegram_message_log", { kind: { field: "kind" }, at: "createdAt", title: (m) => m.text }),
    timeline.source("notification_log", {
      kind: "failed",
      at: "createdAt",
      tone: "err",
      where: { failedReason: "__notnull__", deliveredAt: "__null__" },
      title: "Delivery failed",
    }),
  ],
});
```

On a record page a source reads only rows referencing the record, AND-ed with
`where`; `by` picks the column when several reference it. On a dashboard it reads
rows whose `at` is in the picked range.

| `at` | `keyof R & string` | The timestamp; a row without one is not an event. |

| `where?` | `Where<R> \| ((ctx: WidgetContext) => Where<R>)` | Narrows the rows. On a record page the filter to the viewed record is always AND-ed in and `where` cannot set its field; on a dashboard the source reads the picked range. |
| `title?` | `\| string \| ((row: R, refs: Readonly<Record<string, string \| null>>, ctx: WidgetContext) => string)` | The line's title. Default: the kind's label. |
| `meta?` | `( row: R, refs: Readonly<Record<string, string \| null>>, ctx: WidgetContext, ) => string \| null \| undefined` | Trailing detail. |
| `body?` | `(row: R, ctx: WidgetContext) => string \| null \| undefined` | Longer text, folded under the line. |
| `tone?` | `Tone \| ((row: R) => Tone \| undefined)` | The dot's color. Default: the kind's tone. |
