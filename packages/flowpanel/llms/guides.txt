# FlowPanel — Production

## Production readiness

Verify FlowPanel's ownership, security, data, scaling, and release boundaries before deploying an admin.

Docs: https://flowpanel.tech/docs/guides/production-readiness

Do this review before an admin takes production traffic. FlowPanel runs inside your Next.js process with your database client and your auth; there is no FlowPanel control plane, so each item below is yours.

### Runtime and data ownership

- Review `flowpanel.config.ts`, the generated routes and migrations like the rest of the app.
- Expose only the resources and fields that belong in the admin.
- Custom widgets, pages, renderers and workers are your code: generated-handler policies do not cover them.

### Security boundary

- **Authentication.** Replace any development session with real auth and set `auth.access`. `devAuth()` refuses to start when `NODE_ENV` is `production`. See [Authentication](/docs/guides/authentication).
- **Roles.** Use resource and action `access` and field rules; the server rejects fields an operation may not write. See [Roles and permissions](/docs/guides/permissions).
- **Tenants.** Scope every tenant-owned resource. The first-party adapters fail closed when a bound scope does not constrain the query. See [Multi-tenant scope](/docs/guides/multi-tenant-scope).
- **Client IP.** Set `security.trustedProxies` to the number of proxies that append to `X-Forwarded-For` (`1` on Vercel or behind one nginx). Without it `ctx.ip` is `null` and `rateLimit` with `per: "ip"` puts every caller in one bucket. Never grant access by `ctx.ip`. See [SecurityConfig](/docs/reference/define-config#securityconfig).
- **Origins.** Cross-origin writes are blocked by default. Add exact `security.trustedOrigins` only for another frontend that must write. Server-to-server clients without an `Origin` header pass this check, so authenticate them yourself.
- **Read-only mode.** `readOnly: true` turns off every generated write for a demo, maintenance or an incident.

### Writes and their effects

- Declare explicit create and update fields.
- Turn on the [audit log](/docs/guides/audit-log) and run `flowpanel migrate`, or pass `audit.sink` to keep events in your own store.
- Use the Redis rate-limit driver with more than one instance; the memory driver counts per process.
- `rateLimit` counts each admin page view once, page and metadata together, and a router prefetch counts like a view. The admin's own links do not prefetch; give your own links into the admin `prefetch={false}`, or set the limit with room for their prefetches.
- Audit, realtime and revalidation run after commit. A failure there is logged on the server and leaves the write committed; alert on those log lines ([details](/docs/reference/runtime-contracts#post-commit-effects)).

### Migrations

Run `pnpm flowpanel migrate --dry-run` before applying. On PostgreSQL and SQLite each file and its applied marker share one transaction. MySQL commits DDL implicitly, so make changes restart-safe, take a backup, and plan a forward fix. See [flowpanel migrate](/docs/reference/cli#flowpanel-migrate).

### Realtime and queues

Use the Redis driver when more than one process serves the admin, and treat events as refresh signals, not a durable log. Keep the queue board on a protected network with a strong token. See [Realtime](/docs/guides/realtime) and [Queues](/docs/guides/queues).

### Observability

Log FlowPanel request IDs, alert on auth, scope, rate-limit, adapter and post-commit failures, and document how to turn off writes and restore from backup. See [Errors](/docs/reference/errors).

### Browser smoke test

Run `smokeAdmin` from `@flowpanel/kit/test` in CI. It opens every dashboard, list and first record, and fails on a 4xx/5xx, a console error, a FlowPanel error card, and, with `a11y: true` and `@axe-core/playwright` installed, an axe WCAG 2.2 AA violation. See [Testing](/docs/reference/testing).

### Release checklist

- [ ] Real authentication; unauthenticated requests fail.
- [ ] `auth.access` and resource policies have allowed and denied tests.
- [ ] Every tenant-owned resource is scoped; cross-tenant reads and writes fail.
- [ ] Trusted origins are set only where needed.
- [ ] Forms, imports, exports, actions and hidden resources expose nothing unintended.
- [ ] Audit log, rate limiting, logs, request IDs and alerts are configured.
- [ ] Pending migrations were reviewed with `--dry-run`; backup and recovery are documented.
- [ ] Realtime and queues use production drivers and protected origins.
- [ ] Typecheck, lint, build and `smokeAdmin` pass.

## Authentication

Connect better-auth, Clerk, NextAuth, Lucia or your own session to FlowPanel and require a role.

Docs: https://flowpanel.tech/docs/guides/authentication

FlowPanel reads the session from your existing auth provider and checks a role on every page and API request. A preset from `@flowpanel/kit/auth` builds the `auth` config for common providers.

| Preset | Session source | Role read from |
| --- | --- | --- |
| `withBetterAuth(opts)` | the better-auth instance you pass | `session.user.role` |
| `withClerk(opts?)` | Clerk's `auth()` helper | `sessionClaims.publicMetadata.role` |
| `withNextAuth(opts)` | the `auth` function you pass: Auth.js v5's `auth`, or `() => getServerSession(authOptions)` on NextAuth v4 | `session.user.role` |
| `withLucia(opts)` | the Lucia instance you pass | `user.role` |
| `devAuth(role?)` | a fixed `{ id: "dev" }` | the `role` argument, default `"admin"` |

A missing role resolves to `guest`. `devAuth()` authenticates nobody, so it throws when `NODE_ENV` is `production`, whatever `auth.access` says. Use it only locally.

### better-auth

```ts
import { defineAdmin } from "@flowpanel/kit";
import { withBetterAuth } from "@flowpanel/kit/auth";
import { auth } from "@/lib/auth";

export default defineAdmin({
  adapter,
  auth: withBetterAuth({
    auth,
    access: "admin",
    signInUrl: "/sign-in",
    forbiddenUrl: "/",
  }),
  resources,
});
```

`init` writes this wiring when it finds `better-auth`: the preset goes in `server/lib/flowpanel-session.ts` as `flowpanelAuth`, and the config uses `auth: flowpanelAuth`. Add `signInUrl` and `forbiddenUrl` there. The preset calls `auth.api.getSession` with the request being served, so cookie sessions work in pages and API routes. The audit actor is `session.user.id`.

When the role lives in your own table, `role` can be async:

```ts
auth: withBetterAuth({
  auth,
  access: "admin",
  role: async (session) => {
    const id = (session?.user as { id?: string } | undefined)?.id;
    if (!id) return "guest";
    const member = await db.query.members.findFirst({
      where: (m, { eq }) => eq(m.userId, id),
      columns: { role: true },
    });
    return member?.role ?? "guest";
  },
}),
```

It runs on every request, so keep it to one indexed read. FlowPanel does not cache it. A resolver that throws fails the request closed.

### Clerk

Clerk must already protect the app: `clerkMiddleware()` covering the admin, API and stream paths, and `ClerkProvider` at the root. See [`examples/with-clerk`](https://github.com/getflowpanel/flowpanel/tree/main/examples/with-clerk).

```ts
import { defineAdmin } from "@flowpanel/kit";
import { withClerk } from "@flowpanel/kit/auth";

export default defineAdmin({
  adapter,
  auth: withClerk({
    access: "admin",
    signInUrl: "/sign-in",
    forbiddenUrl: "/",
  }),
  resources,
});
```

Set the user's `publicMetadata.role`, and add `"publicMetadata": "{{user.public_metadata}}"` to the Clerk session token; Clerk leaves it out by default. Refresh the session after changing a role. The audit actor is the Clerk user ID. `withClerk` throws when `@clerk/nextjs` is not installed.

### Your own session

```ts
auth: {
  session: getSession,
  role: (session) => session?.user?.role ?? "guest",
  userId: (session) => session?.user?.id ?? null,
  access: ["admin", "support"],
}
```

`session` receives the request. Both `session` and `role` run on every request. `access` takes the same rule as everywhere else: a role, a list of roles, or a function of `{ session, role }`. It runs before `scope`, so a function sees `scope` as `null`.

### Verify

1. With no session, the page redirects to `signInUrl` and the API rejects the request.
2. Signed in without the role, the page redirects to `forbiddenUrl` and the API returns 403.
3. Signed in with the role, pages and API calls succeed.

Without a `signInUrl`, the page shows a sign-in screen instead of redirecting. In development it says that `auth.session` returned null and links to this guide.

Call one action route as a non-admin as well, such as `POST /api/flowpanel/orders/1/actions/refund` with a non-admin session cookie, and check that it answers 403.

In production, an admin without `auth.access` refuses to start unless it sets both `allowUnauthenticated: true` and `readOnly: true`.

Every option: [AuthConfig](/docs/reference/define-config#authconfig).

## Roles and permissions

Enforce admin, resource, action, field, row, and tenant access on the server.

Docs: https://flowpanel.tech/docs/guides/permissions

Every rule is checked on the server route; the UI only hides what a role cannot use. Rules narrow from the whole admin down to a field, and each one is an `AccessRule`: `true` or `false`, a role, a list of roles, or a function of `{ session, role, scope }` that may be async.

### The whole admin

`auth.access` protects every page, API handler and stream. See [Authentication](/docs/guides/authentication).

```ts
auth: {
  session: getSession,
  role: (session) => session?.user?.role ?? "guest",
  access: ["admin", "support"],
}
```

### A dashboard, page or queue

`access` on any of them hides it from the navigation and rejects its direct route. A dashboard's `access` also gates its actions, on top of each action's own `access`.

```ts
dashboard({ path: "/finance", label: "Finance", access: "admin", sections });
page({ path: "/audit", label: "Audit", component: AuditPage, access: ["admin", "support"] });
queue(emailQueue, { label: "Emails", boardUrl, access: "admin" });
```

### A resource or action

`access` on a resource sets a rule per operation: `read`, `create`, `update`, `delete`. A resource the caller may not `read` leaves the navigation and rejects its routes.

An action with its own `access` runs under that rule alone, the same one that shows it in the UI. An action without one runs under the resource's `update` rule.

### Fields

`fieldAccess` on a resource is the one field policy: a `read` and a `write` rule per field. A field its `write` rule denies is treated like a `readOnly` one: read-only on the form, rejected from the API. A field the caller may neither read nor write is left out of the form. The route drops both from what it saves; an API or programmatic write that carries such a field is rejected. A field's `readOnly` wins over its `fieldAccess.write`. `hidden` is not an access rule; it only removes the control.

```ts
resource(users, {
  fieldAccess: {
    role: { read: "admin", write: "admin" },
  },
  update: {
    fields: [
      { name: "name", required: true },
      { name: "role", type: "select", options: ["member", "admin"] },
      { name: "createdAt", readOnly: true },
    ],
  },
});
```

### Rows

A row action's `when` is a server-side row condition: it runs on the loaded row, and the route answers 404 when it returns false. `hidden(row)` removes the action for that row and its route also answers 404; `disabled(row)` shows it with a reason and its route answers 409. For tenant isolation use [scope](/docs/guides/multi-tenant-scope), which applies to every read and write by ID.

### Read-only mode

`readOnly: true` on the admin turns off every generated mutation, for maintenance or an incident.

### Verify

For each role, request the page and the route behind it: list and get, create, update and delete, actions, import, drawer tabs and queues. Include a crafted write with a read-only field. Authorization runs before input validation, so a denied caller learns nothing about the form.

## Multi-tenant scope

Bind every tenant-owned resource operation to the current tenant and verify fail-closed behavior.

Docs: https://flowpanel.tech/docs/guides/multi-tenant-scope

Tenant scope has two parts: the root config resolves the tenant from the session once per request, and each tenant-owned resource turns it into a query predicate. Take the tenant from trusted session state, never from a query parameter.

### Resolve the tenant

```ts
export default defineAdmin({
  adapter,
  auth: flowpanelAuth,
  scope: async ({ session }) => {
    const tenantId = session?.user?.tenantId;
    if (!tenantId) throw new Error("No tenant selected");
    return { tenantId };
  },
  resources,
});
```

`session` is typed by the `session` you register on `FlowpanelTypes`; see [Registry](/docs/reference/registry).

The value reaches resource predicates as their first argument, and policies and actions as `ctx.scope`. Widgets get no scope: `ctx.count` and `ctx.read` apply it for you, and a `ctx.sql` or `ctx.db` query reads the tenant from `ctx.session`.

### Bind each resource

```ts
import type { QueryContext } from "@flowpanel/kit";
import { eq, type SQL } from "drizzle-orm";

resource(schema.orders, {
  columns: ["number", "status", "total", "createdAt"],
  scope: (scope, query: { where(condition: SQL): unknown }) =>
    query.where(eq(schema.orders.tenantId, scope?.tenantId as string)),
  create: {
    fields: [
      { name: "number" },
      { name: "status" },
      { name: "total" },
      {
        name: "tenantId",
        type: "hidden",
        hidden: true,
        defaultValue: async (ctx: QueryContext) => ctx.scope?.tenantId,
      },
    ],
  },
})
```

The adapter decides what `query` is, so annotate it: with Drizzle, something you call `.where(condition)` on; with Prisma, the `where` object. Merge the tenant into it:

```ts
scope: (scope, where: Record<string, unknown>) => ({ ...where, tenantId: scope?.tenantId }),
```

The predicate applies to lists, lookups, updates, deletes, restores, references and related tabs. On create, set the tenant with a server `defaultValue` on a hidden field, as above, so the form never shows it. A hidden field does not stop a crafted request from sending another tenant ID; the adapter does:

- On create, Drizzle checks that the new row matches the scope, and Prisma merges the scope into the data, so the write fails or lands in the caller's tenant.
- On update, both adapters refuse a change that would move the row out of the scope, through the JSON API, forms and inline edits alike. The request fails with `403` and the row stays as it was. Drizzle checks inside a transaction on PostgreSQL and MySQL and inside the `UPDATE` itself on SQLite.
- A driver without interactive transactions, such as `drizzle-orm/neon-http`, gets the same guarantee from a check that runs just before the write, as on SQLite; Prisma uses `$transaction`.

### Fail closed

With a global `scope`, every resource must declare its own `scope` or opt out with `scope: "bypass"`. A resource that does neither, or whose predicate adds no constraint, throws `FlowpanelAccessError` on its first query instead of returning another tenant's rows. Do not catch that error and retry unscoped.

`ctx.sql`, `ctx.db` and your own queries in widgets and pages are not scoped. Add the tenant predicate yourself, reading the tenant from `ctx.session`.

### Verify isolation

With fixtures for two tenants, check that:

1. each tenant lists only its own rows;
2. reading the other tenant's row by ID fails;
3. update, delete, restore and row actions cannot reach the other tenant;
4. create cannot set another tenant ID;
5. references and related tabs stay scoped;
6. dashboard queries that use `ctx.sql` or `ctx.db` filter by the tenant from `ctx.session`.

Every option: [Scope reference](/docs/reference/scope-realtime#scope).

## Audit log

Record who changed what through the admin, and read it back on each record and in one log.

Docs: https://flowpanel.tech/docs/guides/audit-log

With the audit log on, every write through the admin records one event: who acted, what ran, which record, the fields that changed with their old and new values, and when. Each record page gets a **History** tab, and the admin gets an **Audit log** page.

### Turn it on

Create the table once with the migration `init` wrote, then turn auditing on:

```bash
pnpm flowpanel migrate
```

```ts
audit: { enabled: true },
```

`flowpanel migrate` creates `flowpanel_audit_log` through the database client in `flowpanel.config.ts`, with SQL for PostgreSQL, MySQL or SQLite. Both shipped adapters write to it through the same client. With a custom adapter that has no `auditLog`, `defineAdmin` refuses to start until you pass a `sink`.

### What is recorded

Creates, updates (form and inline), deletes, restores, exports, and row, bulk, drawer and dashboard actions each record one event after the write commits. A bulk action records one row per selected record, so each record's History shows it.

The diff holds the changed fields only: every readable field of a new or deleted record, and the fields an update or action changed. A `sensitive` field, and a column the adapter reports as sensitive, never reaches the table. When the admin cannot read the row back after an action, the event is still recorded, without a diff.

If the table cannot be written, the error is logged and the user's change stands.

The actor is `auth.userId` of the session, and their name or email comes from `theme.user`, so the log reads "Ann Lee" rather than an ID. The request's IP and user agent are kept too.

### History on a record

Each record of an audited resource gets a History tab beside its other tabs, newest event first, twenty to a page. Each event shows the action, who and when, and each changed field as `old → new`, formatted the way the list formats that column.

A reader sees only the fields their `fieldAccess` lets them read. Hide the tab for one resource with `detail.history`, or stop auditing it with `audit: false`:

```ts
resource(userVisit, {
  audit: false,
});

resource(orders, {
  detail: { history: false },
});
```

### The Audit log page

The admin's navigation gets an **Audit log** entry at `/admin/audit-log`. It lists events fifty to a page, filtered by who, resource, action and date, and each event links to its record. A reader sees the events of resources their `access.read` admits and the runs of dashboard actions they may run (recorded with `resource: "dashboard"`), on the page and in every History tab; the Resource filter offers only those resources. An event your own route records without a `resource` shows to every reader of the page; one whose `resource` the admin does not declare shows to no one. The count stops at 10,000, and the who and action filters offer what happened in the last 90 days.

`audit.access` decides who sees the page and the History tabs. Without it, everyone `auth.access` lets in sees them. A field rule still applies to every diff.

```ts
audit: { enabled: true, access: ["admin"] },
```

### Tenants

With a global [`scope`](/docs/guides/multi-tenant-scope), each event stores the tenant the request was scoped to, and a reader sees only the events of their own tenant, on the page and in every History tab. The tenant is the whole scope object the request carried, so two scopes that differ in any key are two tenants (a `userId` in the scope splits a record's History by author), and a request with no scope reads only the events written without one.

### Your own store

A `sink` sends events to your own table or log pipeline instead. FlowPanel cannot read them back, so the admin shows no History tab and no Audit log page:

```ts
audit: {
  enabled: true,
  sink: async (event) => {
    console.log(JSON.stringify(event));
  },
},
```

To record an event from your own route handler, call `emitAudit(config, event)` from `@flowpanel/kit/next`; it writes wherever the admin writes. Every field: [`AuditConfig`](/docs/reference/define-config#auditconfig).

## Realtime

Refresh lists and widgets live over SSE, share events across instances with Redis, and publish from workers.

Docs: https://flowpanel.tech/docs/guides/realtime

A committed change publishes a small event; lists and widgets subscribed to its channel refetch through their normal authorized query. Events reach the browser over Server-Sent Events. They are refresh signals, not row data, and not a durable log: a reconnect refetches current state.

### Subscribe

`realtime: true` on a resource refreshes its list. A record page does not subscribe on its own; give its widgets their own `realtime: { resource: "orders" }`. A widget takes a channel name, `{ resource: "orders" }`, or a list of them:

```ts
metric("Open orders", openOrders, { realtime: { resource: "orders" } });
custom(Pipeline, pipelineProps, { realtime: "pipeline" });
```

A channel name other than `resource.<name>` is your own; declare it in `realtime.channels` (below).

Generated creates, updates and deletes publish on their resource automatically. An action publishes when it returns `refresh: true` (its resource) or channels (`refresh: "pipeline"` or a list). In your own server code, call `ctx.publish` in an action, or `publishResource` and `publish` from `@flowpanel/kit/next`.

### Declare your own channels

The stream serves `resource.<name>` channels to whoever may read that resource. Every other channel must be declared, with who may subscribe:

```ts excerpt
import type { RealtimeConfig } from "@flowpanel/kit";

export const realtime = {
  driver: "redis",
  url: process.env.REDIS_URL,
  channels: {
    pipeline: { access: ["admin", "ops"] },
    deploys: { tenantSafe: true },
  },
} satisfies RealtimeConfig;
```

Pass it to `defineAdmin` as `realtime`. `access` takes the same rule as a resource. Without it, everyone `auth.access` admits may subscribe. The stream refuses an undeclared channel, and `defineAdmin` refuses a widget, dashboard or list that subscribes to one, naming it.

With an admin-wide `scope`, an event on your own channel reaches the browser as `{}`: the subscribed widget still refetches through its scoped query, but no payload crosses tenants. Set `tenantSafe: true` only when the payload names nothing tenant-specific, such as a deploy finishing. A tenant-scoped resource's own events keep only their `action`.

### Choose the driver

The default memory driver reaches only the process that published. Use Redis when more than one process serves the admin, during overlapping deploys, or when a worker publishes.

```bash
pnpm add ioredis
```

```ts
import { defineAdmin } from "@flowpanel/kit";
import { flowpanelAuth } from "@/server/lib/flowpanel-session";

export default defineAdmin({
  adapter,
  auth: flowpanelAuth,
  realtime: {
    driver: "redis",
    url: process.env.REDIS_URL,
    keyPrefix: "myapp-production",
  },
  resources,
});
```

Use a distinct `keyPrefix` per app and environment sharing one Redis. FlowPanel warns on the first request when it runs the memory driver while `REDIS_URL` is set.

### Publish from a worker

A worker, cron job or script imports only `@flowpanel/kit/publish`: no admin config, adapter or Next.js. Share the admin's `realtime` options in one module that the admin config and the worker both import, so both sides use the same URL and prefix:

```ts
// src/shared/realtime.ts
import type { PublisherOptions } from "@flowpanel/kit";

export const realtime = {
  driver: "redis",
  url: process.env.REDIS_URL!,
  keyPrefix: `myapp-${process.env.NODE_ENV}`,
} satisfies PublisherOptions;
```

```ts
// worker/admin-events.ts
import { createPublisher } from "@flowpanel/kit/publish";
import { realtime } from "@/shared/realtime";

export const adminEvents = createPublisher({
  ...realtime,
  onError: (err, channel) => console.warn("admin realtime publish failed", { channel, err }),
});

export async function orderShipped(order: { id: number }): Promise<void> {
  await adminEvents.resource("orders", { id: order.id });
  await adminEvents.publish("pipeline");
}
```

`resource(name, { id })` refreshes that resource's lists and the widgets subscribed to it; `action` defaults to `"update"`. `publish(channel)` sends on your own channel. Names are not checked, so a misspelt one refreshes nothing.

A Redis error never fails the job: the call resolves and the error goes to `onError`, or is logged once per error kind. Create the publisher once per process and `close()` it on shutdown. To reuse a configured `ioredis` client, pass it instead of a URL: `createPublisher({ redis, keyPrefix })`.

### Production

- The stream route checks `auth.access` itself. If middleware protects the admin (Clerk, a proxy), include the stream path.
- Turn off reverse-proxy buffering for the stream path.
- Set proxy and load-balancer idle timeouts above 15 s, the stream heartbeat.
- Allow enough long-lived connections for your operators. One user may hold 10 streams at once; the next answers `429`.
- A stream ends after 15 minutes and the browser reconnects through `auth.access`, so a user whose access is revoked stops receiving events within that time. `stream(config, { maxPerActor, maxAgeMs })` changes both.
- Monitor reconnects, stream errors and publish failures.

### Verify end to end

Open one resource in two browsers, change a row in one and watch the other refetch. With several instances, connect the browser to one and change the row through another, then repeat with a worker publish.

Every option: [Publisher reference](/docs/reference/scope-realtime#publisher).

## Queues

Register BullMQ queues and show their jobs in the admin, behind the same authentication as the rest of it.

Docs: https://flowpanel.tech/docs/guides/queues

A queue adds a navigation entry whose page embeds a bull-board server in an iframe. The board is a separate HTTP process with its own secret, so protect it on the network as well.

```bash
pnpm add bullmq ioredis @bull-board/api @bull-board/express express
```

### Register a queue

```ts
import { queue } from "@flowpanel/kit";
import { emailQueue } from "@/server/queues";

export const emailQueuePage = queue(emailQueue, {
  label: "Email",
  boardUrl: "https://internal.example.com/queue/email",
  boardSecret: process.env.BOARD_SECRET,
  access: "admin",
});
```

Add it to `queues` in the config. The queue's `.name` is its key unless you set `key`. `access` protects the admin page, not the board server.

The page embeds `boardUrl` in an iframe. With `boardSecret`, every render adds a link signed for this queue that expires in a minute; the board checks it and adds the queue to its own session cookie, and the secret never reaches the browser. The session reaches only the queues the user opened from the admin, each for an hour after its latest link, so a user who loses access to a queue page loses that queue on the board within the hour. Without `boardSecret`, put the board behind a reverse proxy that adds `Authorization: Bearer <secret>`, and point `boardUrl` at the proxy; without either, the iframe shows a 401.

### Start the board

`flowpanel dev` starts `scripts/board-server.mts` (or `.ts`) when `REDIS_URL` is set, unless you pass `--no-board`:

```ts
import { startBoardServer } from "@flowpanel/kit/bullmq/board";
import { queuesByName } from "@/server/queues";

const secret = process.env.BOARD_SECRET;
if (!secret) throw new Error("BOARD_SECRET is required");

startBoardServer({
  queues: queuesByName,
  port: 3001,
  bindHost: "127.0.0.1",
  auth: { secret },
});
```

The secret is required, and is the same value as each queue's `boardSecret`. A valid link sets an HttpOnly, signed session cookie for the board's assets and polling of that queue, valid for an hour after the queue's latest link. To rotate the secret, pass `auth: { secret: [newSecret, oldSecret] }` until sessions signed with the old one have expired. Behind a TLS-terminating proxy, pass `trustedProxies: 1` so the cookie is `Secure`.

### Deploy

Anyone who reaches the board port with a valid link or cookie reaches its destructive job controls. Keep it on loopback or behind an authenticated reverse proxy, and run it as its own supervised process. A signed link in a log or browser history expires a minute after the page rendered.

### Count jobs in a dashboard

Wrap the same queue instances with `bullmqAdapter` and call BullMQ methods from a widget; the board server is not involved. See [Reading queue state](/docs/reference/queues#reading-queue-state-from-your-own-code).

### Verify and troubleshoot

Test the admin role gate and the board URL separately: a missing, expired or wrongly signed link returns 401. An unreachable `boardUrl` leaves the iframe empty and the rest of the admin working.

## Upgrade from 0.3

Every option and export that 0.4 removed or renamed, what to write instead, and the behaviour that changed.

Docs: https://flowpanel.tech/docs/guides/upgrade

FlowPanel 0.4 publishes three packages: `@flowpanel/kit`, `@flowpanel/cli` and `@flowpanel/eslint-plugin`. Update them together, and remove any other `@flowpanel/*` package from package.json:

```bash
pnpm up "@flowpanel/*" --latest
```

### Removed and renamed

These names are gone in 0.4. Most were deprecated in 0.3; `requireRole` goes everywhere because every gate now takes the same `access` rule. TypeScript reports each one. `defineAdmin` also throws at startup on a leftover `requireRole` on the auth block, a resource, a row, bulk, drawer or dashboard action and its form fields, a create or update form field, a dashboard, a page or a queue, `basePath`, or a detail or drawer `header`, and each auth preset throws when given `requireRole`, so a config that skips the type check fails instead of leaving a resource open.

| 0.3 | 0.4 |
| --- | --- |
| an import from `@flowpanel/core`, `next`, `react`, `client`, `charts`, `test` or an adapter package | the same names from `@flowpanel/kit` or its subpath: `/next`, `/react`, `/client`, `/charts`, `/test`, `/drizzle`, `/prisma`, `/bullmq` |
| `areaChart`, `barChart`, `lineChart`, `pieChart` from `@flowpanel/kit/charts` | the same builders from `@flowpanel/kit` |
| chart components from `@flowpanel/kit/charts/runtime` | the same components from `@flowpanel/kit/charts` |
| `@flowpanel/kit/server` | `publish`, `publishResource`, `bindPublisher`, `emitAudit` from `@flowpanel/kit/next`; `requireAccess` and the request-context accessors from `@flowpanel/kit` |
| `requireRole: "admin"` on a resource | `access: { read: "admin", create: "admin", update: "admin", delete: "admin" }` |
| `requireRole` on a row, bulk, drawer or dashboard action | `access: "admin"` (a role, a list of roles, or a function) |
| `auth: { requireRole: "admin" }`, `withClerk({ requireRole: "admin" })` and the other auth presets | `auth: { access: "admin" }`, `withClerk({ access: "admin" })` |
| `requireRole` on a `dashboard()`, `page()` or `queue()` | `access` on the same object; a queue now also takes a function |
| `requireRole: "admin"` on a create or update form field | `fieldAccess: { field: { read: "admin", write: "admin" } }` on the resource |
| `requireRole` on an action's `form` field | remove it: it never gated anything; gate the whole action with `access` |
| a function `requireRole: (session) => …` | `access: ({ session, role, scope }) => …` |
| `auth: { requireRole: (s) => s !== null }` | `auth: { access: ({ session }) => session !== null }`. Do not just rename the key: `access: (s) => s !== null` receives `{ session, role, scope }`, which is never null, and lets every visitor in. `defineAdmin` warns about it in development and refuses to start in production. |
| `requireRole` from `@flowpanel/kit/server` | `requireAccess(rule, getRequestContext())` from `@flowpanel/kit`, which throws the same access error |
| `checkRequireRole` and the `RequireRole` type | `requireAccess` and `AccessRule` |
| `authorizeOperation(rule, context)` | `requireAccess(rule, context)` |
| `emitAudit` from `@flowpanel/kit` | `emitAudit` from `@flowpanel/kit/next` |
| `isBuiltinBulkDelete`, `assertCountWhereColumns`, `declaredWriteFields` from `@flowpanel/kit` | removed: runtime internals with no public replacement |
| `ctx.db` in an action's `run` | your own `db` import, or `unsafe: ["db"]` on the action and `ctx.unsafe.db` |
| `ctx.db` in a field `options` or `defaultValue` resolver | your own `db` import |
| `ctx.href(target)` in a widget | `ctx.link(target)` |
| `detail.header` | `detail.title` |
| `drawer.header` | `drawer.title` |
| `DrawerPayload.header` | `DrawerPayload.title` |
| `goodWhen` on a metric's returned `delta` | `goodWhen` on the `metric()` options; `MetricCard` takes it as a prop |
| `basePath: "/ops"` | `paths: { admin: "/ops" }` |
| `AdminConfig` | `AdminDefinition` |
| `createPublisher` from `@flowpanel/kit` (the realtime transport) | `createRealtimeTransport`. The worker `createPublisher` in `@flowpanel/kit/publish` keeps its name but no longer rejects when Redis fails; see below. |
| `applyScope` and `scopeRequired` in a custom adapter | `ctx.boundScope` |
| `runMigrationSql` and `markMigrationApplied` in a custom adapter | `applyMigration` |
| `DEFAULT_SHORTCUTS` from `@flowpanel/kit/react` | `<ShortcutsCheatsheet>` without `shortcuts`, which lists the admin's keys in its labels' language |

A field gated by `fieldAccess` shows read-only to a caller its `write` rule denies, and leaves the form only when its `read` rule denies them too. 0.3 left a `requireRole` field out of the form entirely.

### Behaviour that changed

- `defineAdmin` throws at startup when the config names a resource, column or filter that does not exist, such as a stale column in `columns` or a `reference` to a renamed resource. The error names the closest match. 0.3 ignored the name, so run `pnpm flowpanel doctor` after upgrading.
- A resource `scope` function that returns the query unchanged now throws instead of running it unscoped.
- A list row opens its record page when the resource has no drawer, even without `detail`. Set `rowClick: false` to keep rows from opening.
- The drawer keeps its open tab in `?drawerTab=` instead of `?tab=`. Update saved links that open a drawer on a tab.
- A list keeps its page size in `?pageSize=` instead of `?perPage=`, the name the JSON API uses. A saved link with `?perPage=` opens at the default size.
- `useLiveChannel` reports `live` on the server's first frame, not when the connection opens, and `reconnecting` from the first error. Under `RealtimeProvider`, which every admin page mounts, it joins the admin's stream instead of opening a second one.
- Date presets and `daterange` filters start at midnight in `formatting.timeZone`.
- With a Russian `formatting.locale`, the built-in text is Russian. Your `labels` still win, so set them to keep English text.
- `fillDays` buckets days in `range.timeZone` when its options name no zone, and a zoneless timestamp string without seconds, such as `"2026-10-07T10:00"`, stays text instead of reading as a date.
- The worker `createPublisher` from `@flowpanel/kit/publish` resolves when Redis fails instead of rejecting. The error goes to `onError`, or is logged once per kind, so a worker that retried on a rejection should pass `onError` and retry there.
- Widget links resolve on the server. A link to a resource or dashboard the config does not register throws and names the registered ones.
- `ChartRenderer` takes the card's link as a `drilldown` href and no longer reads `options.drilldown`. Pass the resolved link, or the chart card has no link.
- `resolveOperationAccess(access, operation)` takes two arguments; drop the third, `requireRole`, argument.
- An action, form, drawer, inline-edit, import or restore route answers a failure as `{ ok: false, error, code, requestId?, fieldErrors? }`. A form validation failure carries `fieldErrors` instead of an `issues` array, and a 404 has a string `error`. Code that read `issues` from these routes should read `fieldErrors`.
- `StatusBadge` infers different tones: `active` and `completed` are no longer green, `pending`, `waiting` and `processing` are `info` instead of `warn`, `disabled` and `canceled` are `muted` instead of `err`, and an unknown status is `default`. Pass `tone` to keep a colour.
- The default look is a graphite palette with one data colour, `--fp-data`, and a single-series chart draws in it without the area gradient. Set the tokens in [Styling](/docs/customization/styling#change-design-tokens) to keep your colours.
- Related tab rows open their target record, and a single click on an editable cell in a clickable row opens the row; editing starts from the pencil or Enter.
- A list filter's `defaultValue` applies until the URL sets that filter.
- Drizzle forms reject a fractional value for an integer column before it reaches the database.
- Every `flowpanel` command stops with an error on an extra argument, and `migrate` stops before connecting when the database URL your client reads is unset or empty.
- A resource form field with `required: true` is now checked on the server, so a create that leaves it empty, or an edit that clears it, fails even on a nullable column.
- An edit form that empties a NOT NULL column fails with the field's "is required" message instead of keeping the old value.
- A unique, foreign key or NOT NULL violation from the database answers 422 with a field message, or 409, instead of a 500. Any other unexpected error is logged with its request id when `hooks.onError` is not set, and a form route answers it with `requestId` and "Internal server error" instead of "Action failed".
- The Prisma adapter returns `Decimal` columns as strings at their `@db.Decimal` scale, such as `"49.90"`, instead of `Decimal` objects; Prisma 5 does not report the scale, so there the string is `"49.9"`. Code that calls `.toNumber()` on a value from `ctx.read` should use `Number(value)`.
- A Drizzle `numeric` or `decimal` column is a number field with a number filter instead of a text box. Its value is still a string, and a value that is not a number fails with "… must be a number".
- The Prisma and Drizzle adapters' `get` returns `null` for an id that cannot be the key, such as `abc` for an `Int` id or a malformed UUID, so the record page shows not found instead of an error.
- A resource without `labelOne` or `label` names one record by its singular name, "User" for `users`, and the "New …" and "Edit …" titles put the label mid-sentence: "New customer".
- A field's `readOnly` now applies to writes, and a `readOnly` function receives the stored row on edit. `readOnly` also wins over the resource's `fieldAccess.write`.
- A form field that `fieldAccess.write` denies to the signed-in role shows read-only, and saving the form no longer fails with "cannot be changed".
- An unknown admin path and a missing record render your `not-found.tsx` through `notFound()`, with a 404 status, inside the admin's navigation. Under `cacheComponents` Next has already streamed the static shell, so the status stays 200 and the page carries `noindex`. Add `app/admin/not-found.tsx` with `export const metadata = flowpanel.notFoundMetadata;` and `export default flowpanel.notFound;`, or run `pnpm flowpanel doctor --fix`.
