# FlowPanel — Reference — Typed client

## Typed client

Call the protected FlowPanel HTTP API from custom React UI, then add mutation state where needed.

Docs: https://flowpanel.tech/docs/reference/client

Documented types: createFlowpanelClient, UseAdminMutation, UseAdminMutationOptions

`@flowpanel/kit/client` calls the admin's HTTP API from custom browser UI. Calls go
through the same auth, access, scope, validation and audit as generated pages.

```ts
import {
  clientMetadata,
  createFlowpanelClient,
  isFlowpanelErrorCode,
  isFlowpanelErrorResult,
  type CreateFlowpanelClientOptions,
  type FlowpanelClient,
  type FlowpanelClientMetadata,
  type FlowpanelFetchOptions,
  type FlowpanelListOptions,
  type FlowpanelResourceClient,
} from "@flowpanel/kit/client";
```

### Create a client

The client needs the runtime's metadata: `createFlowpanel(config).client`. Read it in a Server Component and pass it to the client component as a prop, so the config, adapter and database client stay on the server:

```tsx
// src/app/orders/page.tsx
import { createFlowpanel } from "@flowpanel/kit/next";
import config from "../../../flowpanel.config";
import { OrdersPanel } from "./orders-panel";

const flowpanel = createFlowpanel(config);

export default function OrdersPage() {
  return <OrdersPanel metadata={flowpanel.client} />;
}
```

```tsx
// src/app/orders/orders-panel.tsx
"use client";

import { createFlowpanelClient, type FlowpanelClientMetadata } from "@flowpanel/kit/client";
import type { orders } from "@/db/schema";

type Order = typeof orders.$inferSelect;

export function OrdersPanel({ metadata }: { metadata: FlowpanelClientMetadata }) {
  async function loadOpenOrders() {
    const orders = createFlowpanelClient(metadata).resource<Order>("orders");
    const result = await orders.list({
      page: 1,
      pageSize: 25,
      search: "acme",
      filters: { status: "open" },
    });
    if (!result.ok) console.error(result.error.code, result.error.message);
  }
  return (
    <button type="button" onClick={loadOpenOrders}>
      Load open orders
    </button>
  );
}
```

`options.fetch` replaces the fetch implementation, `options.baseUrl` puts an origin in
front of `paths.api`, and `options.headers` go with every request. Requests use
`credentials: "same-origin"`. `FlowpanelClientMetadata` holds the runtime id, paths
and protocol version; it is not secret.

### From a script

A Node script, a cron job or a test reaches the API with the same client.
`clientMetadata(config)` builds the metadata from your config, `baseUrl` says where the
app runs (with its `basePath`, if any) and `headers` carries the session, such as a
cookie your auth issued:

```ts
// scripts/open-orders.ts
import { clientMetadata, createFlowpanelClient } from "@flowpanel/kit/client";
import config from "../flowpanel.config";

const client = createFlowpanelClient(clientMetadata(config), {
  baseUrl: process.env.APP_URL ?? "http://localhost:3000",
  headers: { cookie: process.env.ADMIN_COOKIE ?? "" },
});

async function main() {
  const result = await client.resource("orders").list({ filters: { status: "open" } });
  console.log(result.ok ? result.data.total : result.error.message);
}

void main();
```

Run it with `pnpm tsx --env-file=.env scripts/open-orders.ts`. Every kit subpath a
config can import loads from a CommonJS script too, which is what a project without
`"type": "module"`, such as one `create-next-app` makes, runs; it needs Node.js 20.19
or 22.12 and newer, which load the kit's ES modules from `require`.

### Resource methods

`client.resource<Row>(name)` returns a `FlowpanelResourceClient<Row>`:

| Method | HTTP request | Result |
| --- | --- | --- |
| `list(options?)` | `GET /<resource>` | Paginated rows |
| `get(id, options?)` | `GET /<resource>/<id>` | One projected row |
| `create(input, options?)` | `POST /<resource>` | Created row |
| `update(id, input, options?)` | `PATCH /<resource>/<id>` | Updated row |
| `delete(id, options?)` | `DELETE /<resource>/<id>` | `null` on success |

`FlowpanelListOptions` takes `page`, `pageSize`, `search` and `filters`; every call
takes `signal` and `headers`. Network errors and malformed responses become an
`internal` failure; an `AbortError` is rethrown.

### Narrowing errors

`isFlowpanelErrorResult(result)` narrows to the error branch;
`isFlowpanelErrorCode(value)` checks a code.

```ts
import {
  createFlowpanelClient,
  type FlowpanelClientMetadata,
  isFlowpanelErrorCode,
  isFlowpanelErrorResult,
} from "@flowpanel/kit/client";

export async function shipOrder(metadata: FlowpanelClientMetadata, id: string): Promise<void> {
  const orders = createFlowpanelClient(metadata).resource("orders");
  const result = await orders.update(id, { status: "shipped" });
  if (isFlowpanelErrorResult(result) && result.error.code === "field_forbidden") {
    // Hide or disable the corresponding control.
  }
}

isFlowpanelErrorCode("rate_limited"); // true
isFlowpanelErrorCode("anything"); // false
```

### Mutation state hook

`useAdminMutation` tracks pending and error state for an async function that resolves to an `ActionResult` (`{ ok: true, ... }` or `{ ok: false, error }`).

```tsx
// src/app/orders/archive-button.tsx
"use client";
import { useAdminMutation } from "@flowpanel/kit/client";
import { archiveOrder } from "./actions";

export function ArchiveButton({ id }: { id: string }) {
  const { run, pending, error, reset } = useAdminMutation(archiveOrder);
  return (
    <>
      <button type="button" onClick={() => run(id)} disabled={pending}>
        Archive
      </button>
      {error ? <button onClick={reset}>{error}</button> : null}
    </>
  );
}
```

`UseAdminMutation`

| Property | Type | Notes |
| --- | --- | --- |
| `run` | `(...args: Args) => Promise<ActionResult>` |  |
| `pending` | `boolean` |  |
| `error` | `string \| null` |  |
| `reset` | `() => void` |  |

`UseAdminMutationOptions`

| Property | Type | Notes |
| --- | --- | --- |
| `onSuccess?` | `(result: Extract<ActionResult, { ok: true }>) => void` |  |
| `onError?` | `(message: string) => void` |  |

`run` never throws: a rejection sets `error` to its message, and `{ ok: false, error }` sets `error` to that string. `reset()` clears
it. For optimistic values, see [`useOptimisticAction`](/docs/reference/react-components#hooks).
